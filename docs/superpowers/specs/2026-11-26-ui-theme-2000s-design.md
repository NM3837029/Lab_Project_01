# プレイ画面の見た目を「2000年代の編集ソフト風」にし、2種類を切り替える（設計）

日付：2026-11-26　対象：ゲーム本体（DrawPixel.cpp・EditPanel.h・EditToolbar.h・ColorGrade.h・InspLayout.h・UiFont.h・GameConfig.h）
見た目の案：Design キャンバス https://claude.ai/artifact/8vz5L7EyBDrQdW4PYCNQdm のページ「2000年代の編集ソフト風」（案A・案B）

## 1. 目的と背景

右パネルの作り直し（同日）のあと、ユーザーから「右側の形式は良いが、全体的になんとなくAIっぽい。この作品は2000年代の編集ソフトを意識しているので、その雰囲気に合わせたい」と言われた。
キャンバスで2つの案を見せ、ユーザーは「どちらも採用。既定は案A、設定で案Bに変えられるように。切り替えは遊ぶ人が Esc メニューで選ぶ」と決めた。

今の画面が「AIっぽく」見える理由（キャンバス1枚目にまとめた）：角の丸い枠・丸い札、半透明の色の縁と色の点の見出し、大きくなめらかな文字（メイリオ）、広い余白、空の状態のイラスト、ゲーム画面に重なるヒント、一色のゲージ。

## 2. ゴール／しないこと／失敗とみなすこと

**ゴール**
- プレイ画面のまわり（左のツールバー・右パネル・下のタイムライン・情報窓・選択の印・扇形メニュー・Esc メニュー）を、2000年代の編集ソフトの作法で描き直す
  - 角は四角、1pxの線で立体（盛り上がり／へこみ）を表す。半透明の縁・角丸・丸い札は使わない
  - 文字は小さく詰まった「MS UI Gothic」をぼかしなしで
  - 操作のヒントは、ゲーム画面の上から、窓のいちばん下の状態バーへ移す
- 見た目を2種類持ち、遊ぶ人が Esc メニューの「設定」で切り替えられる。選んだものはセーブデータに残る
  - **案A（既定）暗い灰色**：2000年代後半のプロ用映像ソフト風。値は青い点線の下線つきの数字、コストは緑→黄→赤の目盛り、時間は琥珀色
  - **案B 明るい灰色**：2000年代前半の Windows ソフト風。青いグラデーションの見出しバー、白い数値欄、青いブロックの進み具合バー
- 切り替えは、その場ですぐ画面に反映される（再起動しない）

**しないこと**
- 配置・当たり判定・操作の中身（右パネルのタイル、色の輪＋四角、タイムラインのカットの判定、扇形メニューの判定、ツールバーのボタンの位置）を変えること。変えるのは色・線・文字・ヒントの置き場所だけ
- タイトル画面・ステージセレクト・リザルト・メッセージ窓（会話の窓）。これらは Lab_Editor の「UIデザイン」（ui_style）の見た目のまま。あとで別にそろえる
- ゲームの中の物の表示（敵の頭上の「HP 3」、停止中などの札、近くのメーター、ギミックのつまみ）
- Lab_Editor 側の変更

**失敗とみなすこと**
- 見た目を変えたせいで、押せる所・ドラッグできる所が今とずれる
- 切り替えると、どちらかの見た目で読めない文字・見えない部品が出る（明るい灰色の上の白い文字、暗い灰色の上の黒い文字など）
- 60fps を保てなくなる（文字は UiFont のサイズ別ハンドルで描く。毎フレーム SetFontSize を呼ばない）
- セーブデータの既存の中身（クリア状況など）が消える・壊れる

## 3. 制約

- 画面 1280×720。左バー x=0〜68、右パネル x=1030〜1280、下のパネル y=620〜720、モニターはその間。この配置は変えない
- 描画は DxLib の図形・文字・画像だけ。グラデーションは頂点の色（右パネル作り直しで使った `DrawPrimitive2D`）か1pxの線で描く
- 文字は UiFont を通す。MS UI Gothic が無いPC（日本語版でない Windows など）では、今のメイリオに戻す
- セーブデータは `%LOCALAPPDATA%\LabProject01\save.json`（`GameCfg::SaveData`）。キーを1つ足すだけで、無ければ案A
- コメントは日本語で細かく（このリポジトリの約束）。新しいヘッダーは BOM 付き UTF-8・CRLF

## 4. 考えた作り方と選んだもの

| 作り方 | 中身 | 判断 |
|---|---|---|
| **見た目の表＋共通の描き方（選んだ）** | 新しい `UiTheme.h` に「色の表」と「盛り上がり・へこみ・タブ・見出しバー・目盛り…の描き方」を置き、各部品はそれを呼ぶ。案A・案Bは表の中身と少しの作法（見出しの描き方など）の違いだけ | 部品は1回描き直すだけで2種類に対応でき、3つ目の見た目も足せる |
| 部品ごとに「Aなら…Bなら…」と書き分ける | 各描画に if を入れる | 書き分けが散らばり、片方だけ直し忘れが起きる。採らない |
| 見た目を画像（9スライス素材）で持つ | ui_style の窓枠と同じ仕組みを広げる | 小さな立体の線やグラデーションは素材だと作る手間が大きい。今回は採らない（あとで ui_style から上書きできる余地は残す） |

### 5.2 共通の描き方（関数）

- `Raised(box)`：盛り上がり（ボタン・タブ）。外側 左上=hilite／右下=dark、内側 左上=light／右下=shadow、地=face
- `Pressed(box)`：へこんだボタン（ON・押している間）。線を逆にする。地は案A=sel、案B=face の細かい市松（当時の「押し込まれた切り替えボタン」）
- `Sunken(box, fill)`：へこんだ窓（数値欄・色の輪の窓・状態バーの区画）
- `Etched(x1,x2,y)`：溝の区切り線（暗い線の1px下に明るい線）
- `GroupBox(box, caption)`：溝の線の枠と、左上の見出し文字（案B の作法。案A ではタブで代用）
- `Tab(box, text, active)`：タブ。開いているタブは手前に出て、下の線が無い
- `Caption(box, text)`：見出しバー（案A は灰色の上下グラデーション、案B は青の左右グラデーション＋白い太字）
- `HotText(x, y, text)`：ドラッグで変える値（hot の色＋点線の下線）
- `Meter(box, ratio, vertical)`：コストの目盛り（案A は区切りつき3色、案B は青いブロック）
- `StatusPane(box, text)`：状態バーの1区画
- `SelectionMarks(x1,y1,x2,y2)`：選んだ物の印＝白黒の点線（蟻の行列。4フレームごとに1px流れる）と、四隅・辺の真ん中の8つの小さな四角

### 5.3 文字

- UiFont の書体を「MS UI Gothic」、ぼかしなし（DxLib の通常フォント）にする。作れなかったら今のメイリオ（アンチエイリアス）に戻す
- サイズは 11〜13px が中心。太字は見出し・名前だけ
- ゲームの中の物の文字（頭上の HP など、縁取りの HudFont）は変えない

## 6. 部品ごとの見た目（配置は今のまま）

### 6.1 左のツールバー（EditToolbar.h）
- 地は face、右端に立体の線。いちばん上に「つまみ」（点々の帯）
- ツールのボタンは `Raised`、使っている間は `Pressed`。封印は今の錠前のまま
- 縦のコストのゲージは `Meter`（縦）、下に数値
- ツールの説明カード（? を押すと出る）は、見出しバーつきの窓（`Caption`＋face）にする。中のミニ実演はそのまま

### 6.2 右パネル（EditPanel.h・ColorGrade.h・DrawPixel.cpp のインスペクター描画）
- 「選んだ物」「画面全体」の2つの枠は残す。枠の見出しは、案A＝タブ、案B＝見出しバー「プロパティ」＋グループ枠
- 選んだ物のカード：絵は `Sunken`（黒）、名前は太字、説明・「種類：敵　HP：3」は小さい文字。右上の丸い札はやめる
- タイル：`Raised`、ON は `Pressed`。値のタイルの値は `HotText`（案A）／白い数値欄＋↔（案B）。帯（いまの位置）は1pxの細い線に
- 何も選んでいないとき：絵と説明文をやめ、枠の中に小さく「（何も選んでいません）」、状態バーに「右クリックで物を選ぶ」
- 効いている編集：「▼ 効いている編集」と、角の四角い札（sel の地）
- 画面全体：タブ（色と明るさ｜細かい調整）は `Tab`。色の輪＋四角は `Sunken`（well）の窓に入れる。右下の2色はペイントソフトの「描画色／背景色」の四角（角丸なし・黒い縁）。色相・強さ・明るさの数値を `HotText` で並べ、判定は `Sunken` の1行「判定：明るさ ふつう／フィルタ なし」。リセットは `Raised` のボタン

### 6.3 下のパネル（タイムライン・状態バー）
- 1段目（y=622〜644）：左に「タイムライン」のタブと時間表示（`Sunken`＋well、timeInk の等幅数字 `00:00:03;12`）。真ん中に巻き戻し・停止・早送り・カットのボタン（`Raised`／ON は `Pressed`。位置は今の ButtonRect のまま）
- 2段目（y=646〜690）：目盛り（タイル数。0・20・40…）と、カットの帯（y=660〜680。位置・当たり判定は今のまま）。今の位置の赤い線と三角
- 3段目＝状態バー（y=701〜720）：区画に分ける。左＝いまの状況の操作ヒント（今モニターの下に出しているもの）、中＝カットのコスト、右＝「F1 操作一覧　Esc メニュー」
- 今の「Ctrl＋クリック2回 カット」「右クリック 選択」の札は、状態バーのヒントにまとめて消す
- 時間表示は「ステージの経過時間」：世界が1コマ進むたびに増え、全体の巻き戻し中は減り、時間停止中は止まる（新しく数える）
- パネルが出ていないとき（F10 の拡大表示、編集パネルの無いふつうのプレイ）は状態バーも無いので、ヒントは今までどおりモニターの下に1行で出す（見た目だけテーマに合わせる：face の帯＋ink の文字）

### 6.4 情報窓（コイン・HP・コスト・層）と、上の状態の札
- 情報窓：`Caption`「情報」＋face の小窓。コインは数値、HP はハート、コストは `Meter`（横）、層は3つの切り替えボタン（今いる層が `Pressed`）
- 右上の状態の札（時間停止中・フィルタ・ズーム…）とトースト：角の四角い窓（face＋立体の線）に、色付きの文字。位置は今のまま
- 画面の縁の色（世界が止まっているときの琥珀・水色の枠）はそのまま
- モニターの下のヒント行は出さない（状態バーへ移した）

### 6.5 選んだ物の印
- 青い角かっこをやめ、`SelectionMarks`（白黒の点線＋8つの小さな四角）にする。白と黒が交互なので、どんな背景・色フィルタでも見える（右パネル作り直しで残った「色フィルタで角かっこが暗くなる」課題もこれで解消）
- ギミックの大きさのつまみ（黄色い四角）はそのまま

### 6.6 扇形メニュー
- 形と判定はそのまま。扇の地を face、乗っている扇を sel、縁を dark、文字を ink にする（案B では明るい灰色の扇になる）

### 6.7 Esc メニューと「設定」
- メニューの窓は `Caption`（「メニュー」）＋face。項目は `Raised` のボタン、選んでいる項目は `Pressed`
- 項目に「設定」を足す：つづける／もういちど／ステージセレクトへ／操作一覧／**設定**／ゲームをおわる
- 設定のページ：見出し「設定」、1行目「画面の見た目」に2つの選択肢（ラジオボタン）
  - 「暗い灰色（標準）」…案A
  - 「明るい灰色」…案B
  - 選んだ瞬間に画面全体（メニューの窓も含む）が切り替わる。Esc か「もどる」でメニューへ
  - キーボード（↑↓←→・Enter）とマウスの両方で選べる（今のメニューと同じ）
- 選んだものは、その場でセーブデータに書く（`"ui_theme": "dark"` / `"light"`。無い・読めない値は dark）

## 7. 作り方の指針

- `UiTheme.h`（新規）：5章の色の表・描き方・`Current()`／`Set(id)`。DxLib と UiFont だけに頼る
- 色を直接書いている所（EditPanel の `ColBack()` など、EditToolbar・ColorGrade・DrawPixel の HUD とパネルの描画）を、表の色・描き方の呼び出しに置き換える。EditPanel の `Col*()` は中身を表の色に向けるだけでも、呼び出し側は変えずに済む
- ColorGrade.h は UiTheme.h を読み込む（ColorGrade.h は DrawPixel.cpp の前のほうで読まれるので、UiTheme.h はそれより前に置ける形にする）
- 時間表示のコマ数は、世界の更新をしている所（時間停止・巻き戻しの判定と同じ所）で数える
- セーブデータの読み書きは `GameCfg::LoadSaveData` / `WriteSaveData` に1キー足す

## 8. 確かめ方

- 単体テスト（scratchpad の tests）：色の表（2つの見た目で、地と文字の明るさの差が十分＝読める）、セーブデータの往復（"ui_theme" の読み書き、無い・おかしい値は dark、ほかのキーが消えない）、時間表示の文字（コマ数→ `00:00:03;12`）、蟻の行列の点線の位置
- 画面の撮影（右パネル作り直しと同じ別ビルドと入力の差し替え）：2つの見た目それぞれで、何も選んでいない／敵／ギミック／プレイヤー／封印／扇形メニュー／Esc メニュー／設定のページ／時間停止中／色フィルタ中。キャンバスの案A・案B と見比べる
- 設定で切り替え → ゲームを終えて起動し直し → 選んだ見た目で始まること
- 同じ操作で、コスト・値・判定が今と同じであること（右パネル作り直しのときと同じ比べ方）。60fps を保つこと

## 9. 作る人に任せること

- 色の細かい値（表の値は目安。読みやすさを確かめて調整してよい）
- 点線・目盛り・ブロックの細かい寸法、立体の線の太さ（1px が基本）
- 扇形メニューの文字の大きさ、状態バーの区画の幅
