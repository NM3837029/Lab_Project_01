# 補正で実体化するタイルと、範囲を絞った色・明るさ補正 — 設計書

日付：2026-10-14 ／ 対象：`DrawPixel.cpp`・`ColorGrade.h`・`Lab_Editor`（タイル定義エディタ）

## 1. 目的（ユーザーの依頼）

1. 明るさ・暗さ・色の補正しだいで**当たり判定が現れる／消える地形タイル**を追加する。
2. その**基準（中心の値）と許容幅（ブレ）**を設定できるようにする。
3. 設定は **Lab_Editor のタイル定義エディタ**から操作できるようにする。
4. 色・明るさの補正は画面全体にしか掛からないので、**特定の物だけ／特定の範囲だけ**に絞って掛けられるようにする。

### 確認済みの方針（ユーザーの回答）
| 項目 | 決定 |
|---|---|
| 絞り方 | **選んだ物だけ**／**ドラッグした四角い範囲**（制作者が置く「補正ゾーン」は今回は作らない） |
| タイルが見る値 | **そのタイルの位置の値**（全体の補正に、そのタイルを含む範囲の補正を重ねた値） |
| タイル1枚の条件 | **1つの値を選び、「基準 ± 許容幅」**で指定（複数条件のANDは作らない） |
| 新タイルの用意 | **タイルエディタに雛形（プリセット）ボタンを足す**。作業中の `assets/tiles.json` は触らない |

### 非目標
複数条件のAND／制作者配置の補正ゾーン／アイテムへの局所補正／補正値の巻き戻し（補正は今までどおり巻き戻し対象外）／ゲームパッド。

## 2. 既存の仕組み（再利用するもの）
- `ColorGrade::PanelState`（明るさ・コントラスト・彩度・色相・色温度・色フィルタの色相と強さ）。局所補正の1件分は、これをそのまま持つ。
- `g_screenFx`（`ScreenFxSnapshot`）… 「画面に実際に出ている値」。ギミックの補正ロック足場・敵の判定が読んでいる。
- ギミック補正ロックの「見る値（gradeChannel 0〜5）」の並びと名前。タイルでも同じ並びにして、エディタの選択肢を共通にする。
- `GraphFilterRectBlt`（DxLib。矩形だけにフィルタを掛けられる）、`ColorGrade::DrawGraded`（明るさ・色フィルタの乗算）。
- 地形の当たり判定は `tileDefs[tid].isCollidable` を読む16か所（`DrawPixel.cpp`）。いずれも列・行を持っている。

## 3. 全体構成
独立した3つの部品に分け、**実装も2段階**で進める（段階1：タイル、段階2：局所補正）。

| 部品 | 役割 | 依存 |
|---|---|---|
| A. タイルのゲート定義＋判定 | `tiles.json` の項目、実体化の判定、見た目（半透明の幽霊表示） | `GradeAt()`（部品B） |
| B. 補正値の問い合わせ `GradeAt(x,y)` | 全体＋局所の合成値を返す。タイルと敵・ギミックが使う | `g_screenFx`・局所補正の一覧 |
| C. 局所補正（物／範囲）の操作・描画 | パネルの対象切替、範囲のドラッグ作成、gameScreen への描画 | B |
| D. Lab_Editor のタイルエディタ | ゲート項目の編集、雛形ボタン、マップ上の目印 | A のJSON仕様 |

段階1（A・D と、B の「全体の値だけ返す版」）で「補正で現れるタイル」が完結して遊べる。段階2（B の局所合成・C）で範囲・物への補正が加わり、タイルが局所値を見るようになる。

## 4. データ仕様（`tiles.json`、新規キーはすべて省略可）
既存のキーは変えない。次の7キーを足す。`gateChannel` が無い／-1 のタイルは従来どおり。

| キー | 型・既定 | 意味 |
|---|---|---|
| `gateChannel` | int・-1 | 見る値。-1=ゲートなし／0=明るさ／1=コントラスト／2=彩度／3=色相の回転(度)／4=色温度／5=**色フィルタの色**(輪の角度, 度) |
| `gateCenter` | float・値ごとの既定 | **基準値**。明るさ 0.4、コントラスト 0、彩度 1、色相 0、色温度 0、色フィルタ 0（赤） |
| `gateTolerance` | float・値ごとの既定 | **許容幅（±）**。明るさ 0.2、コントラスト 0.3、彩度 0.3、色相 35、色温度 0.3、色フィルタ 35 |
| `gateMinStrength` | float・0.5 | 色フィルタ(5)のとき、フィルタの強さがこれ未満なら「色なし」とみなして不成立。既存の色ロックと同じ0.5 |
| `gateInvert` | bool・false | true なら、条件を**満たすとき消える**（満たさないとき実体化する） |
| `gateGhostAlpha` | float・0.3 | 実体でない間の見た目の濃さ（0=見えない〜1） |
| `gateHoldWhileOverlap` | bool・true | 実体化しようとする位置にプレイヤー・敵が重なっている間は、実体化を保留する（めり込み・詰み防止） |

成立の判定：
- 通常の値(0〜4)：`|値 − 基準| ≤ 許容幅`。色相(3)は円周上の距離で比べる（−180と+180は隣り合う）。
- 色フィルタ(5)：`強さ ≥ gateMinStrength` かつ `色の輪の角度の円周上の距離 ≤ 許容幅`。
- 実体化＝（成立 XOR gateInvert）。

実体でないタイルは、当たり判定（`isCollidable`）も、`deadly` による被害も出さない（敵のAI用の足元・壁判定も含め、すべて同じ関数を通す）。

## 5. ゲーム側の設計

### 5.1 タイルの実体判定（部品A）
- `TileDefinition` に上記7項目を追加し、`tiles.json` の読み込みに足す（`DrawPixel.cpp` 4100付近）。
- 新関数 `TileSolid(tileDefs, tid, col, row)`：ゲートなしなら従来の `isCollidable`、ゲートありなら「`isCollidable` かつ そのマスが現在実体」。`isCollidable` を読む16か所をこの関数へ置き換える（`tid` の範囲チェックも関数へ集約。11015 の既存ガードと同じ扱い）。
- ゲート付きのマスは、ステージ読み込み時（`ResetStage`）に元のマップを走査して**一覧**を作る（壊れて消えても、巻き戻しで復活しても同じマスなので一覧は変えない。評価時に今のタイルを見直す）。
- 毎フレーム1回、一覧の各マスについて、そのマスの中心の `GradeAt()` から「成立か」を計算し、`g_tileGateSolid[行][列]` を更新する。更新は当たり判定より前（`g_screenFx` を写している位置のすぐ後）。
- 保留：`gateHoldWhileOverlap` が true で、前フレームまで実体でなかったマスが成立した場合、プレイヤーまたは有効な敵のAABBが重なっていれば更新しない。出ていった次のフレームに実体化する。
- 描画：ゲート付きで実体でないマスは `gateGhostAlpha` の半透明で描き、細い破線風の枠を足す（「そこに何かある」と分かる）。実体のマスは今までどおり。デバッグ描画の水色枠は実体のマスにだけ付ける。

### 5.2 補正値の問い合わせ（部品B）
```
struct GradeValues { bright, contrast, saturation, hue, temperature, tintHue, tintAmount }
GradeValues GradeAt(float worldX, float worldY)
```
- 全体の値は `g_screenFx`（`ScreenFxSnapshot` に `tintHue`・`tintAmount` を追加し、`cgState` から写す）。
- 局所の値は、そのワールド座標を含む**範囲の補正**を、合成規則（下記）で重ねる。物の補正はタイルの判定には使わない。
- 合成規則（`Screen_MixGrade` と同じ考え方）：明るさ・彩度は**掛け算**、コントラスト・色相・色温度は**足し算**（色温度は−1〜+1に収める）、色フィルタは**強さが大きいほう**を採用（同じなら局所）。
- 段階1では局所の一覧が空なので、全体の値をそのまま返す。

### 5.3 局所補正（部品C）— 段階2
**状態**：`LocalGrade { 種別(範囲/物), PanelState, [範囲] ワールド矩形, [物] 種別+添字 }`。範囲は最大4つ、物は何件でも。
ステージのリセット、「画面エフェクトが封印されたステージ」、編集コストが尽きたとき、すべて消す（今の `cgState` と同じ扱い）。**巻き戻し対象外**。

**操作（カラー補正パネル）**：
- パネル最上段に対象の切替タブ **［全体］［選んだ物］［範囲］** を足す。スライダー・色の輪・リセットは、選んでいる対象の `PanelState` を編集する。
- ［全体］＝今までどおり（X/C/T キーも全体にだけ効く）。
- ［選んだ物］＝右クリックで選んでいる敵・ギミック・プレイヤーに掛ける（複数選択なら同じ値を全員に）。何も選んでいなければ、パネルを灰色にして「物を選んでください」を出す。
- ［範囲］＝モニター上で左ドラッグして四角を作る（この間、空き地のドラッグは範囲選択でなく補正範囲の作成になる）。範囲の中をクリックで選択、選んだ範囲は枠とハンドルで表示し、`Delete` か［×］で削除。範囲の移動・リサイズは今回は作らない（作り直す）。
- パネルが y=232 から詰まっているため、タブ行ぶん全体を約22px下げ、いまの注意書き2行（「ダブルクリック＝初期値」「コスト：…」）は F1 の一覧へ移して外す。

**描画**（`gameScreen` の中。全体補正はその後に重なる＝自然に「局所→全体」の順で掛かる）：
- 範囲：世界を描き終えた直後（編集用の枠・つまみより前）に、範囲の矩形を作業用画面へコピー → `GraphFilterRectBlt` で彩度・色相・コントラスト → `DrawGraded` で明るさ・色フィルタ・色温度を掛けて貼り戻す。
- 物：その物の描画ブロックを、一時画面へ描いて補正し、シルエットだけ `gameScreen` へ貼る。**背景ごと四角く変わるのではなく、物の形だけ**が変わる。対象は敵・ギミック・プレイヤー（パーツ構成のものを含む）。
- 補正が無い物は今までどおり直接 `gameScreen` に描く（追加の負荷なし）。

**判定への反映**：物の局所補正は、その物自身が読む補正値（明暗で動く敵、色ロック足場など `g_screenFx`・`playerColorFilter`・`fxCurBright` を読む処理）にも反映する。物ごとの更新ブロックの前後で値を差し替える RAII（`LocalFxScope`）を使う。範囲の補正は、範囲の中にある物の判定にも反映する（物の位置が範囲に入っているとき、その範囲の値を重ねる）。

**コスト**：局所補正のどれかに「コストを使う補正」（明るさ・色フィルタ）があれば、画面エフェクトのドレインを**1回分**払う（件数で増やさない）。

### 5.4 ゲーム内の表示
- 範囲は半透明の枠で見せる（選択中は強調）。
- 右上のバッジに「補正：範囲 1／物 2」のように数を出す（既存のバッジ欄）。
- F1 の一覧と README に、タブの使い方とタイルのゲートを追記。

## 6. Lab_Editor（部品D）
`TileDef`（`StageData.cs`）に7項目を追加。**【重要】`TileEditorForm.cs` に3か所ある `TileDef` の複製／読み書き（コンストラクタの複製・`ReadTilesFromGrid`・`LoadGrid`）にも必ず足す**（過去に、片方だけだと保存で値が消えた）。

- グリッドに列を増やすと既に窮屈なので、**一覧の下に「補正ゲート」の詳細パネル**を置く（選んだ行を編集）。
  - 見る値（コンボ：なし／明るさ／コントラスト／彩度／色相／色温度／色フィルタの色）、基準、許容幅、（色フィルタのとき）強さの下限、反転、非実体時の濃さ、重なり保留。
  - 許容範囲を一目で見せる：明るさなら「0.20 〜 0.60」、色なら輪の上に弧、のような**帯の図**と、基準色のサンプル表示。
  - 入力値の範囲を丸める（許容幅は0以上、色相は0〜360）。
- **雛形ボタン「＋ 明暗・色タイル」**：選ぶと新しいタイル行を作る。名前・色・`collidable=true`・ゲート項目を埋め、画像は空（色塗りタイル）。雛形：暗いときだけ実体化／明るいときだけ実体化／赤・緑・青フィルタのときだけ実体化／暗いときだけ消える／明るさがふつうの帯のときだけ実体化。
- マップ編集（`MapCanvas`）では、ゲート付きのタイルに小さな目印（◐）を重ねる。
- 既存の `assets/tiles.json` は編集しない。雛形は、ユーザーがボタンを押したときだけ追加される。

## 7. 検証
- **ゲームの入力差し替え**（`testroot`・フック付きビルド）で、専用のテストステージとテスト用 `tiles.json` を `testroot` に置いて確認する（ユーザーの `assets` は触らない）。
  - 暗いとき実体化：明るさ 1.0→0.3 で、足場として立てる／戻すと落ちる。許容幅の境目（0.59／0.61 など）で切り替わる。
  - 反転、色フィルタ（赤の許容 ±35 度の内外）、色相の円周比較（−170 と 175）。
  - 重なり保留：実体化しようとするマスにプレイヤーが立っているとき、出るまで実体化しない。
  - 敵の足元判定・タイル破壊・巻き戻しとの併用で落ちない。
  - 段階2：範囲だけ暗くして、その範囲内のタイルだけ実体化／範囲の外は変わらない。物だけ補正して、その物の形だけ色が変わり、背景は変わらない。物の補正で、その物の暗いとき動く敵の挙動が変わる。範囲の外の敵は変わらない。
- スクリーンショットで、幽霊表示・範囲の枠・パネルのタブ・HUD のバッジが重ならないことを確認。
- Lab_Editor は、ビルドして雛形追加→保存→JSON に7キーが出る→再読み込みで値が残る、の往復を確認。**既存の `tiles.json` を読んで保存し直しても差分が出ない**（新キーは既定値のとき書かない）ことを、テスト用コピーで確認。
- 既存ステージ・既存タイルは、新キーが無いので挙動が変わらない（回帰ゼロをフック付きビルドで確認）。

## 8. リスクと対処
| リスク | 対処 |
|---|---|
| `isCollidable` の置き換え漏れ | 16か所を `grep` で洗い出し、置き換え後に `isCollidable` を直接読む箇所が定義の初期化以外に残っていないことを確認 |

## 9. 実装の順序（概略。詳細は実装計画で）
1. 段階1：`GradeAt`（全体のみ）→ `TileDefinition`・読み込み → `TileSolid` への置き換え → 一覧と毎フレーム更新・保留 → 描画 → Lab_Editor（項目・詳細パネル・雛形・目印）→ 検証 → コミット。
2. 段階2：局所補正の状態 → `GradeAt` の合成 → パネルのタブ・範囲の作成 → 範囲の描画 → 物の描画（一時画面） → 判定への反映（`LocalFxScope`）→ コスト・リセット → 表示（枠・バッジ）→ F1・README → 検証 → コミット。
