# 色・明るさで出入りするギミックの「出る条件」編集の改良（設計）

日付：2026-11-22　対象：Lab_Editor（C#）とゲーム本体（DrawPixel.cpp）

## 1. 目的と背景

画面の明るさ・色で現れたり消えたりするギミック（色ロック足場・明暗ロック足場・補正スイッチ・補正ロック足場・明暗ゾーン・色調ゾーン）は、作るのも置くのも確かめるのも手間がかかる。ユーザーからは「アセットを作るとき・ステージに置くとき・ゲームで確かめるとき、どれも手間取っている」と聞いている。

今の困りごと（調査の結果）：

| 場面 | 今のやり方 | 困るところ |
|---|---|---|
| アセットを作る（補正スイッチ26・補正ロック足場27） | 「見る値」を選び、下限・上限を数字で入れる（-999／999＝未指定） | 値ごとに単位も範囲も違う（明るさ 1.0＝100%、色相は度、コントラスト -1〜1…）。範囲を知らないと決められない |
| アセットを作る（明暗ゾーン18・色調ゾーン19） | 色調R・G・B、彩度、色相、コントラストを数字で入れる | どんな色になるかの見本が無い |
| ステージに置く（色ロック22・明暗ロック23） | 置いた物の「パラメータ」欄に `1`/`2`/`3`（赤緑青）・`dark`/`bright` を手で打つ | 選択肢が無く、打ち間違えても気づけない |
| ステージに置く（全部） | マップ上は同じ絵で並ぶ | どれが何色・何の条件かが地図で見分けられない |
| ステージに置く（補正ロック足場27） | 条件はアセット単位 | 赤用・青用を置き分けるには、アセットを2つ作る必要がある |
| ゲームで確かめる | 条件を満たすと実体化、満たさないと半透明 | 「今の値」と「出る範囲」がどれだけ離れているかが見えない |

## 2. ゴール／しないこと／失敗とみなすこと

**ゴール**
- 「出る条件」を決める画面を1つの部品（条件エディタ）にまとめ、アセット画面・ステージの配置・（表示の考え方として）ゲーム内で、同じ見せ方・同じ言葉で扱えるようにする
- 数字を覚えずに決められる（目盛りつきのつまみ・よく使う条件のボタン・条件を文章で表示）
- 地図の上で、各ブロックの条件が見分けられる
- ゲーム中、近くのロック足場・スイッチに「今の値」と「出る範囲」が見える
- 補正ロック足場（27）・補正スイッチ（26）を、置いた場所ごとに条件を変えられる

**しないこと**
- 色ロック足場（22）・明暗ロック足場（23）を補正ロック足場（27）へ統合・変換すること（既存ステージのデータを書き換えるため見送り）
- 条件の判定のしかた（成立の計算）を変えること。追加は「置いた物ごとの上書き」だけ
- カラー補正パネルそのものの改修、新しいギミックタイプの追加

**失敗とみなすこと**
- 既存のステージ・アセットの挙動が1つでも変わる
- 何も触っていないのに、ステージ・アセットのJSONに新しいキーが書かれる（チームの差分が汚れる）
- エディタで決めた条件と、ゲーム内の判定・表示の文章が食い違う

## 3. 制約

- コメントは自分のコードすべて日本語で細かく書く
- C++ は UTF-8（BOM付き）・CRLF。`/execution-charset:utf-8` 前提
- 既存の値の意味を守る：gradeMin/gradeMax の -999/999 は「未指定」、22 の param は "1"/"2"/"3"（空なら赤）、23 の param は "bright" 以外はすべて暗い
- ゲーム内の ImGui ステージエディタで保存しても、新しいキーが消えないこと（`PlacedGimmick` に持たせて書き戻す）
- チームの未コミットのアセット（`assets/stages/Dossun.json`・`Color.json`）には触れない
- コミット時は `update_prebuilt.bat` で prebuilt/ を作り直す

## 4. 進め方の候補（検討した案）

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **① 条件エディタを1つの部品にそろえる（採用）** | 条件を決める部品を1つ作り、アセット画面・ステージの右クリックで同じものを使う。地図の印・ゲーム内メーターも同じ言葉で出す | 操作と言葉が3つの場面でそろう。1か所直せば全部に効く | 作る量が多い |
| ② 今の画面にそれぞれ手直しを足す | パラメータ欄を選択式に、数字欄に説明を、ゲームに文字を | 手早い | 場面ごとに操作がバラバラのまま |
| ③ 22/23 を 27 に統合 | 古い足場を補正ロック足場へ変換し、仕組みを1本化 | 仕組みが最も単純 | 既存ステージのデータ書き換えが必要。失敗とみなすことに当たる |

ユーザーが①を選んだ。

## 5. 設計

### 5.1 条件の共通モデル（エディタ側）

`GradeCondition.cs`（新規）に、条件を表す型と、値ごとの情報をまとめる。

- 条件の種類
  - **範囲条件**（26・27）：見る値（0 明るさ／1 コントラスト／2 彩度／3 色相／4 色温度／5 色フィルタ／6 拡大中／7 縮小中）＋下限・上限（未指定あり）
  - **色の条件**（22）：赤・緑・青のどれか（param "1"/"2"/"3"）
  - **明暗の条件**（23）：暗い・明るい（param "dark"/"bright"）
- 値ごとの情報（ゲームの `GradeRange` の既定値・`ColorGrade.h` の範囲と一致させる）

| 見る値 | 表示の単位 | つまみの範囲 | 未指定時の既定（ゲームと同じ） |
|---|---|---|---|
| 明るさ | %（1.0＝100%） | 30〜170% | 〜60% |
| コントラスト | ±100 | -100〜+100 | +30〜 |
| 彩度 | %（1.0＝100%） | 0〜200% | 〜20% |
| 色相 | 度 | -180〜180 | 30〜180 |
| 色温度 | ±100（寒色〜暖色） | -100〜+100 | +30〜 |
| 色フィルタ | 赤・緑・青 | 選択 | 赤 |
| 拡大中（Z） | 倍 | 1.0〜2.0 | 1.15倍〜 |
| 縮小中（V） | 倍 | 0.5〜1.0 | 〜0.95倍 |

- 条件を日本語の文にする関数（例：「明るさが 30〜60% のとき出る」「赤のフィルタのとき出る」）。ゲームの `GradeConditionLabel` と同じ言い方にそろえる
- 条件の色（地図の枠・見本に使う）：赤緑青はその色、暗いは紺、明るいは黄、範囲条件は値ごとの代表色（ゲームの `GradeConditionColor` と同じ考え方）

### 5.2 条件エディタ（共通の部品）

`GradeConditionEditor.cs`（新規の UserControl）。

```
┌ 出る条件 ─────────────────────────────┐
│ 見る値: [明るさ ▼]                         │
│ 暗 ■■■■■■■■■■■■■■ 明   ← 値に合わせたグラデーション │
│    0% ──●────●── 200%                      │
│ □ 下限なし   □ 上限なし                        │
│ 「明るさが 30〜60% のとき出る」                  │
│ よく使う: [暗いとき][明るいとき][白黒][暖色]…      │
└────────────────────────────────────┘
```

- 見る値を選ぶと、つまみの範囲・単位・背景のグラデーション（明るさ＝黒→白、彩度＝灰→鮮やか、色相＝虹、色温度＝青→橙、拡大縮小＝無地）が切り替わる
- つまみは2つ（下限・上限）。「下限なし」「上限なし」のチェックで -999／999 にする
- 色フィルタ（5）のときは、つまみの代わりに赤・緑・青のボタン
- 22 用は赤・緑・青のボタンだけ、23 用は暗い・明るいのボタンだけの簡易版になる（同じ部品のモード切替）
- 値が変わるたびに Changed イベントを出す（呼び出し側が保存する）

### 5.3 アセット画面（ギミックの詳細）

- 26・27：今の「見る値」「下限」「上限」の3つの欄を、条件エディタ1つに置き換える
- 18・19：今の数字欄はそのまま残し、その下に**見本**を出す。見本は、白〜黒のグレーの帯と色見本（赤・緑・青・肌色）に、入力中の値（色調RGBの掛け算・彩度・色相・コントラスト、18 は明転・暗転の明るさ）をかけた絵。数字を変えるとすぐ描き直す
- プリセット（GimmickPresets）は今のまま使える

### 5.4 ステージの配置

- 置いた物の右クリックメニューに **「出る条件…」** を足す（22・23・26・27 のときだけ出る）。条件エディタの入ったダイアログを開く
  - 22・23：決めた条件を param に書く（"1"/"2"/"3"、"dark"/"bright"）
  - 26・27：置いた物ごとの上書きとして書く。ダイアログに「アセットの設定に従う」のチェックを置き、外したときだけ上書きする
- 置いた物ごとの上書きのJSON：配置のエントリに `gradeChannel`・`gradeMin`・`gradeMax` の3つ。**上書きしていない配置には書かない**
- 操作は保存と「元に戻す」の対象にする（既存の「編集の可否を設定…」と同じ扱い）
- 地図の上の印：22・23・26・27 の配置に、条件の色で枠を描き、上に短い文字（「赤」「暗」「明るさ≤60%」など）を出す。18・19 のゾーンは、範囲を条件の色で薄く塗る

### 5.5 ゲーム本体

- **置いた物ごとの上書き**：`Gimmick` に上書きの有無と3つの値を持たせ、ステージJSONから読む。`GradeConditionMet`・`GradeConditionLabel`・`GradeConditionColor` を「ギミックの個体」を受け取る形にし、上書きがあればそちらを使う（26・27 の判定・ラベル・色の全か所）
- ImGui ステージエディタ：`PlacedGimmick` にも3つの値を持たせ、読み込み・保存で落とさない
- **近くのメーター**：プレイヤーが近く（中心どうしが約4マス以内）にいる 22・23・26・27 の上に、小さなメーターを出す
  - 範囲条件：横長の帯（5.2 と同じグラデーション）に、出る範囲を明るく、今の値を縦線で示す
  - 22：赤・緑・青の3つの丸。必要な色に枠、今のフィルタの色を塗る
  - 23：暗い〜明るいの帯にしきい値（60%・130%）と今の値
  - 既存の「条件の文字」は残す。メーターはその下に重ねて出す
  - 画面がズームや補正で変わっていても読めるよう、HUD と同じ層（補正の影響を受けない層）に描く

### 5.6 確認のしかた

- エディタ：検証用の WinForms プログラムから、条件エディタの操作 → 保存 → 読み直しの往復（22 の param、27 の上書きキー、上書きなしではキーが出ないこと）と、画面のスクリーンショット
- ゲーム：検証用の一時フックを入れた別ビルドで、上書きした 27 が上書きの条件で出入りすること、メーターの画面写真。フックはコミット前に必ず外す
- 既存ステージの JSON を読み込んで保存し、差分が出ないこと
