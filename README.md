# Lab_Project_01

DxLib(C++)で作られた2Dアクションゲーム本体と、それ専用のステージ/アセット編集ツール「Lab_Editor」(C# / .NET 8 / WinForms)から構成されるプロジェクトです。時間巻き戻し(リワインド)ギミックを軸にした横スクロールアクションで、敵・ギミック・アイテム・トリガーイベント・BGM/SEなどをすべてLab_Editor側のGUIとJSONアセットファイルで組み立てます。

さらに、既存のプリセット挙動だけでは足りない場合のために、**Scratch風のビジュアルブロックエディタで敵・ギミック・アイテムの挙動を自作できるスクリプトシステム**と、**複数の画像パーツを組み合わせて1つの敵・ギミック・アイテムを構成できる複合オブジェクト・システム**（ドアの開閉パネル、回転するファイアバー、体が分かれたボス等）を備えています。

## 導入方法（セットアップ）

### 必要環境

- Windows 10/11
- **Visual Studio 2022**（「C++によるデスクトップ開発」ワークロード）… ゲーム本体のビルド用
- **.NET 8 SDK** … Lab_Editorのビルド用
- DxLibは`DxLib_VC/`に同梱済みのため追加インストール不要

### ビルド手順

1. **ゲーム本体**
   - `Lab_Project_01.sln` をVisual Studio 2022で開く
   - 構成 `Debug` / プラットフォーム `x64` を選択してビルド
   - 成功すると `x64/Debug/Lab_Project_01.exe` が生成される
   - コマンドラインの場合:
     ```
     "C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" Lab_Project_01.vcxproj /p:Configuration=Debug /p:Platform=x64
     ```

2. **Lab_Editor**
   - `Lab_Editor/Lab_Editor/Lab_Editor.csproj` を Visual Studio または `dotnet build` でビルド
     ```
     cd Lab_Editor/Lab_Editor
     dotnet build
     ```
   - 生成された `bin/Debug/net8.0-windows/Lab_Editor.exe` を実行する

Lab_Editorはプロジェクトルート（`Lab_Project_01.vcxproj`が存在するフォルダ）を自動検出し、`assets/`配下を直接読み書きします。ゲーム本体側は**先にビルドしておく**必要があります（Lab_Editorの「▶ プレイ」ボタンは`x64/Debug/Lab_Project_01.exe`を起動する仕組みのため）。

## 使い方

1. Lab_Editorを起動すると、既存のステージ一覧が左側に表示される（無ければ`stage_01`が自動生成される）
2. ツールバーで **レイヤー(遠景/メイン/近景/イベント)** と **ツール(ペン/消しゴム/選択)** を切り替えてタイルマップを編集
3. 右側パネルで敵・ギミック・アイテムを選択し、マップ上をクリックして配置（イベントレイヤー時）
4. 「アセット管理」ボタンから敵・ギミック・アイテム・コモンイベントの定義そのものを編集（パラメータ調整・挙動スクリプト・パーツ編集もすべてここから行う）
5. 「▶ プレイ」でゲーム本体を起動して実際に確認、または「ここからプレイ」で任意の位置からテストプレイ
6. 保存は自動（タイル編集の1ストローク完了時、各種設定変更時）。ゲーム内で**矢印キー全押し**するとゲームを閉じてエディタに戻る（隠しショートカット）

## 敵・ギミック・アイテムの挙動スクリプト（Scratch風ビジュアルブロックエディタ）

既存の20種の敵・24種のギミックには「⚙ 挙動パラメータ」パネル（タイプ選択時に自動で表示項目が切り替わる）で速度・射撃間隔・索敵範囲などを調整できます。それだけでは足りない、完全にオリジナルな敵・ギミックを作りたい場合のために、**Scratchを参考にしたビジュアルなブロックエディタ**を用意しています。JSONを手書きする必要はなく、Lab_Editorの「🧩 挙動スクリプトを編集」ボタンからパレットのブロックをキャンバスへドラッグ&ドロップして組み立てられます。

### 使い方

1. アセット管理画面で、敵の`type_enum`を**20（カスタムスクリプト）**、またはギミックの`type_enum`を**24（カスタムスクリプト）**に設定する
2. 対象の行を選択した状態で「🧩 挙動スクリプトを編集」ボタンを押す
3. 開いたエディタで、左のパレットからブロックをキャンバスへドラッグして縦に積み上げていく。`Forever`/`If`等のC字ブロックの中にはブロックをネストできる
4. 数値・文字列・選択式の入力欄はクリックしてその場で編集できる。レポーター（丸型）/真偽値（六角形）ブロックは、対応するソケット（数値欄・条件欄）へドラッグして差し込める
5. 差し込み済みのブロックは右クリックで取り外せる。ブロック単体はキャンバス上で選択してDeleteキーで削除できる
6. 「💾 OK」で確定すると、そのままアセット管理画面の保存対象に反映される

保存されるデータの実体はJSON AST（下記参照）で、`assets/enemies.json`/`gimmicks.json`の`script`フィールドに格納されます。手書きで直接JSONを編集することも可能です。

```json
{
  "id": "my_custom_enemy",
  "name": "自作の敵",
  "type_enum": 20,
  "hp": 3, "width": 32, "height": 32, "sprite": "img/enemy.png",
  "script": [
    {
      "hat": "OnSpawn",
      "body": [
        { "op": "Forever", "body": [
          { "op": "MoveDirection", "dir": "Toward", "speed": 2 },
          { "op": "Wait", "frames": 30 },
          { "op": "Shoot", "angle": { "op": "DirectionToPlayer" }, "speed": 6, "damage": 1 }
        ]}
      ]
    }
  ]
}
```

実際に動く参考例が `assets/enemies.json`（`enemy_script_sample` / `enemy_script_patrol` / `enemy_script_stationary` / `enemy_script_dashcharger`）と `assets/gimmicks.json`（`gim_script_movingplatform`）に入っているので、そのまま参照・改造してください（複合パーツの参考例は次章参照）。

### 命令（ブロック）一覧

| カテゴリ | 命令 | 内容 |
|---|---|---|
| 制御 | `OnSpawn` / `OnDamaged` / `OnDeath`（ハット） | スクリプトの開始点。出現時／被ダメージ時／死亡時にそれぞれ実行される |
| 制御 | `Forever { body }` | 本体を無限に繰り返す |
| 制御 | `Repeat { count, body }` | count回繰り返す |
| 制御 | `RepeatUntil { cond, body }` | condが真になるまで繰り返す |
| 制御 | `If { cond, body }` / `IfElse { cond, body, else }` | 条件分岐 |
| 制御 | `Wait { frames }` | 指定フレーム待機 |
| 制御 | `WaitUntil { cond }` | condが真になるまで待機 |
| 動き | `MoveDirection { dir: "Left"/"Right"/"Toward"/"Away", speed }` | 方向・速度を指定して移動 |
| 動き | `ApplyImpulse { vx, vy }` | 速度を直接設定 |
| 動き | `SetPosition { x, y }` / `OffsetPosition { dx, dy }` | 位置を設定／相対移動 |
| 動き | `FaceTowards` | プレイヤーの方を向く |
| 動き | `Oscillate { min, max, periodFrames }` | Y座標をmin〜maxで周期的に振動（動く足場等向け） |
| 動き | `SetLocalOffset { dx, dy }` | **パーツ専用。** 親（複合体本体）の現在座標からの相対位置を設定する |
| 動き | `SetLocalOffsetPolar { angle, radius }` | **パーツ専用。** 親を中心に「角度・半径」で相対位置を設定する。`Cos`/`Sin`を2回書かずに済む糖衣構文で、ファイアバーのように「同じ角度・パーツごとに異なる半径」を並べて回転する棒を作るのに使う |
| 動き | `SetAngle { angle }` | 見た目の回転角(ラジアン)を設定 |
| 攻撃・演出 | `Shoot { angle, speed, damage }` | 指定角度(ラジアン)へ弾を発射 |
| 攻撃・演出 | `ShootAtPlayer { speed, damage }` | プレイヤーへ自動照準して発射 |
| 攻撃・演出 | `SetInvincible { on }` / `SetScale { scale }` | 無敵状態／表示スケールの変更 |
| 攻撃・演出 | `SetVisualEffect { kind: "brightness"/"zoom", intensity }` | 画面演出 |
| 攻撃・演出 | `PlaySound { slot }` | 効果音を再生（`se.json`/`ui_se.json`に登録したidを指定。BGM再生には未対応） |
| 変数 | `SetVar { name, value }` / `ChangeVar { name, value }` | 変数の設定／加算 |
| センサー(式) | `SelfX` / `SelfY` / `PlayerX` / `PlayerY` / `DistanceToPlayer` / `DirectionToPlayer` / `Random{min,max}` / `GetVar{name}` | 数値を返す式ブロック |
| センサー(式) | `Time` | ゲーム開始からの経過フレーム数（リセットされないグローバルな「時計」） |
| センサー(式) | `ParentX` / `ParentY` | **パーツ専用。** 親（複合体本体）の現在のワールド座標 |
| センサー(式) | `PartIndex` | **パーツ専用。** 自分が親のパーツ配列の何番目か(0始まり)。同一スクリプトを複数パーツで共有しつつ、パーツごとに異なる位相をつけるのに使う |
| 演算子(式) | `Add`/`Sub`/`Mul`/`Div` `{a,b}` / `Const{value}` | 四則演算 |
| 演算子(式) | `Sin{a}` / `Cos{a}` | 三角関数（ラジアン）。回転・周回運動の自作に使う |
| 条件(式) | `Gt`/`Lt`/`Eq`/`And`/`Or`/`Not` `{a,b}` / `IsGrounded` / `IsWallAhead` / `IsGroundAhead` | 真偽値を返す式ブロック |

`OnDamaged`/`OnDeath`は、`OnSpawn`とは独立した専用の実行状態で発火するため、`OnSpawn`側で`Forever`ループを回している最中に被弾・死亡してもそのループは巻き込まれて止まらない。ただし`OnDeath`は死亡と同じフレーム内で完結する処理（`PlaySound`/`SetVisualEffect`/`Shoot`等）のみを想定しており、`Wait`を挟む複数フレームにまたがる演出には対応していない（死亡直後は更新自体が止まるため）。

### 安全設計

無限ループを含むスクリプトを書いてもゲームがフリーズしないよう、以下の安全装置が入っています。

- `Forever`/`Repeat`が1周してループの先頭に戻る瞬間、必ずそのフレームの実行を打ち切る（次フレームで続きから再開）
- 1体・1フレームあたりの命令実行数に上限（500）
- 全スクリプト実行体の合計で1フレームあたりの命令数に上限（20000）
- コールスタックの深さに上限（32）。超えた場合はエラーとしてログに記録し、そのスクリプトの実行を停止する（"Faulted"状態、ゲーム自体は継続）

デバッグモード表示中（`isDebugDrawMode`）は、スクリプトで動く敵・ギミックの上に実行状態（RUN/DONE/FAULT、スタック深さ、待機フレーム数、Faulted時はエラー内容）が表示されます。さらに、デバッグモードでなくてもFaulted状態の敵・ギミックには常に赤字で「SCRIPT ERROR」と表示されるため、手編集したJSONが壊れている場合もプレイ中に気付けます。

## 複合パーツ・オブジェクト・システム（マルチスプライト構成の敵・ギミック・アイテム）

通常の敵・ギミック・アイテムは1つの画像・1つの当たり判定だけで構成されますが、扉（開閉する複数パネル）、マリオ風ファイアバー（軸を中心に回転する複数の火の玉）、体が分かれた敵（各部位を個別に攻撃できるボス等）のような**複数の画像パーツを組み合わせたオブジェクト**を作ることができます。パーツは前章のブロックスクリプトで自由に制御でき、**パーツごとに個別の当たり判定・HP**を持てます。

### 使い方

1. アセット管理画面で対象の敵/ギミック/アイテムの行を選択し、「🧩 パーツを編集」ボタンを押す（このボタンは`type_enum`に関係なく、どのタイプの敵/ギミック/アイテムでも使える。パーツは本体の挙動タイプとは独立して動作するため）
2. エディタは左（パーツ一覧）／中央（合成プレビュー）／右（選択中パーツの詳細）の3分割で、境界線をドラッグして各領域の広さを調整できる。左の一覧でパーツを追加・選択し、右側の詳細パネルで画像・offsetX/offsetY・表示スケール・HP・zOrder（奥/手前）を編集する。中央の合成プレビューではパーツをドラッグして初期位置を直接調整できる
3. 右側の詳細パネルの「📝 挙動スクリプトを編集」ボタンから、そのパーツ専用の挙動スクリプトを編集する（前章と全く同じブロックエディタ）。「🧩 このスクリプトを全パーツへ」ボタンで、選択中のパーツのスクリプトを全パーツにコピーできる（`PartIndex`で位相・半径をずらせば、同一スクリプトのままファイアバーの火の玉のように動きを分岐させられる）
4. 左下の「🌀 回転する棒として配置...」ボタンから、マリオのファイアバーのように中心から一直線に並んだ球が棒状に回転するパーツ一式（個数・間隔・回転速度・画像を指定）を一括生成できる
5. 「💾 OK」で確定し、通常通りアセット管理画面から保存する

### パーツの仕組み

- パーツは`PartDef`（テンプレート）として敵/ギミック/アイテムの定義に付随する（JSON上は`parts`配列）。`parts`が空の既存アセットは完全に無変更で動作する
- 各パーツは`offsetX`/`offsetY`（本体からの初期相対位置）、`width`/`height`（表示サイズ）、`hitboxOffsetX/Y`・`hitboxWidth/Height`（個別の当たり判定）、`scale`、`hp`、`zOrder`、`script`を持つ
- **HP=0のパーツは破壊不能な常在ハザード**（ファイアバーの火の玉のように、触れると常にダメージを与え続ける）。**HP≧1のパーツは弾で個別に破壊可能**で、破壊されても本体自身のHP・生死には一切影響しない（弱点部位のみを狙い撃つボス戦などに使える）
- パーツはスクリプトの`SetLocalOffset`/`SetLocalOffsetPolar`/`SetAngle`で自由に動かせる。`ParentX`/`ParentY`で本体の現在座標を、`PartIndex`で自分の番号を、`Time`で経過フレーム数を、`Sin`/`Cos`で三角関数を取得できるため、周回運動・振動・追従・扇状配置などをスクリプトのみで組める。特に「同じ角度・パーツごとに異なる半径」で`SetLocalOffsetPolar`を使うと、ファイアバーのように一直線に並んだまま回転する棒状の配置になる（左のパーツ一覧の「🌀 回転する棒として配置...」ボタンで自動生成できる）
- パーツにスクリプトが無い場合は、初期位置に固定されたまま**動く本体には追従しない**（本体が移動しても最初の座標に留まる）。動く本体に追従させたい場合は、`OnSpawn { Forever { SetLocalOffset(固定オフセットX, 固定オフセットY); Wait 1 } }` のような最小限の追従スクリプトを入れておく
- `OnDamaged`/`OnDeath`はパーツ単位でも発火する。パーツが破壊されるとそのパーツ専用の`OnDeath`が一度だけ実行される
- 描画順は`zOrder`が負のパーツ→本体→`zOrder`が0以上のパーツ、の順（本体より奥/手前を指定できる）

## よくある問題と対処方法

| 症状 | 原因・対処 |
|---|---|
| Lab_Editorの「▶ プレイ」を押しても何も起きない／「ゲーム実行ファイルが見つかりません」 | ゲーム本体(`Lab_Project_01.vcxproj`)を先にビルドし、`x64/Debug/Lab_Project_01.exe`を生成してください |
| `dotnet build`が「ファイルをコピーできません...別のプロセスによってロックされています」で失敗する | Lab_Editor.exeが起動中です。閉じてから再ビルドするか、`dotnet build -c Release`で別出力先にビルドしてください |
| 敵・ギミックの画像が表示されない／`Log.txt`に「画像ファイル...がありません」と出る | 該当のスプライト画像(`img/`フォルダ)が実際には存在しません。アセット管理の「📁選択」で画像を割り当ててください |
| BGM/SEが鳴らない | `assets/bgm.json`/`se.json`/`ui_se.json`のエントリで **id・name・fileがすべて空でない**ことを確認してください（IDが空のエントリは読み込まれません）。サウンド管理画面で保存しようとすると空欄チェックで警告が出ます |
| 敵のHP・移動速度などをテンプレートで変更しても反映されない | アセット管理画面で編集後、必ず「💾 保存して閉じる」を押してください。マップ上の配置自体を打ち直す必要はありません |
| 自作スクリプトを書いた敵・ギミックが動かない／エラーになる | `logs/error.log`を確認してください。`[BehaviorScript] [Tick] ERROR: ...`という行があれば、スクリプトのJSON構造（`body`が配列になっているか、`cond`の式が正しいか等）を見直してください。何も表示されない場合は`type_enum`が20（敵）/24（ギミック）になっているか確認してください |
| 「🧩 挙動スクリプトを編集」ボタンを押しても「対象外」と言われる | 敵は`type_enum=20`、ギミックは`type_enum=24`（いずれも「カスタムスクリプト」）の行でのみ使えます。「🧩 パーツを編集」はタイプに関係なくどの行でも使えます |
| パーツを追加したのに、本体が動くとパーツが置き去りになる | パーツにスクリプトが無い（または`OnSpawn`が無い）と、初期位置に固定されたまま本体を追従しません。`SetLocalOffset`で固定オフセットを毎フレーム設定する最小スクリプトを入れてください（前章参照） |
| ソケット（数値欄・条件欄）に別のブロックを差し込めない | 既にブロックが差し込まれているソケットには上書きドロップできません。右クリックで一度空にしてからドラッグし直してください |
| 新しく`.h`/`.cpp`ファイルを追加したらビルドエラーになる（謎の構文エラーが大量に出る） | このプロジェクトはソースファイルの文字コード判定でCP932(Shift-JIS)とUTF-8のせめぎ合いがあり、**LF改行のみのファイルだと日本語コメントの解釈でコンパイラが誤爆することがあります**。新規ファイルは既存ファイルと同様にCRLF改行で保存してください |
| ステージファイルを直接編集したらゲームが起動しなくなった | JSON構文エラーの可能性が高いです。`node -e "JSON.parse(require('fs').readFileSync('assets/stages/xxx.json','utf8'))"`などで構文チェックしてから再度読み込んでください |

## 既知の制限・今後の予定

- 巻き戻し（リワインド）機能は位置・速度・向き・スケール・角度・生存状態のみを記録しており、スクリプトの実行状態（変数・コールスタック）やパーツのHPは巻き戻し対象に含まれません。スクリプトで動く敵・ギミック・パーツを巻き戻すと、見た目の位置は戻ってもスクリプトの内部状態は戻らない場合があります
- `OnDeath`は死亡と同じフレーム内で完結する処理のみ対応しており、`Wait`を挟む複数フレームの死亡演出は未対応です
- アイテムは取得と同時に画面から消えるため、アイテムのパーツは装飾的な意味合いが中心です（取得判定はパーツに触れても本体と同様に発生します）
- 一部のギミック（ポータル・橋・破壊ブロック等）は専用スプライト画像が用意されておらず、ゲーム内で表示が欠けることがあります。複合パーツのテンプレートも同様に、既存の汎用画像（`img/enemy.png`等）を仮のスプライトとして使っているものがあります
- 効果音は`jump`（ジャンプ音）のみ登録済みで、敵の攻撃音・被弾音・死亡音などは素材が未整備です
