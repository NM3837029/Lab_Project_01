# Lab_Project_01

DxLib(C++)で作られた2Dアクションゲーム本体と、それ専用のステージ/アセット編集ツール「Lab_Editor」(C# / .NET 8 / WinForms)から構成されるプロジェクトです。時間巻き戻し(リワインド)ギミックを軸にした横スクロールアクションで、敵・ギミック・アイテム・トリガーイベント・BGM/SEなどをすべてLab_Editor側のGUIとJSONアセットファイルで組み立てます。

さらに、既存のプリセット挙動だけでは足りない場合のために、**Scratch風のビジュアルブロックエディタで敵・ギミック・アイテムの挙動を自作できるスクリプトシステム**と、**複数の画像パーツを組み合わせて1つの敵・ギミック・アイテムを構成できる複合オブジェクト・システム**（ドアの開閉パネル、回転するファイアバー、体が分かれたボス等）を備えています。

## 導入方法（セットアップ）

### 必要環境

- Windows 10/11
- **Visual Studio 2022**（「C++によるデスクトップ開発」ワークロード）… ゲーム本体のビルド用
- **.NET 8 SDK** … Lab_Editorのビルド用
- DxLibは`DxLib_VC/`に同梱済みのため追加インストール不要

### ビルド手順

1. **ゲーム本体**
   - `Lab_Project_01.sln` をVisual Studio 2022で開く
   - 構成 `Debug` / プラットフォーム `x64` を選択してビルド
   - 成功すると `x64/Debug/Lab_Project_01.exe` が生成される
   - コマンドラインの場合:
     ```
     "C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" Lab_Project_01.vcxproj /p:Configuration=Debug /p:Platform=x64
     ```

2. **Lab_Editor**
   - `Lab_Editor/Lab_Editor/Lab_Editor.csproj` を Visual Studio または `dotnet build` でビルド
     ```
     cd Lab_Editor/Lab_Editor
     dotnet build
     ```
   - 生成された `bin/Debug/net8.0-windows/Lab_Editor.exe` を実行する

Lab_Editorはプロジェクトルート（`Lab_Project_01.vcxproj`が存在するフォルダ）を自動検出し、`assets/`配下を直接読み書きします。ゲーム本体側は**先にビルドしておく**必要があります（Lab_Editorの「▶ プレイ」ボタンがゲーム本体のexeを起動する仕組みのため）。

Lab_Editorが起動するexeは `x64/Release/` と `x64/Debug/` のうち**後からビルドされた方**が自動的に選ばれます。どちらが選ばれているかは画面下部のステータスバーに表示されます。

## 配布（デプロイ）

遊ぶ人に渡すためのzipを作れます。**`build_dist.bat` をダブルクリックするだけ**です。

```
build_dist.bat                  ビルドしてzipまで作る
build_dist.bat -SkipBuild       既にビルド済みのexeを使ってzipだけ作り直す
build_dist.bat -Version 0.2.0   zipのファイル名に付けるバージョン
```

処理の中身は `tools/build_dist.ps1` にあります。

1. Release|x64 をビルドする（MSBuildの場所はvswhereで自動的に探します）
2. `dist/LabProject01/` に `Lab_Project_01.exe` と `assets/ img/ sound/ se/` を集める
3. `_test_play.json`（エディタの一時ステージ）と `img/*.svg`（構成図）を除く
4. 遊び方を書いた `README.txt` を生成する
5. `dist/LabProject01_v<バージョン>.zip` に固める

できたzipは、**展開してexeをダブルクリックするだけで動きます**。ゲーム本体はexeの場所から親フォルダを遡って `assets/enemies.json` を探し、見つかった場所を基準にアセットを読むため、開発フォルダの中でも配布フォルダでも同じバイナリが動きます。

配布するときに知っておくとよいこと:

- **起動時に「Windows によって PC が保護されました」と出ます。** 署名の付いていないソフト全てに出るもので、異常ではありません。「詳細情報」→「実行」で起動できます。生成される `README.txt` にもこの案内が入っています
- **セーブデータは `%LOCALAPPDATA%\LabProject01\` に保存されます。** インストール先へ書き込まないので、`Program Files` 配下へ置いても権限エラーになりません
- **Lab_Editorは同梱していません。** 開発用のツールであり、配布物に含めると `.NET 8 Desktop Runtime` が別途必要になるためです

## 使い方

1. Lab_Editorを起動すると、既存のステージ一覧が左側に表示される（無ければ`stage_01`が自動生成される）
2. ツールバーで **レイヤー(遠景/メイン/近景/イベント)** と **ツール(ペン/消しゴム/選択)** を切り替えてタイルマップを編集
3. 右側パネルで敵・ギミック・アイテムを選択し、マップ上をクリックして配置（イベントレイヤー時）
4. 「アセット管理」ボタンから敵・ギミック・アイテム・コモンイベントの定義そのものを編集（パラメータ調整・挙動スクリプト・パーツ編集もすべてここから行う）
5. 「▶ プレイ」でゲーム本体を起動して実際に確認、または「ここからプレイ」で任意の位置からテストプレイ
6. 保存は自動（タイル編集の1ストローク完了時、各種設定変更時）。ゲーム内で**矢印キー全押し**するとゲームを閉じてエディタに戻る（隠しショートカット）

## タイトル画面・ステージ選択

引数なしでゲームを起動すると、タイトル画面から始まります。

```
タイトル ⇄ ステージ選択 → プレイ ⇄ リザルト
```

| 画面 | 操作 |
|---|---|
| タイトル | ↑↓またはW/Sで選択、Enter/Zで決定、マウスクリックでも可 |
| ステージ選択 | 方向キーで選択、Enter/Zで決定、**BackSpaceまたはXでタイトルへ戻る** |
| リザルト | 「つぎのステージへ」「もういちど」「ステージ選択へ」 |

Escキーはどの画面でもゲームを終了します（そのためステージ選択の「戻る」にはBackSpace/Xを割り当てています）。

**Lab_Editorからテストプレイした場合はタイトルを経由せず、そのステージへ直接入ります。** ゲーム側は「コマンドライン引数が付いているか」でエディタからの起動かを判断しています。タイトル画面そのものを確認したいときは、Lab_Editorのメニュー「プレイ」→「タイトル画面から起動」（Shift+F5）を使ってください。

### 進行状況の保存

クリアしたステージと、そのステージで取ったアイテムの最高数が `%LOCALAPPDATA%\LabProject01\save.json` に保存されます。ステージ選択画面には `CLEAR` の表示と取得数が出ます。

ステージごとに解放条件を設定できます。

| 条件 | 意味 |
|---|---|
| 常に選べる | いつでも選択できる |
| 前のステージをクリア | 一覧で1つ前のステージをクリアすると選べるようになる |
| 指定ステージをクリア | 指定した複数のステージを全てクリアすると選べるようになる |

セーブデータを消して最初から確かめたいときは、Lab_Editorの「ゲーム設定」→「その他」タブにある**「セーブデータを削除」ボタン**が使えます。

### 内容の編集

タイトル画面の文字・背景・メニュー項目・**要素の配置**、およびステージ一覧（表示名・並び順・サムネイル・解放条件）は、Lab_Editorのメニュー **「ゲーム設定(&G)」→「タイトル画面・ステージ一覧」** から編集できます。

- **タイトル画面タブ** … 640x480のゲーム画面をそのまま縮小表示したキャンバス上で、ロゴやタイトル文字をドラッグして配置します。8pxグリッドと画面中央へのスナップが効きます（Shiftを押しながらで無効）。矢印キーで1px、Shift+矢印で10px動きます
- **ステージ一覧タブ** … 並び順がそのまま「1つ前のステージ」の順序になります。▲▼で並べ替えてください
- **その他タブ** … ウィンドウタイトル、テーマ色、リザルト画面の文言、セーブデータの削除

設定は `assets/game_config.json` に保存されます。このファイルが無い・壊れている場合は、タイトル画面を出さずに従来どおり起動即プレイになります（設定が壊れても遊べなくならないようにしてあります）。

## 敵・ギミック・アイテムの挙動スクリプト（Scratch風ビジュアルブロックエディタ）

既存の20種の敵・24種のギミックには「⚙ 挙動パラメータ」パネル（タイプ選択時に自動で表示項目が切り替わる）で速度・射撃間隔・索敵範囲などを調整できます。それだけでは足りない、完全にオリジナルな敵・ギミックを作りたい場合のために、**Scratchを参考にしたビジュアルなブロックエディタ**を用意しています。JSONを手書きする必要はなく、Lab_Editorの「🧩 挙動スクリプトを編集」ボタンからパレットのブロックをキャンバスへドラッグ&ドロップして組み立てられます。

### 使い方

1. アセット管理画面で、敵の`type_enum`を**20（カスタムスクリプト）**、またはギミックの`type_enum`を**24（カスタムスクリプト）**に設定する
2. 対象の行を選択した状態で「🧩 挙動スクリプトを編集」ボタンを押す
3. 開いたエディタで、左のパレットからブロックをキャンバスへドラッグして縦に積み上げていく。`Forever`/`If`等のC字ブロックの中にはブロックをネストできる
4. 数値・文字列・選択式の入力欄はクリックしてその場で編集できる。レポーター（丸型）/真偽値（六角形）ブロックは、対応するソケット（数値欄・条件欄）へドラッグして差し込める
5. 差し込み済みのブロックは右クリックで取り外せる。ブロック単体はキャンバス上で選択してDeleteキーで削除できる
6. 「💾 OK」で確定すると、そのままアセット管理画面の保存対象に反映される

保存されるデータの実体はJSON AST（下記参照）で、`assets/enemies.json`/`gimmicks.json`の`script`フィールドに格納されます。手書きで直接JSONを編集することも可能です。

```json
{
  "id": "my_custom_enemy",
  "name": "自作の敵",
  "type_enum": 20,
  "hp": 3, "width": 32, "height": 32, "sprite": "img/enemy.png",
  "script": [
    {
      "hat": "OnSpawn",
      "body": [
        { "op": "Forever", "body": [
          { "op": "MoveDirection", "dir": "Toward", "speed": 2 },
          { "op": "Wait", "frames": 30 },
          { "op": "Shoot", "angle": { "op": "DirectionToPlayer" }, "speed": 6, "damage": 1 }
        ]}
      ]
    }
  ]
}
```

実際に動く参考例が `assets/enemies.json`（`enemy_script_sample` / `enemy_script_patrol` / `enemy_script_stationary` / `enemy_script_dashcharger`）と `assets/gimmicks.json`（`gim_script_movingplatform`）に入っているので、そのまま参照・改造してください（複合パーツの参考例は次章参照）。

### 命令（ブロック）一覧

| カテゴリ | 命令 | 内容 |
|---|---|---|
| 制御 | `OnSpawn` / `OnDamaged` / `OnDeath`（ハット） | スクリプトの開始点。出現時／被ダメージ時／死亡時にそれぞれ実行される |
| 制御 | `Forever { body }` | 本体を無限に繰り返す |
| 制御 | `Repeat { count, body }` | count回繰り返す |
| 制御 | `RepeatUntil { cond, body }` | condが真になるまで繰り返す |
| 制御 | `If { cond, body }` / `IfElse { cond, body, else }` | 条件分岐 |
| 制御 | `Wait { frames }` | 指定フレーム待機 |
| 制御 | `WaitUntil { cond }` | condが真になるまで待機 |
| 動き | `MoveDirection { dir: "Left"/"Right"/"Toward"/"Away", speed }` | 方向・速度を指定して移動 |
| 動き | `ApplyImpulse { vx, vy }` | 速度を直接設定 |
| 動き | `SetPosition { x, y }` / `OffsetPosition { dx, dy }` | 位置を設定／相対移動 |
| 動き | `FaceTowards` | プレイヤーの方を向く |
| 動き | `Oscillate { min, max, periodFrames }` | Y座標をmin〜maxで周期的に振動（動く足場等向け） |
| 動き | `SetLocalOffset { dx, dy }` | **パーツ専用。** 親（複合体本体）の現在座標からの相対位置を設定する |
| 動き | `SetLocalOffsetPolar { angle, radius }` | **パーツ専用。** 親を中心に「角度・半径」で相対位置を設定する。`Cos`/`Sin`を2回書かずに済む糖衣構文で、ファイアバーのように「同じ角度・パーツごとに異なる半径」を並べて回転する棒を作るのに使う |
| 動き | `SetAngle { angle }` | 見た目の回転角(ラジアン)を設定 |
| 攻撃・演出 | `Shoot { angle, speed, damage }` | 指定角度(ラジアン)へ弾を発射 |
| 攻撃・演出 | `ShootAtPlayer { speed, damage }` | プレイヤーへ自動照準して発射 |
| 攻撃・演出 | `SetInvincible { on }` / `SetScale { scale }` | 無敵状態／表示スケールの変更 |
| 攻撃・演出 | `SetVisualEffect { kind: "brightness"/"zoom", intensity }` | 画面演出 |
| 攻撃・演出 | `PlaySound { slot }` | 効果音を再生（`se.json`/`ui_se.json`に登録したidを指定。BGM再生には未対応） |
| 変数 | `SetVar { name, value }` / `ChangeVar { name, value }` | 変数の設定／加算 |
| センサー(式) | `SelfX` / `SelfY` / `PlayerX` / `PlayerY` / `DistanceToPlayer` / `DirectionToPlayer` / `Random{min,max}` / `GetVar{name}` | 数値を返す式ブロック |
| センサー(式) | `Time` | ゲーム開始からの経過フレーム数（リセットされないグローバルな「時計」） |
| センサー(式) | `ParentX` / `ParentY` | **パーツ専用。** 親（複合体本体）の現在のワールド座標 |
| センサー(式) | `ParentDirection` | **パーツ専用。** 親の向き（右向き=+1／左向き=-1） |
| センサー(式) | `ParentTilt` / `ParentScaleRatio` | **パーツ専用。** 親が配置時からどれだけ傾けられたか（ラジアン）／どれだけ拡大縮小されたか（倍率）。パーツは既定で親と一体の剛体として回るので、「親が傾いてもプレイヤーを向き続けてほしい」パーツは狙った角度から`ParentTilt`を引いて打ち消す |
| センサー(式) | `PartIndex` | **パーツ専用。** 自分が親のパーツ配列の何番目か(0始まり)。同一スクリプトを複数パーツで共有しつつ、パーツごとに異なる位相をつけるのに使う |
| センサー(式) | `SelfScale` / `SelfAngle` | 自分の現在の大きさ（倍率）／角度（ラジアン） |
| センサー(式) | `EditScaleRatio` / `EditTilt` / `EditSpeedRatio` | プレイヤーの編集ツールで、配置時からどれだけ大きさ・傾き・速さを変えられたか |
| センサー(式) | `ScreenColorFilter` / `ScreenBrightness` / `ScreenZoom` | 画面エフェクトの現在値（色フィルタ番号・明るさ・ズーム倍率） |
| 演算子(式) | `Add`/`Sub`/`Mul`/`Div` `{a,b}` / `Const{value}` | 四則演算 |
| 演算子(式) | `Sin{a}` / `Cos{a}` | 三角関数（ラジアン）。回転・周回運動の自作に使う |
| 条件(式) | `Gt`/`Lt`/`Eq`/`And`/`Or`/`Not` `{a,b}` / `IsGrounded` / `IsWallAhead` / `IsGroundAhead` | 真偽値を返す式ブロック |
| 条件(式) | `EditFlipped` / `EditPaused` / `EditRewinding` / `EditEnlarged` / `EditShrunk` / `EditTilted` / `IsFastForward` | プレイヤーの編集操作を真偽値で受け取る（向き反転・一時停止・巻き戻し・拡大・縮小・傾け・早送り） |

`OnDamaged`/`OnDeath`は、`OnSpawn`とは独立した専用の実行状態で発火するため、`OnSpawn`側で`Forever`ループを回している最中に被弾・死亡してもそのループは巻き込まれて止まらない。ただし`OnDeath`は死亡と同じフレーム内で完結する処理（`PlaySound`/`SetVisualEffect`/`Shoot`等）のみを想定しており、`Wait`を挟む複数フレームにまたがる演出には対応していない（死亡直後は更新自体が止まるため）。

### 安全設計

無限ループを含むスクリプトを書いてもゲームがフリーズしないよう、以下の安全装置が入っています。

- `Forever`/`Repeat`が1周してループの先頭に戻る瞬間、必ずそのフレームの実行を打ち切る（次フレームで続きから再開）
- 1体・1フレームあたりの命令実行数に上限（500）
- 全スクリプト実行体の合計で1フレームあたりの命令数に上限（20000）
- コールスタックの深さに上限（32）。超えた場合はエラーとしてログに記録し、そのスクリプトの実行を停止する（"Faulted"状態、ゲーム自体は継続）

デバッグモード表示中（`isDebugDrawMode`）は、スクリプトで動く敵・ギミックの上に実行状態（RUN/DONE/FAULT、スタック深さ、待機フレーム数、Faulted時はエラー内容）が表示されます。さらに、デバッグモードでなくてもFaulted状態の敵・ギミックには常に赤字で「SCRIPT ERROR」と表示されるため、手編集したJSONが壊れている場合もプレイ中に気付けます。

## 複合パーツ・オブジェクト・システム（マルチスプライト構成の敵・ギミック・アイテム）

通常の敵・ギミック・アイテムは1つの画像・1つの当たり判定だけで構成されますが、扉（開閉する複数パネル）、マリオ風ファイアバー（軸を中心に回転する複数の火の玉）、体が分かれた敵（各部位を個別に攻撃できるボス等）のような**複数の画像パーツを組み合わせたオブジェクト**を作ることができます。パーツは前章のブロックスクリプトで自由に制御でき、**パーツごとに個別の当たり判定・HP**を持てます。

### 使い方

1. アセット管理画面で対象の敵/ギミック/アイテムの行を選択し、「🧩 パーツを編集」ボタンを押す（このボタンは`type_enum`に関係なく、どのタイプの敵/ギミック/アイテムでも使える。パーツは本体の挙動タイプとは独立して動作するため）
2. エディタは左（パーツ一覧）／中央（合成プレビュー）／右（選択中パーツの詳細）の3分割で、境界線をドラッグして各領域の広さを調整できる。左の一覧でパーツを追加・選択し、右側の詳細パネルで画像・offsetX/offsetY・表示スケール・HP・zOrder（奥/手前）を編集する。中央の合成プレビューではパーツをドラッグして初期位置を直接調整できる
3. 右側の詳細パネルの「📝 挙動スクリプトを編集」ボタンから、そのパーツ専用の挙動スクリプトを編集する（前章と全く同じブロックエディタ）。「🧩 このスクリプトを全パーツへ」ボタンで、選択中のパーツのスクリプトを全パーツにコピーできる（`PartIndex`で位相・半径をずらせば、同一スクリプトのままファイアバーの火の玉のように動きを分岐させられる）
4. 左下の「🌀 回転する棒として配置...」ボタンから、マリオのファイアバーのように中心から一直線に並んだ球が棒状に回転するパーツ一式（個数・間隔・回転速度・画像を指定）を一括生成できる
5. 「💾 OK」で確定し、通常通りアセット管理画面から保存する

### パーツの仕組み

- パーツは`PartDef`（テンプレート）として敵/ギミック/アイテムの定義に付随する（JSON上は`parts`配列）。`parts`が空の既存アセットは完全に無変更で動作する
- 各パーツは`offsetX`/`offsetY`（本体からの初期相対位置）、`width`/`height`（表示サイズ）、`hitboxOffsetX/Y`・`hitboxWidth/Height`（個別の当たり判定）、`scale`、`hp`、`zOrder`、`script`を持つ
- **HP=0のパーツは破壊不能な常在ハザード**（ファイアバーの火の玉のように、触れると常にダメージを与え続ける）。**HP≧1のパーツは弾で個別に破壊可能**で、破壊されても本体自身のHP・生死には一切影響しない（弱点部位のみを狙い撃つボス戦などに使える）
- パーツはスクリプトの`SetLocalOffset`/`SetLocalOffsetPolar`/`SetAngle`で自由に動かせる。`ParentX`/`ParentY`で本体の現在座標を、`PartIndex`で自分の番号を、`Time`で経過フレーム数を、`Sin`/`Cos`で三角関数を取得できるため、周回運動・振動・追従・扇状配置などをスクリプトのみで組める。特に「同じ角度・パーツごとに異なる半径」で`SetLocalOffsetPolar`を使うと、ファイアバーのように一直線に並んだまま回転する棒状の配置になる（左のパーツ一覧の「🌀 回転する棒として配置...」ボタンで自動生成できる）
- **パーツは本体に必ず追従する。** 本体の移動・拡大縮小・傾けはすべてパーツ側へ合成されるため、スクリプトを持たないパーツでも本体に張り付いたまま動く。編集ツールで本体をドラッグしている最中（ゲーム内の全オブジェクトが止まっている間）も追従は途切れない
  - 親を2倍にすればパーツも2倍の大きさになり、本体の中心からの位置関係も2倍に広がる。親を45度傾ければパーツも一緒に45度回る
  - パーツが継承する倍率は **0.25〜4.0倍にクランプ**される。当たり判定が8x8しかないファイアバーのようなギミックを目一杯引き伸ばしたときに、腕だけが画面外まで伸びて事故になるのを防ぐため。描画と当たり判定の両方に同じ値を使うので、見た目と判定がズレることはない
  - 「親が傾いてもプレイヤーを向き続けてほしい」パーツ（ドッスンの黒目、砲台の砲身など）は、狙った角度から`ParentTilt`を引いて親の回転を打ち消す。`assets/enemies.json`の`enemy_dossun`・`enemy_houdai`が実例
  - 当たり判定は従来どおり軸平行の矩形（AABB）のままで、パーツの回転角は判定に反映されない
- `OnDamaged`/`OnDeath`はパーツ単位でも発火する。パーツが破壊されるとそのパーツ専用の`OnDeath`が一度だけ実行される
- 描画順は`zOrder`が負のパーツ→本体→`zOrder`が0以上のパーツ、の順（本体より奥/手前を指定できる）

## 敵の向きを変えたときの動き

編集ツールで敵を**回転**（`R`＋ドラッグ）させたり**向き反転**させたりすると、その敵の**移動・射出の方向がそのまま向いている方向に変わります**。見た目が傾いているのに真下へ落ちる、といった食い違いは起きません。

### 基準の向き

敵はタイプごとに「編集されていないときにどちらを向いているか」という基準の向きを持っており、回転はその基準を回す形で効きます。回転の向きはスプライトの見た目と完全に一致します（時計回りが正）。

| 基準 | 対象 | 傾けるとどうなるか |
|---|---|---|
| **下** | ドッスン（落ちてくる敵） | 落下方向そのものが変わる。90度倒せば真横へスラムし、180度回せば真上へ突き上げる。落下予兆（溜め）のあいだは空中で静止するので、**動くのは常に向いている方向だけ**です |
| **上** | 飛びかかり・ジャンプ・各種射撃・テレポート | 跳躍角・射出方向・出現方角が変わる。いもむしを真上や後方へ向ければ「砲弾」として撃ち出せる |
| **前（左右）** | 突進・歩行・追跡・浮遊 | 突進は傾けた角度どおりに一直線へ飛ぶ。歩行系は水平成分だけを使うので、90度倒すと止まり、180度回すと逆走する（宙に歩き出すことはない） |

**向き反転**は、縦向きが基準の敵（ドッスン・射撃系など）では基準の向きを向いている側へ30度振ります。ドッスンを反転させると斜めに落ちるのはこのためです。左右が基準の敵はもともと向き自体が反転するので、二重には効きません。

### 落下・突進は重力を切る

ドッスンの落下中と突進の突進中は重力を打ち消し、本体の軸方向へまっすぐ加速します。重力を残すと斜めに向けても途中で失速して真下に落ちてしまい、角度どおりに飛ばないためです。真下を向いているあいだは従来の自由落下と完全に同じ速さになります。

遮る地形が無い向きへ飛ばすと遠くまで飛んでいくので、**マップの外に出るか一定時間が過ぎたら自動的に着地扱い**になり、必ずクールダウンを経て元の位置へ戻ります。

### 砲台の手動照準

砲台を傾けると砲身がその向きへ固定され、**次の一発だけ**そこへ撃ちます。撃つと傾きを消費してプレイヤー追尾に戻るので、スイッチや壊せるブロックを撃たせたいたびに狙いを付け直す操作になります。

**回るのは砲身だけで、台座は置いたときの姿勢のまま動きません。** 砲台は「本体の絵＝台座／砲身＝パーツ」という構成なので、回転を本体にも掛けると三脚ごと傾いて浮いているように見えてしまいます。敵の定義に **`bodyIgnoresTilt`**（Lab_Editor の共通欄「回転しても本体の絵は傾けない（回るのはパーツだけ）」）があり、これがONの敵だけ本体の絵を配置時の姿勢で描きます。既定はOFFなので、ドッスンのように**全体が回るのが正しい敵は従来どおり**です。

**弾は砲身が指している向きへ、そのまま飛びます。** 反転も一緒に使っているときは弾だけ30度ずれて飛んでいましたが（反転ツールが縦向きの敵の軸を振る補正が、砲台にも掛かっていたため）、砲台系ではその補正を掛けないようにしてあります。砲身の絵と弾道は必ず一致します。

### 向き反転でできること

向き反転は、縦向きが基準の敵の落下・射出方向を30度振るほかに、タイプごとの固有の反応も持っています。主なものは次のとおりです。

| 敵 | 反転させると |
|---|---|
| 固定砲台・照準砲台 | **弾がプレイヤー側の弾になり、他の敵に当たるようになります。** ブロックを壊す力も持つので、「敵に壊させる」使い方ができます |
| 巡回砲台 | プレイヤーを見つけても撃たず、反対側へ逃げ出します |
| 巡回敵 | 巡回範囲の端を待たず、その場で折り返します |
| 突進・追跡・歩行・浮遊 | プレイヤーを追うのをやめ、逃げる向きへ進みます |
| 落下リフト・重量スイッチ・色/明暗ゾーンなど | 効果が裏返ります（沈む→浮上、暗転→明転 など） |

**反転の判定には「プレイヤーが反転ツールを使ったか」だけを見ています。** 以前は「配置時と向きが違うか」で判定していたため、プレイヤーを追って自分から向きを変えるタイプの敵では、プレイヤーが左右を行き来するだけで反応が勝手に点滅していました。

## 壊せるブロックの設定

壊せるブロック（type_enum=3）は、**誰が壊せるか**と**壊すのに必要な相手の大きさ**をブロックごとに設定できます。Lab_Editorのアセット管理でブロックを選ぶと、右側のパラメータ欄に出ます。

| 設定 | 意味 |
|---|---|
| ドッスンの落下衝撃で壊れる | ドッスンが着地したとき、衝撃波の範囲内なら壊れる |
| 敵の体当たりで壊れる | 突進・歩行・巡回の敵がぶつかると壊れる |
| 弾で壊れる | プレイヤーの弾（および反転させた砲台の弾）で壊れる |
| クリックで壊れる | 編集モードでの直接クリックで壊れる |
| 45度以上傾けると自重で崩れる | 回転ツールで倒すと自分から崩れる |
| 壊すのに必要な相手の大きさ | 0なら大きさを問わない。1.2なら「1.2倍以上に拡大した敵の衝撃でなければ壊れない」。敵の衝撃にだけ掛かり、クリックと自重崩壊には掛かりません |

同梱している2種類：

- **`gim_breakable`（壊せるブロック）** … 全てONの汎用ブロック。従来どおりどの手段でも壊せます
- **`gim_breakable_heavy`（重量ブロック）** … **ドッスンの落下衝撃でしか壊れません。** 弾も体当たりもクリックも効かないので、「ドッスンの向きを変えて狙わせる」ことが唯一の答えになる仕掛けが作れます

ドッスンは**スラムするときなら編集状態に関係なく**ブロックを壊しにいきます（縮小していても壊します）。壊せるかどうかはブロック側の設定が決める、という分担です。

衝撃が起きる場所は**ぶつかった面**です。真下へ落ちるときは足元、横向きに回してあるときは進行方向側の面が中心になります。真下だけを見ていたころは、横向きのドッスンが壁に密着していても衝撃の中心が体の後ろ側にあり、目の前の壊せる壁が判定の輪から外れて一切壊れませんでした。

### 大きさが足りないときは画面に出ます

「必要な大きさ」を満たしていないだけで弾かれたときは、そのマスに枠と **`1.3倍以上で壊せる`** のような表示が出て、「操作できない」音が鳴ります。条件を緩めるのではなく、条件が見えるようにするための表示です。何も出ないまま壊れない場合は、大きさではなく**そもそも届いていない**（当たっていない・その壊し方が許可されていない）ということになります。

### 変わらないもの

- **当たり判定は軸平行の矩形（AABB）のまま**です。横倒しにしたドッスンの判定が横長になることはありません
- 壊せないブロックに当たった弾は、そのブロックを素通りして先へ進みます（弾はもともと地形タイルにしか遮られません）
- 色・大きさ・テンポだけが変わるタイプ（色調整敵・大きさが変わる敵・速さ操作敵など）の傾け反応は従来どおりです
- まるび（パトロール）を傾けると転がる挙動も従来どおりです（「丸いものは坂を転がる」という別の比喩のため）

## 地形タイルを壊せるようにする

壊せるのはギミックの「壊せるブロック」だけではありません。**マップに敷いた地形タイルそのもの**にも、同じ考え方で破壊条件を設定できます。Lab_Editor の「🧱 タイル定義」から開き、各タイルの行にある4つのチェックで決めます。

| 列 | 意味 |
|---|---|
| 叩きつけ | ドッスンが着地したとき、衝撃波の届く範囲なら砕ける |
| 体当たり | 突進・歩行・巡回の敵がぶつかると砕ける |
| 弾 | 弾が当たると砕ける（当たった弾も消えます） |
| 手動 | 編集モードで直接クリックすると砕ける |
| 必要倍率 | 壊すのに必要な相手の大きさ。0なら大きさを問わない。1.5なら「1.5倍以上に拡大した敵の衝撃でなければ砕けない」 |
| 破壊音ID | 砕けたときに鳴らす効果音のID。空欄なら無音 |

**既定は全てオフです。** 触らない限り、地形は今までどおり絶対に壊れません。

### 巻き戻すと積み直ります

砕けたマスは「壊れてから何フレーム経ったか」を覚えていて、巻き戻している間はその時間が巻き戻ります。0まで戻ったマスは元のタイルへ戻ります。壊せるブロック（ギミック）と同じ振る舞いです。

- **巻き戻せる時間（約10秒）より前に壊したマスは戻りません。** それより過去は履歴自体が残っていないためです
- **プレイヤーが重なっているマスは、退くまで復活を待ちます。** 復活と同時に地形へ埋まって抜け出せなくなるのを防ぐためです
- ミスしてやり直したときやステージを開き直したときは、地形は必ず無傷の状態から始まります

### 壊せるブロック（ギミック）との使い分け

| | 地形タイル | 壊せるブロック（ギミック） |
|---|---|---|
| 置き方 | マップにタイルとして敷く | オブジェクトとして1個ずつ置く |
| 傾けて自重で崩す | できない（タイルは傾かないため） | できる |
| 大きさを変える | できない | できる |
| 大量に敷く | 得意 | 個数ぶん重くなる |

「壊せるブロックはどこで設定するんだったか」と迷ったときのために、タイル定義エディタの下部に **「🧱 壊せるブロック(ギミック)の設定」** ボタンを置いてあります。ここからギミック側の破壊条件もその場で編集できます。

### タイルの名前と色について

タイル定義エディタで付けた**名前と色を、ゲーム側も読むようになりました**（以前は書けるのに無視されていました）。画像を割り当てていないタイルは、指定した色でそのマスを塗ります。仮組みのときに画像を用意せず色だけで地形を作れます。

## 効果音の割り当て

効果音は「カタログに登録する」→「鳴らす場面へ割り当てる」の2段階で設定します。

| 画面 | やること |
|---|---|
| Lab_Editor →「🔊 サウンド管理」 | 音声ファイルに **ID** を付けてカタログへ登録する（`assets/se.json` / `ui_se.json` / `bgm.json`） |
| Lab_Editor →「🔊 サウンド割り当て」 | そのIDを実際の場面へ割り当てる |

割り当てられる場面は7種類です。

| セクション | 内容 |
|---|---|
| 👾 敵 | 出現・攻撃・被弾・撃破 |
| 🔧 ギミック | 起動 |
| 💎 アイテム | 取得 |
| 🎮 プレイヤー操作 | ジャンプ・着地・ダッシュ・射撃・被弾・力尽きる |
| ✏️ 編集ツール | 巻き戻し・拡大縮小・回転・移動・反転・リセット・コマ送り・一時停止・早送り・色フィルタ・カット・操作できない・ゲージ切れ |
| 🏁 タイトル/リザルト | カーソル移動・決定・戻る・ステージクリア・ゲームオーバー |
| 🎵 ステージBGM | 現在開いているステージのBGM |

**空欄は「鳴らさない」という意味**です。プレイヤー・編集ツール・UIの割り当ては `assets/game_config.json` の `player_se` / `edit_se` / `meta_se` に保存されます（敵・ギミック・アイテムは各アセットのJSONに保存されます）。

### IDの打ち間違いに気づけるようにしてあります

ゲームは知らないIDを渡されても**何も言わずに無視する**ため、1文字違うだけで「なぜか鳴らない」という状態になります。そこで起動時に一度だけ全ての割り当てを照合し、カタログに無いIDを指しているものを `logs/error.log` へ出すようにしてあります。音が鳴らないときはまずここを見てください。

### 同じ効果音が別の場面で使い回されていた点について

以前は一時停止とダッシュ取得が同じ音、決定と戻るとステージ開始がすべて同じ音、といった状態でした。専用の音源（`Paused.wav` / `FastFoward.wav` / `ColorChange.wav` / `Rewind.wav`）がありながら一度も使われていなかったため、本来の役へ割り当て直してあります。またIDの名前も「分裂02」のようなファイル由来のものから、`se_enemy_death`（敵:撃破）のように**どこで鳴るか**を表す名前へ付け替えました。

## アセットごとに編集を禁止する

「この敵だけは拡大させたくない」「この足場は動かされたら困る」といった縛りを、アセットごとに設定できます。Lab_Editor のアセット管理で対象を選ぶと、右側のパラメータ欄に出ます。

| 設定 | 禁止される操作 |
|---|---|
| 拡大縮小を禁止 | S+ドラッグ、インスペクタの大きさ |
| 回転を禁止 | R+ドラッグ、インスペクタの角度 |
| 移動を禁止 | ドラッグでの移動 |
| 向き反転を禁止 | 右クリックメニューの「向きを反転」 |
| 一時停止を禁止 | 個別の一時停止 |
| 巻き戻しを禁止 | 個別の巻き戻し |
| 速度変更を禁止 | 速度±0.5、インスペクタの速度 |

**ステージ単位の「使える編集ツール」設定とは別の軸です。** ステージ側は「そのステージでそもそもどのツールを使えるか」、こちらは「このオブジェクトに対して何をしてよいか」を決めます。

複数のオブジェクトをまとめて選んだ場合、**禁止されている相手だけが除外され、他は今までどおり編集できます**。

**アイテムについて**：同じ設定欄をアイテムにも出していますが、アイテムは今のところゲーム内の編集ツールの選択対象になっていません。設定は保存されますが、まだ効果はありません（アイテムを編集できるようにしたときにそのまま効きます）。パラメータ欄にも同じ注意書きを出しています。

## オブジェクトの大きさの決め方

アセット管理の **📏 ボタン**（敵・ギミック・アイテムの各一覧にあります）から、ゲーム内での大きさを決められます。

| やり方 | 使いどころ |
|---|---|
| プリセット（16 / 32 / 48 / 64 / 96 px） | タイル1マスは32pxなので、マス目に合わせたいときはこれが一番早い |
| 仕上がり幅[px] | 「88pxにしたい」のように狙った大きさが決まっているとき。縦横比は保たれます |
| 倍率 | 「今の1.5倍」のように相対で決めたいとき |
| プレビュー右下のハンドルをドラッグ | 見ながら decide したいとき（従来どおり） |

**「当たり判定も同じ比率で合わせる」を入れておくと、大きさを変えたぶんだけ当たり判定も一緒に動きます。** 外すと当たり判定は元のままです（見た目より小さい判定をわざと作りたいときに使います）。

### 表示されるpxはゲームの実寸と一致します

敵の見た目の大きさは「論理サイズ（幅px・高さpx）× 倍率」で決まり、**元画像の解像度は関係ありません**（素材はすべて640x640ですが、それがそのまま出るわけではありません）。以前の画面はここを取り違えて元画像の解像度を基準に表示していたため、表示を信じて合わせてもゲームでは違う大きさで出ていました。今は同じ式で計算しているので、表示された px がそのままゲーム内の大きさです。

ギミックとアイテムには倍率がなく、**当たり判定の大きさがそのまま表示サイズ**です。そのため📏から決めた値は当たり判定へ直接書き戻されます（画面にもその旨を出しています）。

## ステージ編集画面での配置

### 敵・ギミック・アイテムは実際の絵で並びます

以前は種類に関係なく小さな四角と絵文字で表示していたため、「置いたらどのくらいの大きさになるのか」がステージ編集画面では分かりませんでした。今は**実際のスプライトを、実際の大きさで**描きます。画像が無い／読めないアセットは今までどおり絵文字で表示します。

**クリックの当たり判定は従来どおり固定サイズのままです。** 当たり判定まで実サイズにすると、当たり判定が未設定のアセットが掴めなくなるためです。

### 右クリックでメニューが出ます

以前は右クリックした瞬間に確認なしで削除されていました。今は次のメニューが出ます（消しゴムツールでの削除は今までどおりです）。

- **大きさ・角度を編集...** — その1個だけの大きさと角度を決めます
- **削除**

### 置いたもの1つずつに大きさと角度を持たせられます

アセット定義の大きさは「その種類の標準」で、こちらは**それを配置ごとに上書き**するものです。同じ敵を大小いくつも並べたり、最初から傾けて置いたりできます。

- 大きさは倍率で指定します（1.0 = アセットの標準サイズ）
- 角度は度で入力します。0°/45°/90°/180° はボタン一発で入ります
- 何も設定していない配置はステージJSONにキーを書きません。**既存のステージの見え方は一切変わりません**

#### ただの見た目ではなく「最初から編集された状態」になります

ここで設定した大きさ・角度は、**プレイヤーがゲーム内の編集ツールで同じ操作をしたのとまったく同じ扱い**になります。つまり

- 2倍にして置いた敵は、S+ドラッグで2倍にしたときと同じように**重くなる**（段差を越えられなくなる等）
- 90度倒して置いたドッスンは、R+ドラッグで倒したときと同じように**真下ではなく倒した向きへ落ちる**
- 45度以上倒して置いたトゲは、**倒された扱い（無害）**で始まる
- 縮小して置いた岩は、**転がる状態**で始まる

という反応が最初から成立します。ダイアログの下には「この設定だとゲーム内でどう扱われるか」が出るので、45度の境目のような分かりにくい条件も入力しながら確認できます。

#### ギミックは横と縦を別々に指定します

ゲーム内の編集ツールは、敵は倍率1つ（S+ドラッグ）、ギミックは**横幅(Sドラッグ)と縦幅(Wドラッグ)を別々に**変えます。配置ごとの初期値も同じ粒度にしてあるので、ギミックだけ「横の大きさ」「縦の大きさ」の2つが出ます。

また、**角度をAIが自前の状態として使っている型**（自動で回る橋・ちくわブロック・挙動スクリプトで角度を動かすもの）は、ゲーム内でも回せないので、この画面でも角度が入力できません。

### ゲーム設定のステージ一覧

「ゲーム設定」→「ステージ一覧」タブで、タイトル画面のステージ選択に並ぶステージを管理します。

| ボタン | 動作 |
|---|---|
| ＋ 追加 | まだ一覧に載っていないステージファイルを選んで追加します（複数同時に選べます）。2本目以降は解放条件の初期値が「前のステージをクリア」になります |
| 🗑 削除 | 選んでいる行を一覧から外します。**ステージファイル自体を消すかどうかは別に確認します**（既定は外すだけなので、あとで追加し直せます） |
| ▲ 上へ / ▼ 下へ | 並び替えます。並び順がそのまま「前のステージ」の順序になります |
| サムネイルを選ぶ | ステージ選択画面に出す画像を選びます |

ステージファイルそのものを新しく作るのはメイン画面の「新規ステージ」です。作ったあと、この画面で一覧へ追加してください。

**消えたステージファイルを参照している行も、書かれているとおりに表示されます。** 以前はファイル選択の候補に無い名前が別のファイル名に化けて見え、そのまま保存すると設定が黙って別のステージを指してしまう状態でした。

## 背景レイヤー

背景は複数のレイヤーを重ねられ、`scrollRate` を小さくするほど遠くにあるようにゆっくり動きます（視差スクロール）。

**画像を指定せず、色だけを指定することもできます。** 空や単色の下地を、画像を用意せずに作れます。Lab_Editor の「背景レイヤー設定」で `色(#RRGGBB)` 欄へ直接書くか、🎨ボタンから選んでください。画像と色を両方指定した場合は、色が下地になり、その上に画像が重なります。

レイヤーは `drawOrder` の小さい順（奥から手前）に描かれます。

## 同梱ステージ

タイトル画面のステージ選択から遊べます。前のステージをクリアすると次が解放されます。

| ステージ | 広さ | 使える編集ツール |
|---|---|---|

### 共通する考え方

どれも**敵とギミックを道具として使う**ことで進みます。倒すのではなく、向きを変えたり止めたりして働かせる相手です。

- **反転させた砲台の弾は他の敵に当たる**ようになります（味方撃ち）。壊せる地形もこの弾でなら壊せます
- **回転させた砲台は、砲身の向いている方向へ固定射撃**します。狙いを自分で決められます
- **一時停止した敵は踏み台**になります。空を飛ぶ敵を止めれば足場になります
- **縮小したドッスンは衝撃波を起こせなくなり**、そのぶん安全な台になります
- **敵食らい（チョンパー）に敵が触れると相討ち**になります

### 壊せる地形タイル

3種類の「壊せる地形」を用意してあります。**画像を持たず色だけのブロック**にしてあるので、普通の地形と見分けがつきます。

| 見た目 | 壊し方 |
|---|---|
| 桃色 | **弾でしか壊れません。** 自分は弾を撃てないので、砲台を反転させて味方撃ちにする必要があります |
| 土色 | **叩きつけでしか壊れず、しかも等倍では壊せません**（1.3倍以上）。ドッスンを拡大してぶつける必要があります |
| 青緑 | **体当たりでしか壊れません。** 突進してくる敵の向きを変えてぶつけさせます |

タイル定義エディタで、どのタイルをどう壊せるかは自由に変えられます。

### かたむく丘（地上）

- **入口の上段は罠です。** コインの並んだ板の道は途中で切れていて、その先は棘の穴です。本当の道は下段で、穴を跳び越します
- 全高の壁の**足元に桃色のブロック**が埋まっています。砲台の弾はもともとここへ当たっていますが、敵の弾のままでは壊せません。**砲台を反転させて味方撃ちにする**のが答えです（壁との間に立てば、追尾している弾がそのまま壁へ届きます）
- 横穴を塞ぐ**土色の壁**は、ドッスンを横へ回して飛ばし、さらに拡大しないと砕けません。壁は**左右どちらにもある**ので、どちらへ回しても手応えが返ります（左の壁の中にはコインが隠してあります）
- 谷は素では絶対に届きません。**追ってきたドローンを空中で止めて踏み台**にします
- 低い天井の通路にいる敵食らいは、巡回している敵を誘導して**相討ちさせて**から通ります
- 最後の**青緑の壁**は、突進してくる敵を反転させてぶつけさせます

### ほりぬきの坑道（地下）

岩盤をくり抜いた2階建ての坑道です。

- 上層の行き止まりで、**床が土色**になっています。ドッスンを拡大して砕き、下層へ落ちます
- 下層の広間では**機械いもむし**が斜めに跳ね回っています。回して逸らすか、跳ね返りの周期を読んで抜けます
- 上層へ戻る唯一の道は**天井に埋まった桃色のブロック**です。砲台を真上へ回し、反転させて撃ち抜きます
- 重量スイッチは、箱を拡大して踏ませます
- **近道に見えるちくわ床は罠です。** 乗ると抜け落ち、跳んでは出られない縦穴に閉じ込められます。巻き戻して落ちる前に戻るか、底の箱を拡大して踏み台にすれば出られます

### わきあがる縦坑（下から上）

**巻き戻しが使えません。** 落ちたら下まで戻ります。

- 登りは3マスずつの棚で組んであるので、基本は素で登れます
- ただし**1箇所だけ6マスの断絶**があり、そこは追ってきたドローンを止めて中継にしないと越えられません
- 途中の部屋には**真上向きに置いた機械いもむし**が上下に跳ね回っています。止めるか回すかして横断します
- **縮小して置いたドッスン**は最初から乗れる台です（近道）
- 棚の真上が棘になっている場所が2箇所あります。**まっすぐ登ると死にます**
- 最後のゲートは、箱を拡大して重量スイッチに乗せると開きます

## 跳ね回る節足敵（機械いもむし）

`enemy_kikai_imomushi`（タイプ22 = Bouncing Worm）は、**重力を受けずに向いている方向へまっすぐ飛び続け、壁・床・天井に当たるとランダムな角度で跳ね返る**敵です。胴体の節が頭の通った跡を辿って連なります。

| 見た目 | 画像 |
|---|---|
| 頭 | `img/機械いもむし頭部.png` |
| 胴体（既定6節） | `img/機械いもむし胴体.png` |

### 動き

- **頭**は空中でも落ちません。`飛ぶ速さ` の分だけ毎フレーム直進し続けます
- 地形や画面端にぶつかると反射し、そのたびに `跳ね返り角の乱れ` の範囲で角度がずれます。まっすぐ跳ね返らないので同じ軌道を繰り返さず、待ち構えて避けるのが難しい相手になります
- 乱れのせいで壁の内側を向いてしまう場合は、その回だけ乱れを捨てて正しく反射します（壁にめり込んで動けなくなるのを防ぐため）
- **胴体**は頭の軌跡を `胴体の節の間隔` ごとに辿ります。頭が曲がれば、その曲がりが順番に後ろの節へ伝わっていきます

### 調整できる項目

Lab_Editor のアセット管理でこの敵を選ぶと、右側のパラメータ欄に出ます。

| 項目 | 意味 | 既定 |
|---|---|---|
| 飛ぶ速さ(px/フレーム) | 直進する速さ | 3.0 |
| 跳ね返り角の乱れ(度) | 反射角へ足す乱れの最大値。0にすると物理どおりの正反射になる | 25 |
| 胴体の節の間隔(px) | 節と節の距離 | 22 |

節の数は `parts`（パーツ編集）で増減します。節を増やすほど長い胴になります。

### 編集ツールへの反応

| 操作 | 反応 |
|---|---|
| 回転 | **回した向きがそのまま進む方向になります。** 狙った所へ飛ばしたり、自分から遠ざけたりできます |
| 向き反転 | 進む方向が逆になります |
| 拡大 | 体が重くなって遅くなります |
| 縮小 | 軽くなって速くなります |
| 一時停止・速度 | 他の敵と同じように効きます |

ステージに置くときの角度（配置ごとの「大きさ・角度」）も、そのまま**飛び出す方向**になります。45度で置けば斜め下へ飛び出します。

### 巻き戻しについて

跳ね返る角度は乱数で決まりますが、**巻き戻して再生し直しても必ず同じ角度になります。** 「何回目の跳ね返りか」と「どこで跳ね返ったか」だけから決まる値を使っているためで、`rand()` は使っていません。巻き戻して跳ね返り先を確かめてから動く、という遊び方が成立するようにするためです。

胴体も専用の記録を持たず、巻き戻し用の履歴をそのまま軌跡として使っています。そのため巻き戻すと胴体もきちんと巻き戻ります。

## マウスカーソル

ゲーム中はOS標準のカーソルを隠し、`img/マウスホイール.png`（矢印の絵）を自前で描いています。

**押せるものの上に来ると、実物のマウスカーソルと同じように指差しの手（`img/マウスカーソル指差し.png`）へ変わります。** どこが押せてどこが背景なのかを、クリックしてみなくても見分けられます。指差しになるのは次の場所です。

| 場所 | 何ができるか |
|---|---|
| 一時停止／再開ボタン | 押すと時間が止まる・動き出す |
| 開いているコンテキストメニューの上 | 各項目を押せる |
| インスペクタの操作行 | 左右にドラッグして大きさ・角度・速さを変える／押して切り替える |
| 下部のタイムライン帯 | Ctrl+クリック2回でカットを作る／右クリックでカットを選ぶ |
| モニター内のプレイヤー・敵・ギミック | 右クリックで選ぶ、ドラッグで動かす |
| タイトル画面・ステージ選択のボタンとマス目 | 押して決定する |

判定はクリックを実際に受け付けている箇所と同じ矩形・同じ有効条件を見ています。たとえばインスペクタの行は、その対象で意味を持たない項目（カットに対する「大きさ」など）では押しても何も起きないので、指差しにもなりません。

**タイトル画面・ステージ選択でもカーソルが出ます。** 以前はこの2画面でカーソルの表示切り替えを行っておらず、ステージから戻ってきたあとは「OSカーソルは消えたまま、自前カーソルも描かれない」状態になり、マウスで押せる画面なのにカーソルが1つも見えませんでした。

## よくある問題と対処方法

| 症状 | 原因・対処 |
|---|---|
| 棘ブロックに乗っても死なない | **修正済みです。** 以前は足元の1点しか見ておらず、着地すると必ず1マス上を調べてしまうため、「当たり判定あり＋即死」のタイルが無害になっていました。現在は体が触れているタイルを全て見るので、乗っても・横から当たっても・頭をぶつけても即死します |
| Lab_Editorの「▶ プレイ」を押しても何も起きない／「ゲーム実行ファイルが見つかりません」 | ゲーム本体(`Lab_Project_01.vcxproj`)を先にビルドし、`x64/Debug/Lab_Project_01.exe`を生成してください |
| `dotnet build`が「ファイルをコピーできません...別のプロセスによってロックされています」で失敗する | Lab_Editor.exeが起動中です。閉じてから再ビルドするか、`dotnet build -c Release`で別出力先にビルドしてください |
| 敵・ギミックの画像が表示されない／`Log.txt`に「画像ファイル...がありません」と出る | 該当のスプライト画像(`img/`フォルダ)が実際には存在しません。アセット管理の「📁選択」で画像を割り当ててください |
| BGM/SEが鳴らない | `assets/bgm.json`/`se.json`/`ui_se.json`のエントリで **id・name・fileがすべて空でない**ことを確認してください（IDが空のエントリは読み込まれません）。サウンド管理画面で保存しようとすると空欄チェックで警告が出ます |
| 敵のHP・移動速度などをテンプレートで変更しても反映されない | アセット管理画面で編集後、必ず「💾 保存して閉じる」を押してください。マップ上の配置自体を打ち直す必要はありません |
| 自作スクリプトを書いた敵・ギミックが動かない／エラーになる | `logs/error.log`を確認してください。`[BehaviorScript] [Tick] ERROR: ...`という行があれば、スクリプトのJSON構造（`body`が配列になっているか、`cond`の式が正しいか等）を見直してください。何も表示されない場合は`type_enum`が20（敵）/24（ギミック）になっているか確認してください |
| 「🧩 挙動スクリプトを編集」ボタンを押しても「対象外」と言われる | 敵は`type_enum=20`、ギミックは`type_enum=24`（いずれも「カスタムスクリプト」）の行でのみ使えます。「🧩 パーツを編集」はタイプに関係なくどの行でも使えます |
| パーツを追加したのに、本体が動くとパーツが置き去りになる | パーツにスクリプトが無い（または`OnSpawn`が無い）と、初期位置に固定されたまま本体を追従しません。`SetLocalOffset`で固定オフセットを毎フレーム設定する最小スクリプトを入れてください（前章参照） |
| ソケット（数値欄・条件欄）に別のブロックを差し込めない | 既にブロックが差し込まれているソケットには上書きドロップできません。右クリックで一度空にしてからドラッグし直してください |
| 新しく`.h`/`.cpp`ファイルを追加したらビルドエラーになる（謎の構文エラーが大量に出る） | このプロジェクトはソースファイルの文字コード判定でCP932(Shift-JIS)とUTF-8のせめぎ合いがあり、**LF改行のみのファイルだと日本語コメントの解釈でコンパイラが誤爆することがあります**。新規ファイルは既存ファイルと同様にCRLF改行で保存してください |
| ステージファイルを直接編集したらゲームが起動しなくなった | JSON構文エラーの可能性が高いです。`node -e "JSON.parse(require('fs').readFileSync('assets/stages/xxx.json','utf8'))"`などで構文チェックしてから再度読み込んでください |

## 既知の制限・今後の予定

- 巻き戻し（リワインド）機能は位置・速度・向き・スケール・角度・生存状態のみを記録しており、スクリプトの実行状態（変数・コールスタック）やパーツのHPは巻き戻し対象に含まれません。スクリプトで動く敵・ギミック・パーツを巻き戻すと、見た目の位置は戻ってもスクリプトの内部状態は戻らない場合があります
- `OnDeath`は死亡と同じフレーム内で完結する処理のみ対応しており、`Wait`を挟む複数フレームの死亡演出は未対応です
- アイテムは取得と同時に画面から消えるため、アイテムのパーツは装飾的な意味合いが中心です（取得判定はパーツに触れても本体と同様に発生します）
- 一部のギミック（ポータル・橋・破壊ブロック等）は専用スプライト画像が用意されておらず、ゲーム内で表示が欠けることがあります。複合パーツのテンプレートも同様に、既存の汎用画像（`img/enemy.png`等）を仮のスプライトとして使っているものがあります
- 効果音は`jump`（ジャンプ音）のみ登録済みで、敵の攻撃音・被弾音・死亡音などは素材が未整備です
