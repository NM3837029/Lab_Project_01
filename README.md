# Lab_Project_01

DxLib(C++)で作られた2Dアクションゲーム本体と、それ専用のステージ/アセット編集ツール「Lab_Editor」(C# / .NET 8 / WinForms)から構成されるプロジェクトです。時間巻き戻し(リワインド)ギミックを軸にした横スクロールアクションで、敵・ギミック・アイテム・トリガーイベント・BGM/SEなどをすべてLab_Editor側のGUIとJSONアセットファイルで組み立てます。

さらに、既存のプリセット挙動だけでは足りない場合のために、**Scratch風のビジュアルブロックエディタで敵・ギミック・アイテムの挙動を自作できるスクリプトシステム**と、**複数の画像パーツを組み合わせて1つの敵・ギミック・アイテムを構成できる複合オブジェクト・システム**（ドアの開閉パネル、回転するファイアバー、体が分かれたボス等）を備えています。

> **展示・発表で説明するための資料は [`docs/`](docs/) にあります。**
> このREADMEは開発者向けの取扱説明書です。ブースで声に出して説明するための
> カンペ（30秒の掴み・声かけ集・技術説明・想定Q&A・数字と年表）は docs 側にまとめてあります。

## 導入方法（セットアップ）

### 必要環境

- Windows 10/11
- **Visual Studio 2022**（「C++によるデスクトップ開発」ワークロード）… ゲーム本体のビルド用
- **.NET 8 SDK** … Lab_Editorのビルド用
- DxLibは`DxLib_VC/`に同梱済みのため追加インストール不要

### ビルド手順

1. **ゲーム本体**
   - `Lab_Project_01.sln` をVisual Studio 2022で開く
   - 構成 `Debug` / プラットフォーム `x64` を選択してビルド
   - 成功すると `x64/Debug/Lab_Project_01.exe` が生成される
   - コマンドラインの場合:
     ```
     "C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" Lab_Project_01.vcxproj /p:Configuration=Debug /p:Platform=x64
     ```

2. **Lab_Editor**
   - `Lab_Editor/Lab_Editor/Lab_Editor.csproj` を Visual Studio または `dotnet build` でビルド
     ```
     cd Lab_Editor/Lab_Editor
     dotnet build
     ```
   - 生成された `bin/Debug/net8.0-windows/Lab_Editor.exe` を実行する

Lab_Editorはプロジェクトルート（`Lab_Project_01.vcxproj`が存在するフォルダ）を自動検出し、`assets/`配下を直接読み書きします。ゲーム本体側は**先にビルドしておく**必要があります（Lab_Editorの「▶ プレイ」ボタンがゲーム本体のexeを起動する仕組みのため）。

Lab_Editorが起動するexeは `x64/Release/` と `x64/Debug/` のうち**後からビルドされた方**が自動的に選ばれます。どちらが選ばれているかは画面下部のステータスバーに表示されます。

## 配布（デプロイ）

遊ぶ人に渡すためのzipを作れます。入口は2つあり、**どちらも同じ `tools/build_dist.ps1` を呼んでいます**。

### Lab_Editor から作る（ふだんはこちら）

メニューの **「ファイル」→「📦 配布用パッケージを作る...」** です。

- バージョンは、前回作ったzipの末尾を1つ繰り上げた値が最初から入っています（`0.1.0` の次なら `0.1.1`）
- **「ビルドし直さず、既にある Release のexeでzipだけ作る」** にチェックを入れると、ステージやアセットだけ直したときに速く済みます。C++側を直したときは外してください
- スクリプトの出力はそのまま画面に流れるので、失敗したときの理由もこの画面の中で読めます
- **画面を開いた時点で、編集中のステージは保存されます。** 配布物には `assets/stages/` の中身がそのまま入るため、保存していない編集が黙って漏れないようにしてあります

### バッチから作る

エディタを開かずに作りたいときは、**`build_dist.bat` をダブルクリック**します。

```
build_dist.bat                  ビルドしてzipまで作る
build_dist.bat -SkipBuild       既にビルド済みのexeを使ってzipだけ作り直す
build_dist.bat -Version 0.2.0   zipのファイル名に付けるバージョン
```

処理の中身は `tools/build_dist.ps1` にあります。

1. Release|x64 をビルドする（MSBuildの場所はvswhereで自動的に探します）
2. `dist/LabProject01/` に `Lab_Project_01.exe` と `assets/ img/ sound/ se/` を集める
3. `_test_play.json`（エディタの一時ステージ）と `img/*.svg`（構成図）を除く
4. 遊び方を書いた `README.txt` を生成する
5. `dist/LabProject01_v<バージョン>.zip` に固める

できたzipは、**展開してexeをダブルクリックするだけで動きます**。ゲーム本体はexeの場所から親フォルダを遡って `assets/enemies.json` を探し、見つかった場所を基準にアセットを読むため、開発フォルダの中でも配布フォルダでも同じバイナリが動きます。

配布するときに知っておくとよいこと:

- **起動時に「Windows によって PC が保護されました」と出ます。** 署名の付いていないソフト全てに出るもので、異常ではありません。「詳細情報」→「実行」で起動できます。生成される `README.txt` にもこの案内が入っています
- **セーブデータは `%LOCALAPPDATA%\LabProject01\` に保存されます。** インストール先へ書き込まないので、`Program Files` 配下へ置いても権限エラーになりません
- **Lab_Editorは同梱していません。** 開発用のツールであり、配布物に含めると `.NET 8 Desktop Runtime` が別途必要になるためです

## 使い方

1. Lab_Editorを起動すると、既存のステージ一覧が左側に表示される（無ければ`stage_01`が自動生成される）
2. ツールバーで **レイヤー(遠景/メイン/近景/イベント)** と **ツール(ペン/消しゴム/選択)** を切り替えてタイルマップを編集
3. 右側パネルで敵・ギミック・アイテムを選択し、マップ上をクリックして配置（イベントレイヤー時）
4. 「アセット管理」ボタンから敵・ギミック・アイテム・コモンイベントの定義そのものを編集（パラメータ調整・挙動スクリプト・パーツ編集もすべてここから行う）
5. 「▶ プレイ」でゲーム本体を起動して実際に確認、または「ここからプレイ」で任意の位置からテストプレイ
6. 保存は自動（タイル編集の1ストローク完了時、各種設定変更時）。ゲーム内で**矢印キー全押し**するとゲームを閉じてエディタに戻る（隠しショートカット）

## タイトル画面・ステージ選択

引数なしでゲームを起動すると、タイトル画面から始まります。

```
タイトル ⇄ ステージ選択 → プレイ ⇄ リザルト
```

| 画面 | 操作 |
|---|---|
| タイトル | ↑↓またはW/Sで選択、Enter/Zで決定、マウスクリックでも可 |
| ステージ選択 | 方向キーで選択、Enter/Zで決定、**Esc・BackSpace・Xでタイトルへ戻る** |
| リザルト | 「つぎのステージへ」「もういちど」「ステージ選択へ」 |

**Esc キー**は、画面によって次のように動きます（以前は確認なしでゲームが終了していました）。

| 画面 | Esc の動き |
|---|---|
| プレイ中・リザルト | **システムメニュー**を開く（つづける／もういちど／ステージセレクトへ／操作一覧／ゲームをおわる）。もう一度 Esc で閉じる。メニュー中は世界が完全に止まる。「ゲームをおわる」は**2回押して確定** |
| ステージ選択 | タイトルへ戻る |
| タイトル | ゲームを終了する |

**F1** はプレイ中にいつでも**操作一覧**を開きます（キー操作とマウス操作をまとめた一覧）。

プレイ中の移動は **A／D と ←／→**、ジャンプは **W と ↑** のどちらでも動かせます（時間停止中の ←／→ は「コマ送り」に使うため、停止中は動きません）。Space は時間停止に使っているため、ジャンプには割り当てていません。

**Lab_Editorからテストプレイした場合はタイトルを経由せず、そのステージへ直接入ります。** ゲーム側は「コマンドライン引数が付いているか」でエディタからの起動かを判断しています。タイトル画面そのものを確認したいときは、Lab_Editorのメニュー「プレイ」→「タイトル画面から起動」（Shift+F5）を使ってください。

### 進行状況の保存

クリアしたステージと、そのステージで取ったアイテムの最高数が `%LOCALAPPDATA%\LabProject01\save.json` に保存されます。ステージ選択画面には `CLEAR` の表示と取得数が出ます。

ステージごとに解放条件を設定できます。

| 条件 | 意味 |
|---|---|
| 常に選べる | いつでも選択できる |
| 前のステージをクリア | 一覧で1つ前のステージをクリアすると選べるようになる |
| 指定ステージをクリア | 指定した複数のステージを全てクリアすると選べるようになる |

セーブデータを消して最初から確かめたいときは、Lab_Editorの「ゲーム設定」→「その他」タブにある**「セーブデータを削除」ボタン**が使えます。

### 内容の編集

タイトル画面の文字・背景・メニュー項目・**要素の配置**、およびステージ一覧（表示名・並び順・サムネイル・解放条件）は、Lab_Editorのメニュー **「ゲーム設定(&G)」→「タイトル画面・ステージ一覧」** から編集できます。

- **タイトル画面タブ** … 640x480のゲーム画面をそのまま縮小表示したキャンバス上で、ロゴやタイトル文字をドラッグして配置します。8pxグリッドと画面中央へのスナップが効きます（Shiftを押しながらで無効）。矢印キーで1px、Shift+矢印で10px動きます
- **ステージ一覧タブ** … 並び順がそのまま「1つ前のステージ」の順序になります。▲▼で並べ替えてください
- **UIデザインタブ** … ゲーム画面に出るウィンドウの見た目を変えます（次節）
- **その他タブ** … ウィンドウタイトル、背景の下地色、リザルト画面の文言、セーブデータの削除

### ゲーム画面のウィンドウのデザイン（UIデザインタブ）

ゲーム画面に出る枠（左上のコイン・ゲージ、メッセージ、リザルトやポーズメニューのボタン、右クリックの円形メニュー、編集画面のパネル、ポーズメニュー、ステージセレクトのマス）は、これまで `img/UIウィンドウ.png` の固定の絵と、プログラムに書かれた数値・色で描かれていて、見た目を変える手段がありませんでした。「ゲーム設定」の**UIデザイン**タブで、コードを書き換えずに変えられます。

左のプレビューは**ゲーム画面と同じ並び**で枠のサンプルを描きます（ゲームと同じ式で描くので、見えている形がそのまま出ます）。サンプルをクリックすると、その枠の「枠ごとの設定」が開きます。

| 設定 | 内容 |
|---|---|
| 全体の枠の素材 | 9スライスで引き伸ばす枠の画像。「参照」で差し替え、「素材なし」で単色の枠、「既定の素材に戻す」で元の絵 |
| 素材の余白／縁の太さ／画面上の縁の太さ | 9スライスの切り方。素材の絵に合わせて調整する（四隅は伸ばさず、辺と中央だけ伸ばす） |
| 素材なしのときの単色の枠 | 素材を使わない（または読めない）ときの塗り・縁の色 |
| 文字の色 | 標準／うすい（補助・無効）／強調／警告・削除／正常・有効。標準・うすい・強調はタイトル／セレクト画面の文字色（テーマ色）と共通 |
| 編集コストゲージの色 | 中身／残りわずか（点滅）／器 |
| メッセージの置き方 | 左右の余白・下の余白・1行のときの高さ |
| 枠ごとの設定 | 枠の種類（7種）ごとに、素材・色合わせ（乗算）・不透明度・縁の太さを上書き。「全体と同じ」「全体に合わせる」で戻せる |

- 設定は `assets/game_config.json` の `ui_style`（文字色は `theme`）に保存され、**次にゲームを起動したとき**から反映されます。キーが無い古い設定でも、従来と同じ見た目で動きます
- ポーズメニュー（Esc）と操作一覧（F1）も、同じ枠・文字色で描かれるので、ここでの設定が一緒に変わります
- 色合わせは「素材の色に掛け算」なので、明るい素材を暗くする・色味を足すのに向きます。素材そのものの色を大きく変えたいときは、素材を差し替えてください

設定は `assets/game_config.json` に保存されます。このファイルが無い・壊れている場合は、タイトル画面を出さずに従来どおり起動即プレイになります（設定が壊れても遊べなくならないようにしてあります）。

## チュートリアルステージ

ステージ選択の先頭に、操作を順に覚えるステージが2つあります。どちらも**死にません**（敵・トゲ・穴が無く、各部屋の入口にチェックポイントがあります）。部屋ごとに説明が出て、**その操作をすると扉が開いて**先へ進めます。

| ステージ | 部屋（操作） |
|---|---|
| チュートリアル1：きほんと時間 | 移動 → ジャンプ（段差）→ ダッシュ → 弾を撃つ → 時間停止とコマ送り → 巻き戻し → 早送り → ゴール |
| チュートリアル2：画面と物の編集 | 色フィルタ(T) → 暗転(X) → 明転(C) → カラー補正パネル → ズーム(Z) → 縮小(V) → 右クリックで選ぶ・円形メニュー → ドラッグ移動 → 拡大縮小（重量スイッチ）→ 回転 → 反転 → 取り消し → 範囲選択 → カット → 地面を置く(G) → ゴール |

- 部屋の幅は画面1枚ぶん（20タイル）。扉の手前でその操作をすると、「できました！」が出て扉が開きます
- 拡大縮小の部屋だけは、物理ギミックです（ブロックを広げて重量スイッチに乗せる）。ジャンプの部屋は段差を越えるだけで、扉はありません
- 作り直すには `python tools/gen_tutorial_stages.py`（`assets/stages/tutorial_1_kihon.json` と `tutorial_2_hensyu.json` を書き出し、致死タイルが無い・地面に穴が無い・メッセージが3行×全角28字以内・扉の対応、を検査します）。Lab_Editor で保存し直しても動きますが、部屋を足すときはスクリプトを直すほうが楽です

### 「操作したら扉が開く」ステージの作り方

ゲームは、プレイヤーが操作した瞬間に、イベントのスイッチ `op_<名前>` をONにします。ステージのトリガーから、既存の条件 `SwitchOn`（`conditionParam` に `op_zoomin` など）で使えます。

| スイッチ | 操作 | スイッチ | 操作 |
|---|---|---|---|
| `op_dash` | ダッシュで走る | `op_zoomin` | Z（ズーム） |
| `op_shoot` | 弾を撃つ | `op_zoomout` | V（縮小） |
| `op_pause` / `op_step` | 時間停止 / コマ送り | `op_select` / `op_menu` | 右クリックで選ぶ / 円形メニューを開く |
| `op_rewind` | 巻き戻し | `op_move` / `op_scale` / `op_rotate` | ドラッグ移動 / 拡縮 / 回転 |
| `op_ff` | 早送り | `op_flip` / `op_undo` | 反転 / 取り消し |
| `op_color` / `op_dark` / `op_bright` | 色フィルタ / 暗転 / 明転（パネルで同じ状態にしても成立） | `op_areaselect` / `op_cut` / `op_ground` | 範囲選択 / カット / 地面を置く(G) |
| `op_grade` | 彩度・色相・コントラストを動かした | | |

- **`op_` で始まる `SwitchOn` は、トリガーの矩形の中にプレイヤーがいるときだけ**成立します。ほかの部屋でした操作で、先の部屋の扉が開いたりメッセージが出たりしないためです
- 扉を1枚ずつ開けるには、`OpenDoor` の `param2` に、置いた扉の `param` を書きます（空なら、その種類の扉を全部開けます）
- やり直し（リトライ）で、イベントのスイッチは全部消えます（以前は消えず、`SwitchOn` が1フレーム目から再発火していました）
- 時間停止中はイベントが止まるので、`op_pause` で開く扉は、停止を解いてから開きます。コマ送り（`op_step`）はコマ送りした瞬間に動きます

## カラー補正パネル（明るさ・色の調整）

ゲーム画面の右下に、動画編集ソフト（Premiere の Lumetri カラー、Photoshop の色調補正）に近い「**カラー補正**」パネルがあります。以前は「X長押し＝固定の暗転」「C長押し＝固定の明転」「Tキー＝赤→緑→青」だけで、どれだけ暗くなるのか・どの色になるのかを自分で決められませんでした。

| 部品 | 内容 |
|---|---|
| スライダー | **明るさ**（30〜170%）／**コントラスト**／**彩度**（0%で白黒）／**色相**（-180〜+180度）／**色温度**（寒色〜暖色）。つまみをドラッグして決めます。**ダブルクリックでその項目だけ初期値**、**ホイール**で微調整、初期値の近くではぴたりと吸い付きます |
| 色の輪 | **色フィルタ**の色（輪の角度）と強さ（中心からの距離）を、輪の上でつまんで決めます。中心＝かけない。「赤」「緑」「青」「×」のボタンで一気に合わせられます（Tキーと同じ状態） |
| テストチャート | 灰色の階調と虹色の帯を、「元」と「後（いまの補正をかけたもの）」で並べて見せます。いま何が起きているかが、ゲーム画面を見なくても分かります |
| ゲームの判定の表示 | 「[暗い判定]」「[明るい判定]」、「赤フィルタ／緑フィルタ／青フィルタ／判定なし」を文字で出します |
| リセット | すべて初期値へ戻します |

- パネルをつかんでいる間は**時間が止まります**（他の編集のドラッグと同じ）。止まっているあいだも画面には反映されるので、狙いを付けて合わせられます
- 画面の見た目はスライダーの値がそのまま反映されますが、**ゲームの判定は従来どおり**「暗い／ふつう／明るい」と「赤・緑・青・なし」で行います。連続した値から自動で決まります：

| 見る値 | 判定 |
|---|---|
| 明るさ | **60%未満＝暗い**、**130%より上＝明るい**（敵やギミックが見ているしきい値と同じ） |
| 色フィルタ | 色の輪の強さが**50%以上**で、色相が赤(0度)・緑(120度)・青(240度)の**±35度以内**なら 1/2/3。それ以外は「なし」 |

  このため、既存の敵・ギミック・ステージは1つも直さずにそのまま動きます。弱点色の敵、色ロック足場、暗いと動く敵も、パネルで合わせた色・明るさに反応します
- **編集コスト**は、判定に関わる「明るさ」と「色フィルタ」だけが対象です（使っている間だけ減ります。0.05以内のずれは使っていない扱い）。コントラスト・彩度・色相・色温度は**見た目だけ**なので、画面エフェクトが使えるステージなら無料です
- X長押し（暗転）・C長押し（明転）・Tキー（色フィルタの巡回）は従来どおり使えます（長押し中はそちらが優先）
- 画面エフェクトが封印されたステージでは、パネルは暗くなって使えません
- 明るさ1.0を超えた分は、**加算合成**で本当に明るく描かれます（以前は上限255で頭打ちになり、明転が見た目に出ていませんでした）。彩度・色相・コントラストは画面全体にフィルタとして掛かります

### カラー補正と連動するギミック

- **補正スイッチ**（ギミックのタイプ26）：「見る値」（明るさ・コントラスト・彩度・色相・色温度・色フィルタ）が指定の範囲に入っている間だけ「押された」状態になり、**同じ param のゲート扉**（重量スイッチと同じ仕組み。param が空なら最初に見つかったスイッチと連動）を開けます。スイッチの上に条件が文字で出ます
- **補正ロック足場**（27）：同じ条件で実体化する足場。色ロック足場・明暗ロック足場を、コントラスト・彩度・色相・色温度にも広げたものです
- **色調ゾーン**（19）は、色の乗算（R/G/B）に加えて**彩度・色相・コントラスト**も重ねられます（モノクロ・セピア・色相ずらしなど）
- 敵の**多彩行動**（23）には、行動「**色補正**」（彩度・色相・コントラストを、近いほど強く変える）が加わりました
- どれも `gimmicks.json` / `enemies.json` に項目を足しただけで、書いていない既存のアセットは今までどおり動きます。Lab_Editor では、ギミックの行を選ぶと「見る値」を名前で選べます

## 画面の見かた（HUD・ヒントバー・パネル）

プレイ中の画面は、初めて遊ぶ人でも「いま何ができるか」が分かるように作ってあります。表記は日本語が基本で、キー名だけ英字（`[Space]` `[F1]` など）です。

| 場所 | 内容 |
|---|---|
| **左上の枠** | コインの枚数、体力（ハートの並び。失った分は灰色）、編集コストのゲージ |
| **右上のバッジ** | 世界の状態（「時間停止中」「編集中：時間が止まっています」）、色フィルタ、明るさ（暗い／明るい判定）、ミュート、拡大表示中の案内。縦に積まれるので重なりません |
| **コストの増減** | ゲージの右隣に「-3」「+5」のように短く浮かびます |
| **下寄り中央のメッセージ** | 取り消し・やり直し・できなかった理由。頭の記号で種別が分かります（○ 成功／× 拒否／！ 情報） |
| **下端のヒントバー** | いまの状況に合わせて1行で出ます（通常／時間停止中／物を選んでいるとき／物の編集が封印されたステージ）。幅が足りないときは後ろの項目から省かれますが、末尾の「F1 操作一覧」「Esc メニュー」は必ず残ります |
| **画面の縁の色** | 琥珀色＝時間停止中、水色＝ドラッグ中（つまんでいる間だけ止まる） |
| **物の頭上の札** | 「停止中（踏める）」「巻き戻し中（すり抜け）」「無害」など。乗ってよいのか、触れたら被弾するのかの目印です |

- これらの HUD は、ゲーム画面を転送したあとに重ねて描くので、X長押し（暗転）・Z長押し（ズーム）・色補正の影響を受けません。F10 の拡大表示でも文字がにじみません
- 左パネルには「いま使える編集」（○＝使える／封印）、マウス操作、キー操作の早見表があります。詳しい一覧は **F1**
- 右パネルのインスペクターは日本語表記で、角度は度で出ます。物の編集が封印されたステージでは灰色になります
- 文字は、メイリオ（アンチエイリアス）に統一してあります。メイリオが無い環境では、DxLib の既定フォントで表示されます

### ズーム（Z）

見たい所を、**虫眼鏡のように**拡大して見られます。

- **Z を押している間**、マウスの位置を動かさないまま拡大します。マウスを動かすと、見る場所も動きます
- **Z を押したままホイール**で、倍率を 1.2〜3.0 倍に変えられます（0.1刻み）。選んだ倍率は覚えていて、次に押したときもそこから始まります
- **時間停止中でも使えます**（ドラッグ中も）。世界を動かさず、見た目だけを変える操作だからです。使えないのは、メッセージ表示中だけです
- **拡大枠**（四隅の印つきの四角）は、必要なときだけ出ます。Z を押した直後（拡大されていく範囲を示し、拡大が落ち着くと消えます）と、Z を押したままホイールで倍率を上げた直後（新しい倍率で映る範囲を示し、落ち着くと消えます）。ふだんは出ません
- 拡大中は、右上のバッジに「ズーム ×1.6」、左パネルの「ズーム [Z長押し]」の行にも倍率が出ます
- 編集コスト（画面エフェクトのドレイン）を使います。コストが足りないとき・画面エフェクトが封印されたステージでは効きません
- 拡大中も、右クリックの選択・ドラッグ・つまみは指した場所どおりに効きます
- ズーム固定の敵に捕まっている間は、その敵の中心・倍率が優先されます（Zでは打ち消せません）

### ズームアウト（V）

ズーム（Z）の反対に、**広い範囲を見渡せます**。ズームと同じく、カーソルの下の点を動かさないまま縮めます。

- **V を押している間**、マウスの位置を中心に縮小します（画面の外側にあった敵やステージの端も映ります）
- **V を押したままホイール**で、倍率を 0.5〜0.9 倍に変えられます（0.1刻み。上へ回すほど等倍に近づきます）。選んだ倍率は覚えていて、次に押したときもそこから始まります（初期値は 0.6）
- Z（ズームイン）を押しているときは、Z が優先されます。時間停止中・ドラッグ中でも使えます
- 縮小中は、右上のバッジに「ズームアウト ×0.6」、左パネルの「縮小 [V長押し]」の行にも倍率が出ます
- 編集コスト（画面エフェクトのドレイン）を使います。コストが足りないとき・画面エフェクトが封印されたステージでは効きません
- 縮小中も、右クリックの選択・ドラッグ・つまみは指した場所どおりに効きます
- **新しく映った敵は動きはじめます**（敵は「モニターに映っている間だけ動く」ため）。広く見るぶん、遠くの敵まで目を覚まします
- ズーム固定の敵に捕まっている間は効きません（縮小で打ち消せません）
- ステージの端より外は、背景の色（背景が無ければ暗い色）のままです
- しくみ：縮小しているあいだだけ、世界を余白つきの大きな画面（1920x1440）へ描き、縮めて通常の画面へ写します。縮小していないときの描画は今までと同じです

## 画面の大きさとフルスクリーン

大きなディスプレイで遊んでも、キャラ・ブロック・ギミックが小さく見えないように、画面を大きくできます。見える範囲（640x480 ぶんの世界）は変わらないので、ステージの難しさは変わりません。

| 操作 | 内容 |
|---|---|
| **ウィンドウの大きさ** | 起動時、デスクトップに収まる最大の大きさ（最大1.5倍＝1920x1080）で開きます。縁をつかんで大きさを変えられ、縦横比 16:9 は保たれます。画面全体（パネルも文字も）がまとめて拡大されます |
| **F11** | フルスクリーンの切り替え（縁なしでモニターを覆います。モニターの縦横比が違うときは、黒い余白が付きます）。タイトル画面・ステージ選択・メニュー中でも効きます |
| **F10** | 拡大表示の切り替え。左・右・下の編集パネルを隠して、ゲーム画面を 1.5 倍（ふだんは 1.2 倍）で見せます。もう一度押すと戻ります |

- ゲーム画面は、ふだんの表示でも従来より大きく（等倍→1.2倍）なっています
- 拡大表示のあいだは、インスペクター・カラー補正パネル・タイムライン（カット）・一時停止ボタンが使えません（Space・T/X/C などのキー、ホイール、右クリックの円形メニュー、つまみでの編集は使えます）
- マウスの位置は、ウィンドウの大きさやフルスクリーンに関わらず、画面上の同じ場所を指します

## 敵・ギミック・アイテムの挙動スクリプト（Scratch風ビジュアルブロックエディタ）

既存の22種の敵・25種のギミックには「⚙ 挙動パラメータ」パネル（タイプ選択時に自動で表示項目が切り替わる）で速度・射撃間隔・索敵範囲などを調整できます。それだけでは足りない、完全にオリジナルな敵・ギミックを作りたい場合のために、**Scratchを参考にしたビジュアルなブロックエディタ**を用意しています。JSONを手書きする必要はなく、Lab_Editorの「🧩 挙動スクリプトを編集」ボタンからパレットのブロックをキャンバスへドラッグ&ドロップして組み立てられます。

### 使い方

1. アセット管理画面で、敵の`type_enum`を**20（カスタムスクリプト）**、またはギミックの`type_enum`を**24（カスタムスクリプト）**に設定する
2. 対象の行を選択した状態で「🧩 挙動スクリプトを編集」ボタンを押す
3. 開いたエディタで、左のパレットからブロックをキャンバスへドラッグして縦に積み上げていく。`Forever`/`If`等のC字ブロックの中にはブロックをネストできる
4. 数値・文字列・選択式の入力欄はクリックしてその場で編集できる。レポーター（丸型）/真偽値（六角形）ブロックは、対応するソケット（数値欄・条件欄）へドラッグして差し込める
5. 差し込み済みのブロックは右クリックで取り外せる。ブロック単体はキャンバス上で選択してDeleteキーで削除できる
6. 「💾 OK」で確定すると、そのままアセット管理画面の保存対象に反映される

保存されるデータの実体はJSON AST（下記参照）で、`assets/enemies.json`/`gimmicks.json`の`script`フィールドに格納されます。手書きで直接JSONを編集することも可能です。

```json
{
  "id": "my_custom_enemy",
  "name": "自作の敵",
  "type_enum": 20,
  "hp": 3, "width": 32, "height": 32, "sprite": "img/enemy.png",
  "script": [
    {
      "hat": "OnSpawn",
      "body": [
        { "op": "Forever", "body": [
          { "op": "MoveDirection", "dir": "Toward", "speed": 2 },
          { "op": "Wait", "frames": 30 },
          { "op": "Shoot", "angle": { "op": "DirectionToPlayer" }, "speed": 6, "damage": 1 }
        ]}
      ]
    }
  ]
}
```

実際に動く参考例が `assets/enemies.json`（`enemy_script_sample` / `enemy_script_patrol` / `enemy_script_stationary` / `enemy_script_dashcharger`）と `assets/gimmicks.json`（`gim_script_movingplatform`）に入っているので、そのまま参照・改造してください（複合パーツの参考例は次章参照）。

### 命令（ブロック）一覧

| カテゴリ | 命令 | 内容 |
|---|---|---|
| 制御 | `OnSpawn` / `OnDamaged` / `OnDeath`（ハット） | スクリプトの開始点。出現時／被ダメージ時／死亡時にそれぞれ実行される |
| 制御 | `Forever { body }` | 本体を無限に繰り返す |
| 制御 | `Repeat { count, body }` | count回繰り返す |
| 制御 | `RepeatUntil { cond, body }` | condが真になるまで繰り返す |
| 制御 | `If { cond, body }` / `IfElse { cond, body, else }` | 条件分岐 |
| 制御 | `Wait { frames }` | 指定フレーム待機 |
| 制御 | `WaitUntil { cond }` | condが真になるまで待機 |
| 動き | `MoveDirection { dir: "Left"/"Right"/"Toward"/"Away", speed }` | 方向・速度を指定して移動 |
| 動き | `ApplyImpulse { vx, vy }` | 速度を直接設定 |
| 動き | `SetPosition { x, y }` / `OffsetPosition { dx, dy }` | 位置を設定／相対移動 |
| 動き | `FaceTowards` | プレイヤーの方を向く |
| 動き | `Oscillate { min, max, periodFrames }` | Y座標をmin〜maxで周期的に振動（動く足場等向け） |
| 動き | `SetLocalOffset { dx, dy }` | **パーツ専用。** 親（複合体本体）の現在座標からの相対位置を設定する |
| 動き | `SetLocalOffsetPolar { angle, radius }` | **パーツ専用。** 親を中心に「角度・半径」で相対位置を設定する。`Cos`/`Sin`を2回書かずに済む糖衣構文で、ファイアバーのように「同じ角度・パーツごとに異なる半径」を並べて回転する棒を作るのに使う |
| 動き | `SetAngle { angle }` | 見た目の回転角(ラジアン)を設定 |
| 攻撃・演出 | `Shoot { angle, speed, damage }` | 指定角度(ラジアン)へ弾を発射 |
| 攻撃・演出 | `ShootAtPlayer { speed, damage }` | プレイヤーへ自動照準して発射 |
| 攻撃・演出 | `SetInvincible { on }` / `SetScale { scale }` | 無敵状態／表示スケールの変更 |
| 攻撃・演出 | `SetVisualEffect { kind: "brightness"/"zoom", intensity }` | 画面演出 |
| 攻撃・演出 | `PlaySound { slot }` | 効果音を再生（`se.json`/`ui_se.json`に登録したidを指定。BGM再生には未対応） |
| 変数 | `SetVar { name, value }` / `ChangeVar { name, value }` | 変数の設定／加算 |
| センサー(式) | `SelfX` / `SelfY` / `PlayerX` / `PlayerY` / `DistanceToPlayer` / `DirectionToPlayer` / `Random{min,max}` / `GetVar{name}` | 数値を返す式ブロック |
| センサー(式) | `Time` | ゲーム開始からの経過フレーム数（リセットされないグローバルな「時計」） |
| センサー(式) | `ParentX` / `ParentY` | **パーツ専用。** 親（複合体本体）の現在のワールド座標 |
| センサー(式) | `ParentDirection` | **パーツ専用。** 親の向き（右向き=+1／左向き=-1） |
| センサー(式) | `ParentTilt` / `ParentScaleRatio` | **パーツ専用。** 親が配置時からどれだけ傾けられたか（ラジアン）／どれだけ拡大縮小されたか（倍率）。パーツは既定で親と一体の剛体として回るので、「親が傾いてもプレイヤーを向き続けてほしい」パーツは狙った角度から`ParentTilt`を引いて打ち消す |
| センサー(式) | `PartIndex` | **パーツ専用。** 自分が親のパーツ配列の何番目か(0始まり)。同一スクリプトを複数パーツで共有しつつ、パーツごとに異なる位相をつけるのに使う |
| センサー(式) | `SelfScale` / `SelfAngle` | 自分の現在の大きさ（倍率）／角度（ラジアン） |
| センサー(式) | `EditScaleRatio` / `EditTilt` / `EditSpeedRatio` | プレイヤーの編集ツールで、配置時からどれだけ大きさ・傾き・速さを変えられたか |
| センサー(式) | `ScreenColorFilter` / `ScreenBrightness` / `ScreenZoom` / `ScreenSaturation` / `ScreenContrast` / `ScreenHue` | 画面エフェクトの現在値（色フィルタ番号・明るさ・ズーム倍率・彩度(1が通常)・コントラスト(0が通常)・色相の回転(度)） |
| 演算子(式) | `Add`/`Sub`/`Mul`/`Div` `{a,b}` / `Const{value}` | 四則演算 |
| 演算子(式) | `Sin{a}` / `Cos{a}` | 三角関数（ラジアン）。回転・周回運動の自作に使う |
| 条件(式) | `Gt`/`Lt`/`Eq`/`And`/`Or`/`Not` `{a,b}` / `IsGrounded` / `IsWallAhead` / `IsGroundAhead` | 真偽値を返す式ブロック |
| 条件(式) | `EditFlipped` / `EditPaused` / `EditRewinding` / `EditEnlarged` / `EditShrunk` / `EditTilted` / `IsFastForward` | プレイヤーの編集操作を真偽値で受け取る（向き反転・一時停止・巻き戻し・拡大・縮小・傾け・早送り） |

`OnDamaged`/`OnDeath`は、`OnSpawn`とは独立した専用の実行状態で発火するため、`OnSpawn`側で`Forever`ループを回している最中に被弾・死亡してもそのループは巻き込まれて止まらない。ただし`OnDeath`は死亡と同じフレーム内で完結する処理（`PlaySound`/`SetVisualEffect`/`Shoot`等）のみを想定しており、`Wait`を挟む複数フレームにまたがる演出には対応していない（死亡直後は更新自体が止まるため）。

### 安全設計

無限ループを含むスクリプトを書いてもゲームがフリーズしないよう、以下の安全装置が入っています。

- `Forever`/`Repeat`が1周してループの先頭に戻る瞬間、必ずそのフレームの実行を打ち切る（次フレームで続きから再開）
- 1体・1フレームあたりの命令実行数に上限（500）
- 全スクリプト実行体の合計で1フレームあたりの命令数に上限（20000）
- コールスタックの深さに上限（32）。超えた場合はエラーとしてログに記録し、そのスクリプトの実行を停止する（"Faulted"状態、ゲーム自体は継続）

デバッグモード表示中（`isDebugDrawMode`）は、スクリプトで動く敵・ギミックの上に実行状態（RUN/DONE/FAULT、スタック深さ、待機フレーム数、Faulted時はエラー内容）が表示されます。さらに、デバッグモードでなくてもFaulted状態の敵・ギミックには常に赤字で「SCRIPT ERROR」と表示されるため、手編集したJSONが壊れている場合もプレイ中に気付けます。

## 複合パーツ・オブジェクト・システム（マルチスプライト構成の敵・ギミック・アイテム）

通常の敵・ギミック・アイテムは1つの画像・1つの当たり判定だけで構成されますが、扉（開閉する複数パネル）、マリオ風ファイアバー（軸を中心に回転する複数の火の玉）、体が分かれた敵（各部位を個別に攻撃できるボス等）のような**複数の画像パーツを組み合わせたオブジェクト**を作ることができます。パーツは前章のブロックスクリプトで自由に制御でき、**パーツごとに個別の当たり判定・HP**を持てます。

### 使い方

1. アセット管理画面で対象の敵/ギミック/アイテムの行を選択し、「🧩 パーツを編集」ボタンを押す（このボタンは`type_enum`に関係なく、どのタイプの敵/ギミック/アイテムでも使える。パーツは本体の挙動タイプとは独立して動作するため）
2. エディタは左（パーツ一覧）／中央（合成プレビュー）／右（選択中パーツの詳細）の3分割で、境界線をドラッグして各領域の広さを調整できる。操作の入口は**上のツールバー**にまとまっている（追加・複製・反転複製・削除／手前へ・奥へ／整列／テンプレート／動きを追加）。結果は下の状態欄に出るので、操作のたびにメッセージボックスで止まることはない
3. 右側の詳細パネルは「基本（ID・画像）／位置／大きさ／性質（HP・触れるとダメージ・重なり）／動きと当たり判定」に分かれている。「📝 挙動スクリプトを編集」ボタンから、そのパーツ専用の挙動スクリプトを編集する（前章と全く同じブロックエディタ）。ツールバーの「🧩 スクリプトを全パーツへ」で、選んだパーツのスクリプトを全パーツにコピーできる
4. 動きを持った複合パーツを、数値を入れるだけで作れる。**「✨ テンプレートから追加…」**（次節）か、「🌀 動きを追加」の「回転する棒／振り子／公転」を使う
5. 「💾 OK」で確定し、通常通りアセット管理画面から保存する

### 配置したときの大きさ・角度とパーツ

ステージ編集で敵を置くときに指定する**大きさ（scale）と角度（angle）**は、本体だけでなく**パーツ（黒目・翼・砲身など）にも効きます**。

- 以前は、パーツはゲーム内で操作した「差分」にしか反応せず、配置時に scale 1.4 や角度を付けて置くと、本体だけ大きく・傾き、パーツは元の大きさ・位置のまま取り残されていました（テンプレートで作った敵を置いて大きさを変えると目立ちました）。現在は配置時の値から本体と一緒に拡大・回転します
- scale 1・角度 0 で置いた敵の見た目・当たり判定は、従来と変わりません
- ステージ編集の画面（マップ）にも、敵のパーツが描かれるようになりました。置いてある位置の静止画で、配置した大きさ・角度のとおりに表示されます（動き＝スクリプトは再現しません）

### パーツ編集画面の操作

合成プレビューは、**本体の左上を原点（0,0）とするワールド座標**を、拡大縮小・移動できる画面で表示します。パーツの `offset` は、この原点からの「パーツの左上」の位置です（ゲームと同じ解釈）。

| やりたいこと | 操作 |
|---|---|
| 拡大・縮小 | **マウスホイール**（マウスの下の点が動かない）。`＋`/`－` ボタンや、キーボードの `+` `-` も使える |
| 表示を動かす | **中ボタンのドラッグ**、または **Space を押しながらドラッグ** |
| 全体が収まる表示にする | 「⛶ 全体表示」、または `Home` / `F` |
| パーツを選ぶ | クリック。一覧とプレビューは連動する |
| 複数選ぶ | **Ctrl（Shift）＋クリック**で追加／解除、**何もない所からの範囲ドラッグ**、`Ctrl＋A` で全選択 |
| 動かす | ドラッグ（複数選択のときは全員が一緒に動く）。**8pxのグリッドに吸着**する。`Alt` を押している間は吸着しない |
| 大きさを変える | 選んだパーツの**右下のつまみ**をドラッグ（縦横比を保つ。`Shift` で自由）。幅・高さの数値でも変えられる |
| 微調整 | 矢印キーで1px、`Shift`＋矢印キーで8px |
| 複製／削除 | `Ctrl＋D`／`Delete`（削除は確認なし。`Ctrl＋Z` で戻せる） |
| そろえる | ツールバーの「⇔ 整列」：左・中央・右・上・中央・下にそろえる、横・縦に等間隔にならべる（2つ以上選んだとき） |
| 動きを確かめる | 「▶ 再生」。プレイヤーのいる向きや狙う向きは、左右に振って見せる（黒目や砲身の動きが分かる） |
| 当たり判定を見る | 「当たり判定」にチェック（赤い点線）。選んだパーツは常に表示される |
| 取り消し・やり直し | `Ctrl＋Z` / `Ctrl＋Y`。**同じ項目の連続した変更（数値を何度も変える・矢印キーを何度も押す）は1手にまとまる** |

- 右クリックで、複製・反転複製・削除・手前へ/奥へ・画像・スクリプトのメニューが開く
- **反転複製**は、本体の中心線に対して左右反転します（パーツの位置・当たり判定・スクリプトの横方向の動きがすべて鏡写しになる）
- パーツの `deadly`（触れるとダメージ）を、詳細パネルのチェックで設定できる。以前は、パーツ編集画面を開いて保存し直すだけで `deadly` が消えて、回転する棘の輪などが素通りできる飾りに戻っていた不具合を直してある

### パーツの仕組み

- パーツは`PartDef`（テンプレート）として敵/ギミック/アイテムの定義に付随する（JSON上は`parts`配列）。`parts`が空の既存アセットは完全に無変更で動作する
- 各パーツは`offsetX`/`offsetY`（本体からの初期相対位置）、`width`/`height`（表示サイズ）、`hitboxOffsetX/Y`・`hitboxWidth/Height`（個別の当たり判定）、`scale`、`hp`、`zOrder`、`script`を持つ
- **HP=0のパーツは破壊不能な常在ハザード**（ファイアバーの火の玉のように、触れると常にダメージを与え続ける）。**HP≧1のパーツは弾で個別に破壊可能**で、破壊されても本体自身のHP・生死には一切影響しない（弱点部位のみを狙い撃つボス戦などに使える）
- パーツはスクリプトの`SetLocalOffset`/`SetLocalOffsetPolar`/`SetAngle`で自由に動かせる。`ParentX`/`ParentY`で本体の現在座標を、`PartIndex`で自分の番号を、`Time`で経過フレーム数を、`Sin`/`Cos`で三角関数を取得できるため、周回運動・振動・追従・扇状配置などをスクリプトのみで組める。特に「同じ角度・パーツごとに異なる半径」で`SetLocalOffsetPolar`を使うと、ファイアバーのように一直線に並んだまま回転する棒状の配置になる（左のパーツ一覧の「🌀 回転する棒として配置...」ボタンで自動生成できる）
- **パーツは本体に必ず追従する。** 本体の移動・拡大縮小・傾けはすべてパーツ側へ合成されるため、スクリプトを持たないパーツでも本体に張り付いたまま動く。編集ツールで本体をドラッグしている最中（ゲーム内の全オブジェクトが止まっている間）も追従は途切れない
  - 親を2倍にすればパーツも2倍の大きさになり、本体の中心からの位置関係も2倍に広がる。親を45度傾ければパーツも一緒に45度回る
  - パーツが継承する倍率は **0.25〜4.0倍にクランプ**される。当たり判定が8x8しかないファイアバーのようなギミックを目一杯引き伸ばしたときに、腕だけが画面外まで伸びて事故になるのを防ぐため。描画と当たり判定の両方に同じ値を使うので、見た目と判定がズレることはない
  - 「親が傾いてもプレイヤーを向き続けてほしい」パーツ（ドッスンの黒目、砲台の砲身など）は、狙った角度から`ParentTilt`を引いて親の回転を打ち消す。`assets/enemies.json`の`enemy_dossun`・`enemy_houdai`が実例
  - 当たり判定は従来どおり軸平行の矩形（AABB）のままで、パーツの回転角は判定に反映されない
- `OnDamaged`/`OnDeath`はパーツ単位でも発火する。パーツが破壊されるとそのパーツ専用の`OnDeath`が一度だけ実行される
- 描画順は`zOrder`が負のパーツ→本体→`zOrder`が0以上のパーツ、の順（本体より奥/手前を指定できる）

### テンプレート（複合パーツの「型」）

複数のパーツで動く敵（芋虫の連なる胴体、砲台の動く砲身、ドッスンの黒目、ベロの舌…）は、これまで1つずつスクリプトを書いて作っていました。いまは、そうした動きを**「型」**として切り出してあり、**画像と数値を入れるだけ**で、パーツ（位置・大きさ・当たり判定・挙動スクリプト）が一式できます。

**使い方は2通りあります。**

1. **パーツ編集画面の「✨ テンプレートから追加…」** … 編集中の敵・ギミック・アイテムへ、パーツ一式を追加する（「いまあるパーツを全部消して置き換える」も選べる）。同じ型を続けて追加しても、IDは重ならない
2. **アセット管理画面の「✨ 敵をテンプレートから作る」** … パーツだけでなく、**敵のタイプ・HP・大きさ・体節の間隔・本体の絵・（必要なら）本体のスクリプト**まで、型が勧める設定で、新しい敵を1体作る。作ったあとは、通常の敵と同じように自由に直せる

ダイアログの右側に、作られるパーツが出ます。「▶ 動かす」で、スクリプトの動きも確かめられます（緑の枠＝弾で壊せる、赤の枠＝触れるとダメージ）。

**既存の敵から取り出した型（5つ）** … 初期値は元の敵と同じ動きになります。

| 型 | 元の敵 | 内容 |
|---|---|---|
| 🐛 多節体（うねる胴体） | `enemy_imomushi` | 体節が本体の後ろに連なり、節ごとにずれた波を描いてくねる。節の数・間隔・うねりの大きさ・速さ・波のずれを決められる |
| ⛓ 連なる体節（敵タイプが動かす） | `enemy_kikai_imomushi` | 体節を一列に並べるだけの型。動きはスクリプトではなく敵タイプ「跳ね回る節足敵」が決める。節の間隔は敵の `segmentGap` に自動で入る |

**型の作りの約束（自分で型を足したい人向け）**

- 型の定義は `Lab_Editor/Lab_Editor/PartTemplates.cs`。数値の入力欄・初期値・プレビュー・敵の設定の提案は、定義から自動で作られる
- 位置は「本体の左上が原点」「パーツの左上」で書く。回転や周回は本体の中心を基準にした式にする（`SetLocalOffset` の原点は本体の左上なので、中心からの距離は `本体の幅/2 − パーツの幅/2` を足して表す）
- スクリプトの中の「何番目のパーツか」は、`PartIndex` ではなく**生成時の番号を数値として焼き込む**。`PartIndex` は配列の並びで決まるため、あとから別のパーツを足したり並べ替えたりすると、体節の間隔や位相が崩れてしまうため
- 生成したスクリプトは、ゲームに存在する命令だけを使っていること、有限の位置を返すこと、スクリプトエディタで読めることを、検査してある

| 🔴🟢🔵 3原色の光球 | 赤・緑・青の光球が本体のまわりを回る |
| 🌈 色相環 | 色相がずれた光球の輪が回り、色も虹色に変わり続ける |
| 🚨 回転灯 | 細長い光の帯が回り続ける（逆回りの帯も重ねられる） |
| 🌓 月の満ち欠け | 明るい円の上を暗い円が横切り、明暗がゆっくり入れ替わる |
| 🎚 露出メーター | 暗い側（青）と明るい側（黄）の目盛りの上を、白い針が行き来する |
| 📸 フラッシュ | 溜めている間は明滅しながら強まり、攻撃した瞬間にぱっと閃光する |
| 🌈 色ずれ | 本体と同じ絵が赤・緑・青の3枚に分かれ、少しずれて重なる（色収差） |
| 📺 カラーバー | テレビの調整画面のような色の帯が、波のように順番に明滅する |

- 飾りのパーツは**当たり判定を2×2に絞って**あります（敵のパーツは触れると被弾するため、大きな光の輪が当たり判定を持たないようにしています）
- 追加した型のパーツも、普通のパーツと同じように、位置・色・動きを自由に直せます

#### パーツの色・加算合成・伸縮

パーツの詳細パネルの「性質」に、次の項目が加わりました。どれも使っていないパーツは1ピクセルも変わりません。

- **色**（`color`：`#RRGGBB`）：絵に掛ける色。白い絵を赤・緑・青に塗り分けられます
- **加算合成**（`blend`：`add`）：下の絵に明るさを足して描きます（ゲームで光って見えます。エディタのプレビューは少し薄くして重ねる近似です）
- **縦横を別々に伸ばして描く**（`stretch`）：細長い光の帯や針に。OFFのときは、幅・高さの小さいほうに合わせた縦横比のまま描かれます

### パーツの動き（モーション）

パーツ編集画面の詳細パネルの「**動き（モーション）**」で、**パーツごとに違う動き**を、スクリプトを組まずに作れます。「いつ（トリガー）」「どんな動き（種類）」「数値」を選ぶだけで、いくつでも重ねられます。挙動スクリプトとは独立しているので、併用できます（スクリプトで決めた位置の上に、動きが重なります）。

| いつ（トリガー） | 内容 |
|---|---|
| いつも | 常に動き続ける |
| 攻撃したとき | 弾を撃つ・突進や飛びかかりに入る・体当たりした瞬間から、「動いている長さ」のぶんだけ |
| ジャンプしたとき | ジャンプ（飛びかかりを含む）した瞬間から |
| 溜めているとき | 突進の溜め・落下の予兆・射撃の直前など、「これから行動する」間だけ |
| 行動中 | 突進中・落下中・飛びかかりの飛行中だけ |
| 弾を受けたとき | 弾を受けた瞬間から |
| プレイヤーが近いとき | 指定の距離以内にいる間だけ |
| 動いているとき | 本体が動いている間だけ |
| 向きを反転された／傾けられたとき | 編集ツールで反転・傾けされている間だけ |

動きの種類：**揺れ**（行き来）／**首振り**／**回転**／**円運動**／**ふくらみ**／**スライド**／**突き**（素早く出てゆっくり戻る）／**点滅**／**震え**／**プレイヤーを向く**／**明るさ**（明滅・発光。プラスは光る、マイナスは暗くなる）／**色相が回る**（虹色）。波の形（なめらか・一定の速さ・カクカク）、始まるまでの遅れ、位相のずれも決められます。

- 「＋ 動きを追加」には、**よくある動き**（攻撃したとき前へ突く／溜めている間ふくらむ／プレイヤーが近いと点滅…／ずっと呼吸するように明滅／攻撃したとき一瞬ぱっと光る…）と、複数の動きをまとめて追加する**セット**（警報灯／呼吸する光／虹のきらめき／フラッシュ／被弾リアクション／気づく／攻撃の見せ場）が入っています
- 「**この動きを、選んでいる他のパーツへコピー**」と「**パーツ番号ごとのずれ**」を使うと、同じ動きを少しずつずらして並べられます（波打つ尻尾、順番に光る節など）
- 合成プレビューの「**状況を試す**」で、溜めている・行動中・プレイヤーが近い…といった状況を作り、「攻撃!」「ジャンプ!」「被弾!」のボタンでイベントを起こして、トリガー付きの動きを確かめられます（再生中に動きます）
- 「攻撃・ジャンプ・被弾・溜め・行動中」は**敵のパーツ**でだけ動きます。ギミック・アイテムのパーツでは、「いつも」「プレイヤーが近いとき」などが使えます
- 巻き戻しでは、位置が時計で決まる動き（いつも・状態系）は正しく戻りますが、攻撃などの「イベントを起こした瞬間」の再生までは巻き戻りません

## 敵の動きを調整する

アセット管理の敵の行を選んで「**🎛 敵の動きを調整**」を押すと、その敵の挙動を、日本語の項目名・単位・説明つきのスライダーで細かく調整できます（全タイプ対応）。左のプレビューで、数値がどう動くかを確かめられます。

- **「既定を使う」**にチェックが入った項目は、タイプごとの標準の値で動きます（内部の `-1`）。外すと自分の値を指定でき、「すべて既定に戻す」で全部を標準へ戻せます。変えた項目は強調されます
- プレビューは型ごとに変わります：距離（青い丸＝プレイヤーをドラッグ）／波形のグラフ／暗転の距離ごとの明るさ／色変化の色味と見本画面／弾の向き・本数・ブレと予兆／溜め→行動→休みの時間配分
- 「**▶ ゲームで試す**」で、いまの値でその敵を1体だけ置いたテスト用ステージ（`assets/stages/_enemy_tune.json`）を作ってゲームを起動します（先にアセット定義を保存します）
- 「この内容にする」で反映、「キャンセル」で開いたときの値へ戻ります

### 調整できるようになった項目

| 型 | 項目 |
|---|---|
| 色変化(18) | **画面を寄せる色**（RGBで自由に。指定しないと従来どおり、傾けるたびに赤→緑→青）、**打ち消せる色フィルタ**（自動／なし／赤／緑／青） |

どれも「既定」のままなら、従来と1ミリも変わらない動きです。

### 多彩行動（タイプ 23）

「**何種類の行動をするか**」を自由に決められるタイプです。待機・歩く・ジャンプ・突進・弾（本数・扇・連射・狙い方）・瞬間移動・暗転・色変化（指定色）・ズーム・色補正（彩度・色相・コントラスト）の中から好きな行動を好きな数だけ並べ、**順番どおり／ランダム／重み付き**で切り替えながら繰り返します。

- 1つの行動は「**予兆 → 行動中 → 後隙（休み）**」の3段階で、それぞれの長さを決められます
- この3段階は、パーツの動きの「溜めているとき」「行動中」にそのまま繋がります（例：突進の予兆で口を開く）
- 反転すると弾が味方のものになるなど、他の射撃型と同じ編集ツールへの反応が効きます。巻き戻すと行動も戻ります

## 敵の向きを変えたときの動き

編集ツールで敵を**回転**（`R`＋ドラッグ）させたり**向き反転**させたりすると、その敵の**移動・射出の方向がそのまま向いている方向に変わります**。見た目が傾いているのに真下へ落ちる、といった食い違いは起きません。

### 基準の向き

敵はタイプごとに「編集されていないときにどちらを向いているか」という基準の向きを持っており、回転はその基準を回す形で効きます。回転の向きはスプライトの見た目と完全に一致します（時計回りが正）。

| 基準 | 対象 | 傾けるとどうなるか |
|---|---|---|
| **下** | ドッスン（落ちてくる敵） | 落下方向そのものが変わる。90度倒せば真横へスラムし、180度回せば真上へ突き上げる。落下予兆（溜め）のあいだは空中で静止するので、**動くのは常に向いている方向だけ**です |
| **上** | 飛びかかり・ジャンプ・各種射撃・テレポート | 跳躍角・射出方向・出現方角が変わる。いもむしを真上や後方へ向ければ「砲弾」として撃ち出せる |
| **前（左右）** | 突進・歩行・追跡・浮遊 | 突進は傾けた角度どおりに一直線へ飛ぶ。歩行系は水平成分だけを使うので、90度倒すと止まり、180度回すと逆走する（宙に歩き出すことはない） |

**向き反転**は、縦向きが基準の敵（ドッスン・射撃系など）では基準の向きを向いている側へ30度振ります。ドッスンを反転させると斜めに落ちるのはこのためです。左右が基準の敵はもともと向き自体が反転するので、二重には効きません。

### 落下・突進は重力を切る

ドッスンの落下中と突進の突進中は重力を打ち消し、本体の軸方向へまっすぐ加速します。重力を残すと斜めに向けても途中で失速して真下に落ちてしまい、角度どおりに飛ばないためです。真下を向いているあいだは従来の自由落下と完全に同じ速さになります。

遮る地形が無い向きへ飛ばすと遠くまで飛んでいくので、**マップの外に出るか一定時間が過ぎたら自動的に着地扱い**になり、必ずクールダウンを経て元の位置へ戻ります。

### 砲台の手動照準

砲台の狙いは**本体が1箇所で決め、砲身の絵はその結果を読んでいます**（スクリプトの `ParentAim`）。
砲身が自分で「プレイヤーの方向」を計算し直していたころは、本体が追尾をやめる条件を足すたびに
「砲身はこっちを向いているのに弾は別の方向へ飛ぶ」という食い違いが起きていました。
絵と弾は必ず同じ向きになります。

砲台は **「編集された → その瞬間に追尾を止める → 向けられた方向へ1発撃つ → 追尾を再開する」** という順に動きます。
編集されている間の狙いは、プレイヤーがどこへ動いても**いっさい変わりません**（高さも追いません）。

- **傾ける**：傾けた向きへ固定され、次の一発をそこへ撃ちます。
- **反転する**：向けられた側へ真横に固定され、次の一発をそこへ撃ちます。反転は砲台がプレイヤーを向いている状態で行うので、結果として背中側へ撃つことになります。

撃った時点で編集は消費され、次のフレームからまたプレイヤーを追います。スイッチや壊せるブロックを撃たせたいたびに、狙いを付け直す操作になります。

**回るのは砲身だけで、台座は置いたときの姿勢のまま動きません。** 砲台は「本体の絵＝台座／砲身＝パーツ」という構成なので、回転を本体にも掛けると三脚ごと傾いて浮いているように見えてしまいます。敵の定義に **`bodyIgnoresTilt`**（Lab_Editor の共通欄「回転しても本体の絵は傾けない（回るのはパーツだけ）」）があり、これがONの敵だけ本体の絵を配置時の姿勢で描きます。既定はOFFなので、ドッスンのように**全体が回るのが正しい敵は従来どおり**です。

**弾は砲身が指している向きへ、そのまま飛びます。** 反転も一緒に使っているときは弾だけ30度ずれて飛んでいましたが（反転ツールが縦向きの敵の軸を振る補正が、砲台にも掛かっていたため）、砲台系ではその補正を掛けないようにしてあります。砲身の絵と弾道は必ず一致します。

### 向き反転でできること

向き反転は、縦向きが基準の敵の落下・射出方向を30度振るほかに、タイプごとの固有の反応も持っています。主なものは次のとおりです。

| 敵 | 反転させると |
|---|---|
| 固定砲台・照準砲台 | **その瞬間にプレイヤーを追うのをやめ、背中側へ真横に1発撃ち、撃つと追尾に戻ります。** あわせてその弾がプレイヤー側の弾になり、他の敵や壊せるブロックに当たります。砲台の向こう側にあるものを撃たせたいときは、自分が砲台の手前に立って反転させます |
| 巡回砲台 | プレイヤーを見つけても撃たず、反対側へ逃げ出します |
| 巡回敵 | 巡回範囲の端を待たず、その場で折り返します |
| 突進・追跡・歩行・浮遊 | プレイヤーを追うのをやめ、逃げる向きへ進みます |
| 落下リフト・重量スイッチ・色/明暗ゾーンなど | 効果が裏返ります（沈む→浮上、暗転→明転 など） |

**反転の判定には「プレイヤーが反転ツールを使ったか」だけを見ています。** 以前は「配置時と向きが違うか」で判定していたため、プレイヤーを追って自分から向きを変えるタイプの敵では、プレイヤーが左右を行き来するだけで反応が勝手に点滅していました。

## 壊せるブロックの設定

壊せるブロック（type_enum=3）は、**誰が壊せるか**と**壊すのに必要な相手の大きさ**をブロックごとに設定できます。Lab_Editorのアセット管理でブロックを選ぶと、右側のパラメータ欄に出ます。

| 設定 | 意味 |
|---|---|
| ドッスンの落下衝撃で壊れる | ドッスンが着地したとき、衝撃波の範囲内なら壊れる |
| 敵の体当たりで壊れる | 突進・歩行・巡回の敵がぶつかると壊れる |
| 弾で壊れる | プレイヤーの弾（および反転させた砲台の弾）で壊れる |
| クリックで壊れる | 編集モードでの直接クリックで壊れる |
| 45度以上傾けると自重で崩れる | 回転ツールで倒すと自分から崩れる |
| 壊すのに必要な相手の大きさ | 0なら大きさを問わない。1.2なら「1.2倍以上に拡大した敵の衝撃でなければ壊れない」。敵の衝撃にだけ掛かり、クリックと自重崩壊には掛かりません |

同梱している2種類：

- **`gim_breakable`（壊せるブロック）** … 全てONの汎用ブロック。従来どおりどの手段でも壊せます
- **`gim_breakable_heavy`（重量ブロック）** … **ドッスンの落下衝撃でしか壊れません。** 弾も体当たりもクリックも効かないので、「ドッスンの向きを変えて狙わせる」ことが唯一の答えになる仕掛けが作れます

ドッスンは**スラムするときなら編集状態に関係なく**ブロックを壊しにいきます（縮小していても壊します）。壊せるかどうかはブロック側の設定が決める、という分担です。

衝撃が起きる場所は**ぶつかった面**です。真下へ落ちるときは足元、横向きに回してあるときは進行方向側の面が中心になります。真下だけを見ていたころは、横向きのドッスンが壁に密着していても衝撃の中心が体の後ろ側にあり、目の前の壊せる壁が判定の輪から外れて一切壊れませんでした。

### 大きさが足りないときは画面に出ます

「必要な大きさ」を満たしていないだけで弾かれたときは、そのマスに枠と **`1.3倍以上で壊せる`** のような表示が出て、「操作できない」音が鳴ります。条件を緩めるのではなく、条件が見えるようにするための表示です。何も出ないまま壊れない場合は、大きさではなく**そもそも届いていない**（当たっていない・その壊し方が許可されていない）ということになります。

### 変わらないもの

- **当たり判定は軸平行の矩形（AABB）のまま**です。横倒しにしたドッスンの判定が横長になることはありません
- 壊せないブロックに当たった弾は、そのブロックを素通りして先へ進みます（弾はもともと地形タイルにしか遮られません）
- 色・大きさ・テンポだけが変わるタイプ（色調整敵・大きさが変わる敵・速さ操作敵など）の傾け反応は従来どおりです
- まるび（パトロール）を傾けると転がる挙動も従来どおりです（「丸いものは坂を転がる」という別の比喩のため）

## 地形タイルを壊せるようにする

壊せるのはギミックの「壊せるブロック」だけではありません。**マップに敷いた地形タイルそのもの**にも、同じ考え方で破壊条件を設定できます。Lab_Editor の「🧱 タイル定義」から開き、各タイルの行にある4つのチェックで決めます。

| 列 | 意味 |
|---|---|
| 叩きつけ | ドッスンが着地したとき、衝撃波の届く範囲なら砕ける |
| 体当たり | 突進・歩行・巡回の敵がぶつかると砕ける |
| 弾 | 弾が当たると砕ける（当たった弾も消えます） |
| 手動 | 編集モードで直接クリックすると砕ける |
| 必要倍率 | 壊すのに必要な相手の大きさ。0なら大きさを問わない。1.5なら「1.5倍以上に拡大した敵の衝撃でなければ砕けない」 |
| 破壊音ID | 砕けたときに鳴らす効果音のID。空欄なら無音 |

**既定は全てオフです。** 触らない限り、地形は今までどおり絶対に壊れません。

### 巻き戻すと積み直ります

砕けたマスは「壊れてから何フレーム経ったか」を覚えていて、巻き戻している間はその時間が巻き戻ります。0まで戻ったマスは元のタイルへ戻ります。壊せるブロック（ギミック）と同じ振る舞いです。

- **巻き戻せる時間（約10秒）より前に壊したマスは戻りません。** それより過去は履歴自体が残っていないためです
- **プレイヤーが重なっているマスは、退くまで復活を待ちます。** 復活と同時に地形へ埋まって抜け出せなくなるのを防ぐためです
- ミスしてやり直したときやステージを開き直したときは、地形は必ず無傷の状態から始まります

### 壊せるブロック（ギミック）との使い分け

| | 地形タイル | 壊せるブロック（ギミック） |
|---|---|---|
| 置き方 | マップにタイルとして敷く | オブジェクトとして1個ずつ置く |
| 傾けて自重で崩す | できない（タイルは傾かないため） | できる |
| 大きさを変える | できない | できる |
| 大量に敷く | 得意 | 個数ぶん重くなる |

「壊せるブロックはどこで設定するんだったか」と迷ったときのために、タイル定義エディタの下部に **「🧱 壊せるブロック(ギミック)の設定」** ボタンを置いてあります。ここからギミック側の破壊条件もその場で編集できます。

### タイルの名前と色について

タイル定義エディタで付けた**名前と色を、ゲーム側も読むようになりました**（以前は書けるのに無視されていました）。画像を割り当てていないタイルは、指定した色でそのマスを塗ります。仮組みのときに画像を用意せず色だけで地形を作れます。

## 効果音の割り当て

効果音は「カタログに登録する」→「鳴らす場面へ割り当てる」の2段階で設定します。

| 画面 | やること |
|---|---|
| Lab_Editor →「🔊 サウンド管理」 | 音声ファイルに **ID** を付けてカタログへ登録する（`assets/se.json` / `ui_se.json` / `bgm.json`） |
| Lab_Editor →「🔊 サウンド割り当て」 | そのIDを実際の場面へ割り当てる |

割り当てられる場面は7種類です。

| セクション | 内容 |
|---|---|
| 👾 敵 | 出現・攻撃・被弾・撃破 |
| 🔧 ギミック | 起動 |
| 💎 アイテム | 取得 |
| 🎮 プレイヤー操作 | ジャンプ・着地・ダッシュ・射撃・被弾・力尽きる |
| ✏️ 編集ツール | 巻き戻し・拡大縮小・回転・移動・反転・リセット・コマ送り・一時停止・早送り・色フィルタ・カット・操作できない・ゲージ切れ |
| 🏁 タイトル/リザルト | カーソル移動・決定・戻る・ステージクリア・ゲームオーバー |
| 🎵 ステージBGM | 現在開いているステージのBGM |

**空欄は「鳴らさない」という意味**です。プレイヤー・編集ツール・UIの割り当ては `assets/game_config.json` の `player_se` / `edit_se` / `meta_se` に保存されます（敵・ギミック・アイテムは各アセットのJSONに保存されます）。

### IDの打ち間違いに気づけるようにしてあります

ゲームは知らないIDを渡されても**何も言わずに無視する**ため、1文字違うだけで「なぜか鳴らない」という状態になります。そこで起動時に一度だけ全ての割り当てを照合し、カタログに無いIDを指しているものを `logs/error.log` へ出すようにしてあります。音が鳴らないときはまずここを見てください。

### 同じ効果音が別の場面で使い回されていた点について

以前は一時停止とダッシュ取得が同じ音、決定と戻るとステージ開始がすべて同じ音、といった状態でした。専用の音源（`Paused.wav` / `FastFoward.wav` / `ColorChange.wav` / `Rewind.wav`）がありながら一度も使われていなかったため、本来の役へ割り当て直してあります。またIDの名前も「分裂02」のようなファイル由来のものから、`se_enemy_death`（敵:撃破）のように**どこで鳴るか**を表す名前へ付け替えました。

## アセットごとに編集を禁止する

「この敵だけは拡大させたくない」「この足場は動かされたら困る」といった縛りを、アセットごとに設定できます。Lab_Editor のアセット管理で対象を選ぶと、右側のパラメータ欄に出ます。

| 設定 | 禁止される操作 |
|---|---|
| 拡大縮小を禁止 | S+ドラッグ、インスペクタの大きさ |
| 回転を禁止 | R+ドラッグ、インスペクタの角度 |
| 移動を禁止 | ドラッグでの移動 |
| 向き反転を禁止 | 右クリックの円形メニューの「反転」、ダブルクリック |
| 一時停止を禁止 | 個別の一時停止 |
| 巻き戻しを禁止 | 個別の巻き戻し |
| 速度変更を禁止 | 速度±0.5、インスペクタの速度 |

**ステージ単位の「使える編集ツール」設定とは別の軸です。** ステージ側は「そのステージでそもそもどのツールを使えるか」、こちらは「このオブジェクトに対して何をしてよいか」を決めます。

複数のオブジェクトをまとめて選んだ場合、**禁止されている相手だけが除外され、他は今までどおり編集できます**。

**アイテムについて**：同じ設定欄をアイテムにも出していますが、アイテムは今のところゲーム内の編集ツールの選択対象になっていません。設定は保存されますが、まだ効果はありません（アイテムを編集できるようにしたときにそのまま効きます）。パラメータ欄にも同じ注意書きを出しています。

### 置いたもの1つずつに編集の可否を設定する

アセットごとの禁止は「その種類ぜんぶ」に効きます。同じ敵を置いた場所ごとに変えたいとき（「この1体だけ動かせる」「この箱だけ回せない」）は、ステージ画面で配置物を**右クリック → 編集の可否を設定...** を使います。

- 7つの操作（上の表と同じ並び）ごとに、**既定／許可／禁止**の3つから選びます。右にアセット側の設定（許可／禁止）が出ます
- **既定**＝アセットの設定に従う。**許可**＝アセットが禁止していても、この1つだけ許可。**禁止**＝アセットが許可していても、この1つだけ禁止
- 優先順位は「置いたもの1つずつの設定 → アセットの設定」です。複数選んだときは、これまでどおり禁止されている相手だけが除外されます
- 敵・ギミック・アイテムの全部で設定できます。**アイテムはゲーム内でまだ選択できないため、いまは保存されるだけで効果がありません**（ダイアログにも書いてあります）
- ステージJSONには、アセットと同じ名前のキー（`noMove: true` など）が配置のエントリに付きます。`true`＝禁止、`false`＝許可、キー無し＝既定。何も設定していない配置にはキーを書かないので、既存ステージに差分は出ません
- 設定は保存と「元に戻す」の対象です（右クリックメニューからの「大きさ・角度」「削除」も、操作した時点で保存・登録されるようにしました。以前は次にマウスを動かすまで保存されませんでした）
- ゲーム内のImGuiステージエディタから保存しても、このキーは消えません

## オブジェクトの大きさの決め方

アセット管理の **📏 ボタン**（敵・ギミック・アイテムの各一覧にあります）から、ゲーム内での大きさを決められます。

| やり方 | 使いどころ |
|---|---|
| プリセット（16 / 32 / 48 / 64 / 96 px） | タイル1マスは32pxなので、マス目に合わせたいときはこれが一番早い |
| 仕上がり幅[px] | 「88pxにしたい」のように狙った大きさが決まっているとき。縦横比は保たれます |
| 倍率 | 「今の1.5倍」のように相対で決めたいとき |
| プレビュー右下のハンドルをドラッグ | 見ながら decide したいとき（従来どおり） |

**「当たり判定も同じ比率で合わせる」を入れておくと、大きさを変えたぶんだけ当たり判定も一緒に動きます。** 外すと当たり判定は元のままです（見た目より小さい判定をわざと作りたいときに使います）。

### 表示されるpxはゲームの実寸と一致します

敵の見た目の大きさは「論理サイズ（幅px・高さpx）× 倍率」で決まり、**元画像の解像度は関係ありません**（素材はすべて640x640ですが、それがそのまま出るわけではありません）。以前の画面はここを取り違えて元画像の解像度を基準に表示していたため、表示を信じて合わせてもゲームでは違う大きさで出ていました。今は同じ式で計算しているので、表示された px がそのままゲーム内の大きさです。

ギミックとアイテムには倍率がなく、**当たり判定の大きさがそのまま表示サイズ**です。そのため📏から決めた値は当たり判定へ直接書き戻されます（画面にもその旨を出しています）。

## ステージ編集画面での配置

### 敵・ギミック・アイテムは実際の絵で並びます

以前は種類に関係なく小さな四角と絵文字で表示していたため、「置いたらどのくらいの大きさになるのか」がステージ編集画面では分かりませんでした。今は**実際のスプライトを、実際の大きさで**描きます。画像が無い／読めないアセットは今までどおり絵文字で表示します。

**クリックの当たり判定は従来どおり固定サイズのままです。** 当たり判定まで実サイズにすると、当たり判定が未設定のアセットが掴めなくなるためです。

### イベント・トリガー系統は右クリックで操作します

範囲選択（左ドラッグ）と操作が重ならないよう、**トリガー・プレイヤーの開始位置・ゴール**は、ステージ上の**右ボタン**で作ります。右のパレットにあった「⚡汎用トリガー／🚶開始位置／🏁ゴール」のラジオボタンは無くなり、Layer 4 の標準は「選択」です（敵・ギミック・アイテムを置くときは今までどおり、一覧から選んで左クリックです）。

| 操作 | 動き |
|---|---|
| **何も無い所を右ボタンでドラッグ** | トリガーの範囲を作ります。離すと、これまでどおりイベントの編集ダイアログが開きます |
| 何も無い所を**右クリック**（動かさずに離す） | メニュー：「ここにトリガーを作る」（96×96）／「ここをプレイヤーの開始位置にする」／「ここをゴールにする」。タイルの選択範囲があれば、その塗りつぶしの項目も出ます |
| トリガーを**右クリック** | メニュー：「トリガーを編集...」「削除」 |
| トリガーを左クリック | 選ぶだけです（以前は、選んだ瞬間に編集ダイアログが開いていました）。イベント一覧のダブルクリックからも編集できます |

- メイン・遠景・近景のタイルを編集している間（ペンの Layer 1〜3）は、右ボタンは今までどおり**タイルを消します**。トリガーなどを作るときは、「🔍選択」ツールか、Layer 4 に切り替えてください
- トリガーのIDは、削除で欠番があっても、既存と重ならない最初の番号（`trigger_001` 形式）になります

### 範囲選択と同時編集（「🔍選択」ツール）

敵・ギミック・アイテムを、まとめて選んで、まとめて編集できます。ツールバーの **🔍選択** を選びます。

| 操作 | 動き |
|---|---|
| クリック | 1つ選ぶ（トリガーは今までどおり、専用エディタが開く） |
| **Ctrl＋クリック** | 選択へ足す／外す |
| **何も無い所からドラッグ** | 四角で囲んだ物（少しでもかかっていれば）をまとめて選ぶ。Ctrl を押して始めると、いまの選択へ足す |
| 選んだ物のドラッグ | 選んでいる**全員が一緒に**動く。32pxの格子に合う動きで、行って戻れば元の位置に戻る |
| 複数選択の1つをクリック（動かさない） | その1つだけの選択に絞る |
| 何も無い所をクリック／Esc | 選択をすべて外す |
| **Delete** | 選んだ物をまとめて削除（1回の「元に戻す」で全員が戻ります） |
| 選んだ物を右クリック | 「大きさ・角度を編集（n個）」「編集の可否を設定（n個）」「削除（n個）」 |

- 範囲選択には**トリガーを含めません**（トリガーは自分の矩形が大きく、ほかの物を選ぶ邪魔になるため。クリックで選びます）
- **大きさ・角度をまとめて変える**ダイアログは、項目ごとに「変更しない」が付いていて、初期値は全部「変更しない」です。**触った項目だけ**を全員に書き込むので、触っていない項目で各自の値が上書きされることはありません。ギミックの「縦の大きさ」はギミックにだけ、「角度」は自動回転する橋など、AIが角度を使う型を除いて書き込みます
- **編集の可否をまとめて設定する**ダイアログも、操作ごとに「変更しない／既定／許可／禁止」を選べます。「変更しない」の操作は、各自の今の設定がそのまま残ります
- 同じ種類（敵だけ、ギミックだけ）を選んでいるときは、右のプロパティ表でも値をまとめて編集できます。種類が混ざっているときは何も出ないので、右クリックのメニューを使います。複数選択中に **ID は変えられません**（全員が同じ種類になってしまうため）
- プロパティ表で値を変えたら、そのとき保存と「元に戻す」への登録をします（以前は、次にキャンバスを操作するまで保存されませんでした）
- 「元に戻す」「やり直し」のあとは、選択が外れます

### タイルのフィルと、選択範囲の塗りつぶし

タイルを塗る道具が2つ増えました。どちらも、ツールバーの **Layer 1〜3** で選んだ層（Layer 4 のときはメイン層）に効きます。塗りつぶす色は、右のパレットで選んでいるタイルです。

- **🪣フィル** — クリックした所と**同じタイルで上下左右につながっている範囲**を、選んでいるタイルで埋めます（ドラッグしても1回だけ）。広いマップでも止まりません
- **▦選択範囲を塗る** — 「🔍選択」で何も無い所からドラッグすると、四角に囲んだ範囲が水色の点線の**選択範囲**になります。このボタンで、その範囲を選んでいるタイルで埋めます。右クリック（何も無い所）からも、同じ操作と「選択範囲のタイルを空にする」が選べます
- **Delete**（物が選ばれていないとき）は、選択範囲のタイルを空にします。**Esc** で範囲を解除します
- 選択範囲があるときに🪣フィルを使うと、**範囲の中だけ**を塗ります（範囲の外をクリックしても何もしません）
- 範囲選択は、物の選択と同時に、その四角を選択範囲にします。画面の左上に「n個を選択中 ／ 範囲 17×7マス → Layer 2（メイン）」と出ます
- タイルの選択範囲があるときは、パレットでタイルを選んでも「選択」ツールのままです（範囲を作ってからタイルを選び、ボタンを押せるように）
- 層ボタン（Layer 1〜4）を押しても、フィル・選択・消しゴムを使っている間は、そのツールのままです（以前は編集モードだけがペンに戻り、ツールバーの表示と食い違っていました）

### 右クリックでメニューが出ます

以前は右クリックした瞬間に確認なしで削除されていました。今は次のメニューが出ます（消しゴムツールでの削除は今までどおりです）。

- **大きさ・角度を編集...** — その1個だけの大きさと角度を決めます
- **編集の可否を設定...** — その1個だけ、ゲーム内でプレイヤーにできる編集操作（拡大縮小・回転・移動・向き反転・個別の一時停止・個別の巻き戻し・速度変更）を許可／禁止します（くわしくは[置いたもの1つずつに編集の可否を設定する](#置いたもの1つずつに編集の可否を設定する)）。設定したものは、ステージ画面で右上に小さな印（赤の「禁n」／緑の「許n」）が付きます
- **削除**

### 置いたもの1つずつに大きさと角度を持たせられます

アセット定義の大きさは「その種類の標準」で、こちらは**それを配置ごとに上書き**するものです。同じ敵を大小いくつも並べたり、最初から傾けて置いたりできます。

- 大きさは倍率で指定します（1.0 = アセットの標準サイズ）
- 角度は度で入力します。0°/45°/90°/180° はボタン一発で入ります
- 何も設定していない配置はステージJSONにキーを書きません。**既存のステージの見え方は一切変わりません**

#### ただの見た目ではなく「最初から編集された状態」になります

ここで設定した大きさ・角度は、**プレイヤーがゲーム内の編集ツールで同じ操作をしたのとまったく同じ扱い**になります。つまり

- 2倍にして置いた敵は、S+ドラッグで2倍にしたときと同じように**重くなる**（段差を越えられなくなる等）
- 90度倒して置いたドッスンは、R+ドラッグで倒したときと同じように**真下ではなく倒した向きへ落ちる**
- 45度以上倒して置いたトゲは、**倒された扱い（無害）**で始まる
- 縮小して置いた岩は、**転がる状態**で始まる

という反応が最初から成立します。ダイアログの下には「この設定だとゲーム内でどう扱われるか」が出るので、45度の境目のような分かりにくい条件も入力しながら確認できます。

#### ギミックは横と縦を別々に指定します

ゲーム内の編集ツールは、敵は倍率1つ（S+ドラッグ）、ギミックは**横幅(Sドラッグ)と縦幅(Wドラッグ)を別々に**変えます。配置ごとの初期値も同じ粒度にしてあるので、ギミックだけ「横の大きさ」「縦の大きさ」の2つが出ます。

また、**角度をAIが自前の状態として使っている型**（自動で回る橋・ちくわブロック・挙動スクリプトで角度を動かすもの）は、ゲーム内でも回せないので、この画面でも角度が入力できません。

### ゲーム設定のステージ一覧

「ゲーム設定」→「ステージ一覧」タブで、タイトル画面のステージ選択に並ぶステージを管理します。

| ボタン | 動作 |
|---|---|
| ＋ 追加 | まだ一覧に載っていないステージファイルを選んで追加します（複数同時に選べます）。2本目以降は解放条件の初期値が「前のステージをクリア」になります |
| 🗑 削除 | 選んでいる行を一覧から外します。**ステージファイル自体を消すかどうかは別に確認します**（既定は外すだけなので、あとで追加し直せます） |
| ▲ 上へ / ▼ 下へ | 並び替えます。並び順がそのまま「前のステージ」の順序になります |
| サムネイルを選ぶ | ステージ選択画面に出す画像を選びます |

ステージファイルそのものを新しく作るのはメイン画面の「新規ステージ」です。作ったあと、この画面で一覧へ追加してください。

**消えたステージファイルを参照している行も、書かれているとおりに表示されます。** 以前はファイル選択の候補に無い名前が別のファイル名に化けて見え、そのまま保存すると設定が黙って別のステージを指してしまう状態でした。

## 背景レイヤー

背景は複数のレイヤーを重ねられ、`scrollRate` を小さくするほど遠くにあるようにゆっくり動きます（視差スクロール）。

**画像を指定せず、色だけを指定することもできます。** 空や単色の下地を、画像を用意せずに作れます。Lab_Editor の「背景レイヤー設定」で `色(#RRGGBB)` 欄へ直接書くか、🎨ボタンから選んでください。画像と色を両方指定した場合は、色が下地になり、その上に画像が重なります。

レイヤーは `drawOrder` の小さい順（奥から手前）に描かれます。

| 項目 | 意味 |
|---|---|
| `scrollRate` | カメラに対する動く速さの割合。`1.0` で地形と同じ、小さいほど遠景。既定は `0.3` |
| `loop` | ONなら**画面の幅を覆うまで横に繰り返し並べます**（既定はON）。画像が画面より狭くても、`offsetX` を付けても、端に隙間は出ません |
| `offsetX` / `offsetY` | 初期位置のずらし量。**プラスで右／下**へずれます（Lab_Editor のプレビューも同じ向きです） |

- `loop` をOFFにすると、画像は**1枚だけ**で、スクロールに合わせて動き、端まで行ったら画面の外へ出ていきます（以前はOFFでも途中で先頭へ飛んでいました）
- 新しく追加した行の初期値は `scrollRate=0.3`・`loop=ON` で、ゲームが読むときの既定値と同じです
- 「背景レイヤー設定」の `color` 欄には、入力した色がそのままセルの背景に出ます

## チュートリアル


### チュートリアルステージについて

素材の一新（2026-10-15）で、チュートリアルを含む旧いステージは削除しました。以下は、操作そのものの説明として残しています。

### メニューを開かずに触る（つまみ・ホイール・ダブルクリック）

敵・プレイヤー・ギミックは、**選ぶと枠にそのままつまみが出ます**。キーを覚えなくても、画面にあるものを触れば編集できます。

| 操作 | 効果 |
|---|---|
| 枠の**右下の四角**を引っぱる（敵・プレイヤー） | 大きさが変わる。角が指に付いてくる |
| 枠から伸びた先の**丸**を回す（敵・プレイヤー・ギミック） | その向きへ回る。**15度の倍数の近く（±5度）では吸い付く**ので、真横・真下が簡単に合わせられる |
| **マウスホイール** | 拡大縮小（敵・プレイヤーは±0.1倍、ギミックは横幅±32px、可変地面はタイル1枚ずつ） |
| **Ctrl＋ホイール** | 15度ずつ回す |
| **ダブルクリック**（0.3秒以内） | 向きを反転する（コストは右クリックメニューの反転と同じ） |
| **Ctrl＋クリック** | クリックした物を選択に加える／外す（離れた物を数体だけ選べる） |

- つまみは**選択がちょうど1つのとき**だけ出ます。複数選んでいるときは、ホイール・キー・メニューで全員にまとめて効きます
- つまんでいる間は**世界が止まります**。狙いを付けてゆっくり合わせられます
- **大きさを変えても、地面や壁にめり込みません。** 敵・プレイヤーは**足元（下端の中心）を固定**して、上と左右へ伸び縮みします（地面に立ったまま大きくなる）。右下のつまみは、そのぶん**横へ引いた距離**で大きさが決まります（縦へ動かしても変わりません）。拡大した先が地面・壁・天井・足場に新しく食い込むときは、**食い込む手前の大きさで止まります**。ギミックの横幅・縦幅も同じで、壁や天井で止まります。縮小はいつでもできます
- 範囲を示すだけのギミック（明暗・色調・ズーム・スロー・時間のゾーン）は、壁や床と重なっているのが普通なので、止まりません
- 回転を `Shift` ではなく `Ctrl` にしてあるのは、`Shift` がプレイヤーのダッシュに使われていて、編集中に走り出してしまうためです
- 大きさ・回転を禁止したアセットや、角度をAIが使っているギミックにはつまみが出ません

### 右クリックの円形メニュー

物を右クリックすると、そのまわりに**6つの項目が円形に開きます**（以前は英語の縦メニューでした）。

| 位置（上から時計回り） | 項目 | 効果 |
|---|---|---|
| 上 | 巻き戻し | その物だけ巻き戻す／止める |
| 右上 | 一時停止 | その物だけ時間を止める／動かす（止まった敵は踏み台になる） |
| 右下 | 加速 | 速度＋0.5 |
| 下 | 減速 | 速度－0.5 |
| 左下 | 反転 | 向きを反転する |
| 左上 | リセット | 配置したときの状態へ戻す |

- 各項目には**ON/OFFの状態と、使うコスト**（`-8` など）が出ます。コストが足りない項目は**暗くなり**、押すと拒否音が鳴ります
- 項目は**中心から見た方向**で選びます。次のどちらでも選べます
  - **右ボタンを押したまま、項目の方向へ動かして離す**（いちばん速い）
  - いったん離して、**項目を左クリック**する
- 中心の円の中で離したときは、メニューは開いたまま残ります。中心をクリックすると何もせずに閉じます
- 画面の端で開いたときは、項目が見切れないよう中心を内側へ寄せます。この場合は「押して動かして離す」は使えず、**離してから左クリック**で選びます
- すでに選んでいる物を右クリックしたときは、**選択はそのまま**です。Ctrl＋クリックで選んだ複数の物へ、まとめて反転や速度変更をかけられます
- 下部のタイムラインでカットを右クリックすると、「カット削除」だけの円形メニューが出ます

### 取り消し・やり直し

| 操作 | 効果 |
|---|---|
| **Ctrl＋Z** | 直前の編集を1手戻す |
| **Ctrl＋Y** | 戻した編集をやり直す |

- 1手の単位は「**マウスを押してから離すまで**のドラッグ・つまみ」「メニュー／ダブルクリックの1操作」「0.4秒以内に続いたホイール操作」です
- **使ったコストは全額返ります**（反転・速度・一時停止・巻き戻し・リセット）。やり直しは、もう一度同じ操作をするのと同じなので、コストが足りないとできません
- 戻すのは**変えた項目だけ**です。敵を拡大したあと、その敵が歩いて移動していても、取り消しで元の場所へ瞬間移動することはありません
- 新しい編集をすると、やり直しの履歴は消えます。履歴は最大50手です
- 次の操作は取り消せません：Gキーでの地面の追加、タイムラインのカットの作成・削除、敵タイプの切り替え。ステージをやり直したときも履歴は空になります
- タイムラインでカットの1点目だけ打っているときの Ctrl＋Z は、その打ちかけを捨てます

### 編集の「いま何が起きているか」の表示

操作の結果や、できなかった理由を、画面で確認できます（すべて見た目だけで、ゲームの進行には影響しません）。

| 表示 | いつ出るか | 内容 |
|---|---|---|
| **結果プレビュー**（破線の矢印） | 敵を選んでいる間 | 砲台は「次の一発」の向きと到達点、ドッスンは「落ちる向き」、突進する敵（傾けたとき）は「突進」の向きと距離。つまみで回している間もリアルタイムに動き、地形にぶつかる点には ✕ が付く。反転した砲台は「味方の弾」と表示される。**編集していない「いつもの動き」は薄く**出る |
| **ホバー表示** | 何もつかんでいないとき、マウスを物に重ねる | 白い細枠と名前の札（「クリックで選択」）。動かせない操作があれば「変更不可：大きさ・回転」のように理由を出す。つまみの上では「引いて拡大・縮小」「回す（15度ごとに吸着）」と出る |
| **画面の縁と右上の札** | 世界が止まっている間 | 琥珀色＝「時間停止中」（SPACE で止めた状態。コストを消費し続ける）／水色＝「編集中：時間が止まっています」（ドラッグ・つまみをつかんでいる間だけ。離せば再開） |
| **コストの増減** | 編集コストが一気に動いたとき | ゲージの横に「-3」「+3」が浮かぶ（操作の消費・取り消しの返却・アイテムの回復） |
| **トースト**（下寄りの札） | 取り消し・やり直し・できなかったとき | 「取り消しました：反転（コスト +3）」「コストが足りません（必要 8／残り 5）」「このステージでは時間停止は使えません」「取り消せる操作がありません」など。以前は拒否音だけで理由が分からなかった |

### 大きさの変え方（つまみ）

ギミックを選ぶと、**右辺に横のつまみ、上辺に縦のつまみ**が出ます。これを引っぱるだけで大きさが変わります。

- **横のつまみは横へ、縦のつまみは上へ**引きます。引いている間は `W:130` のように今の値がその場に出ます
- **縦に伸ばしても下端は動きません。** 地面に置いた箱はそのまま上へ伸びるので、踏み台として高くできます
- 従来の `S`＋ドラッグ（横幅）・`W`＋ドラッグ（縦幅）・`R`＋ドラッグ（回転）も使えます。
  **選んだあとに押しても効きます**（以前は一度選ぶと移動にしかならず、選び直すしかありませんでした）
- 大きさを禁止したアセット（`noScale`）にはつまみが出ません

重量スイッチには、**必要な幅の目安線と数値**が本体の上に出ます。足りていない間は橙、足りると緑になります。

### コマ送りリフト

一時停止中の `→` で1コマ進み、**リフトは1コマぶん上がります**。`←` でも1コマ進みますが、
リフトだけは逆に**下がります**（上げすぎたときに巻き戻しを使わず戻せるようにするため）。
上限・下限では折り返さずそこで止まります。

`travelDistance` は**必ず正の値**（＝距離）で書いてください。向きは式の側が持っています。
以前はアセット側が負の値を書いて上昇させるつもりでいましたが、
未指定を表す番兵も負の値なので既定値で上書きされ、「コマを送ると下がる」状態になっていました。
下向きに動かしたい場合は、ゲーム内の**向き反転**で裏返します。

### 説明の出し方

説明は `ShowMessage` のトリガーで出しています。**メッセージは改行で行を分けられ、最大3行**まで
表示されます（枠は行数に合わせて上へ伸びます）。1行が全角28文字ほどを超えると枠からはみ出すので、
Lab_Editor のメッセージ編集画面のプレビューで、はみ出す行が赤く出ないことを確かめてください。

### ズーム固定（タイプ19）

これまでの「画面の拡大・縮小を繰り返す」動きを、次のように作り直しました。

- プレイヤーが**寄せ始める距離**（既定300px）に入ると、**この敵を中心に**画面が少しずつ寄っていきます（既定は3秒で2倍まで）
- 一度寄り始めたら、離れても**戻りません**。**この敵を倒したときだけ**滑らかに解けます
- プレイヤーの Z キーのズームでは打ち消せません。ただし映す範囲は、プレイヤーが必ず見えるようにずれます
- 固定されている間は、右上に「画面が固定されています：寄せている敵を倒す」と出ます
- ズーム中も、右クリックの選択・ドラッグ・つまみは指した場所どおりに効きます（マウス位置の変換がズームに対応しました）
- 調整できる項目：寄せ始める距離・寄る強さ（追加の倍率）・寄りきるまでの時間

### 回転させる敵（タイプ24）

射程（既定240px）の中の**プレイヤー・ほかの敵・ギミック（足場など）・アイテム**を、ゆっくり回し続けます（既定は60度/秒）。

- 回った角度は**残ります**。編集の「回転」やインスペクターで直すか、巻き戻して戻します
- 「回転を禁止」された物は回りません
- 向きを反転すると逆回り。速度を0にすると止まります
- 調整できる項目：回す範囲・回す速さ・回す相手（プレイヤー／敵／ギミック／アイテム）

### 範囲サイズ調整の敵（タイプ25）

プレイヤーが近づくと、**警告音（alert）**のあと、4方向の矢印の十字を投げます。

- 着地点に円形の**範囲**ができ、中のプレイヤー・敵・大きさを変えられるギミックが、**投げるたびに交互に**拡大・縮小します（暖色の範囲＝拡大、寒色＝縮小）
- 変わった大きさは、範囲が消えても**残ります**（編集の「拡大縮小」か巻き戻しで直せます）
- 向きを反転すると、次に投げる種類が入れ替わります
- 調整できる項目：投げ始める距離・投げる間隔・予兆の長さ・範囲の半径・範囲が残る時間・拡大の倍率

### 幽霊（タイプ14）

「過去の動きをなぞる」型から、**暗闇に現れる**型に作り直しました。

- 画面が**明るいあいだは姿を消し**、**暗いあいだだけ現れます**。明るさが「姿を現す明るさ」（既定0.6＝「暗い」の判定と同じ）より暗くなると、約0.4秒でじわっと現れます。暗くするのは、Xキー・カラー補正パネルの明るさ・暗転の敵や明暗ゾーンのどれでも構いません
- 現れているあいだは、**浮いたまま（ふわふわ上下しながら）プレイヤーへ近づきます**。地形・ギミック・足場・ほかの敵、どれもすり抜けます
- 姿を消している間は**その場で止まります**。触れてもダメージを受けず、弾も素通りします（HPの表示も出ません）
- 現れている間は、触れると被弾しますが、**弾が当たります**。暗くして姿を現させてから撃ちます
- 向きを反転すると、近づかず逃げていきます。一時停止・速度0で、動きも現れ方も止まります
- 調整できる項目：姿を現す明るさ・近づき始める距離・近づく速さ・浮く幅と速さ

### パーツの位置の決まり（回る・見る・連なる）

- **回る頭に載った黒目**：回る部品（回転させる敵の頭など）の目の穴に載った黒目は、頭と同じ軸・同じ速さで一緒に回りながら、プレイヤーのほうへ少しずれます（頭だけが回って黒目が取り残されることはありません）。Lab_Editor の型「回る頭に載った黒目」で作れます
- **プレイヤーを見る黒目**は、敵を回したり拡大したりしても、本体の姿勢に合わせて位置と大きさが変わり、見る向きはワールドのプレイヤーの方向のままです
- **跳ね回る節足敵（機械芋虫）の胴体の節**になるのは、本体より奥（`zOrder` が負）のパーツだけです。手前のパーツ（目など）は頭に貼り付いたまま動きます

### 敵の絵の向き

主人公以外の絵は、**左を前として**描かれています。ゲームの向き（`direction`：0＝右向き／1＝左向き）に合わせて、**右を向くときに、絵を左右反転して**描きます（左を向くときは、そのまま）。

- 本体の絵・アニメーション・**パーツの絵**のすべてに効きます。パーツは、本体と同じ箱に重ねてある（位置が動かない）ものなら、一緒に反転するだけでずれません
- 位置が動くパーツ（芋虫の体節など）は、スクリプトの `ParentDirection`（右向きなら+1、左向きなら-1）で、「頭の後ろ」に置きます
- 右向きに描いた絵を使うときだけ、Lab_Editor の敵の設定で「**絵が左向きに描かれている**」（`artFacesLeft`）をオフにします（既定はオン）
- 弾・アイテム・ギミックは、対象外です（向きを持たないため）

### 敵の絵と当たり判定

素材は周りに透明な余白のある640x640です。そこで、敵の定義（`width`/`height`）は**絵を収める箱**、`hitboxWidth`/`hitboxHeight` は**当たり判定**として分けて持ちます。

## 画面に映っていない敵は動かない

敵は、**モニターに映っていない間は何もしません**。映った瞬間から、止まっていた状態の続きで動き出します。

- 止まるのは、移動・重力・射撃・画面エフェクト（暗転・色変化・ズーム）・各タイマー・パーツのスクリプトなど、敵の更新ぜんぶです
- 「映っている」は、**いまモニターに映している範囲**（Zキーのズームやズーム固定の寄せを含む）と、敵の当たり判定が少しでも重なるかで決まります
- 画面の外の敵は、弾を撃たず、プレイヤーにも触れません。画面外から撃たれたり、いきなり追いかけられたりしなくなります
- **ズーム固定の「固定」は、画面外でも解けません**（倒したときだけ解けます）。寄せていく進行だけが止まります
- 例外：Lab_Editor の敵の設定の **「画面の外でも動く」** をオンにした敵は、画面の外でも動きます（標準の敵にはオンのものはありません）
- 巻き戻しとプレイヤーの操作は、今までどおりです

## プレイヤーの弾の向き

プレイヤーの弾は、**プレイヤーが向いている方向**へ飛びます（Enter キー、またはモニター内の左クリック）。

- 左右（A / D で向きが変わる）に合わせて、左向きなら左へ、右向きなら右へ撃ちます
- 回転の敵や編集ツールでプレイヤーが傾いているときは、**傾いた向きのまま斜めにも**撃ちます。右を向いて −45° なら右上へ、左を向いて 30° なら左上へ飛びます。傾きが 0° なら今までどおり真横です
- 弾が出る位置も、体の傾きに合わせて回ります（体の前、少し上寄りの点）。弾の絵も飛ぶ向きに回って描かれます

## 跳ね回る節足敵（機械いもむし）

`enemy_kikai_imomushi`（タイプ22 = Bouncing Worm）は、**重力を受けずに向いている方向へまっすぐ飛び続け、壁・床・天井に当たるとランダムな角度で跳ね返る**敵です。胴体の節が頭の通った跡を辿って連なります。

| 見た目 | 画像 |
|---|---|
| 頭 | `img/機械いもむし頭部.png` |
| 胴体（既定6節） | `img/機械いもむし胴体.png` |

### 動き

- **頭**は空中でも落ちません。`飛ぶ速さ` の分だけ毎フレーム直進し続けます
- 地形や画面端にぶつかると反射し、そのたびに `跳ね返り角の乱れ` の範囲で角度がずれます。まっすぐ跳ね返らないので同じ軌道を繰り返さず、待ち構えて避けるのが難しい相手になります
- 乱れのせいで壁の内側を向いてしまう場合は、その回だけ乱れを捨てて正しく反射します（壁にめり込んで動けなくなるのを防ぐため）
- **胴体**は頭の軌跡を `胴体の節の間隔` ごとに辿ります。頭が曲がれば、その曲がりが順番に後ろの節へ伝わっていきます

### 体当たりで壊す

ぶつかった相手が**体当たりで壊せる**設定なら、跳ね返る前にそれを壊します。地形タイル（やわらかい壁など）でも壊せるブロック（ギミック）でも同じです。

- **壊して道が開いたときは跳ね返らず、そのまま突き抜けて直進します。** 壊した瞬間に反射すると、自分で開けた穴に入らずその場で往復してしまうためです
- 壊せない相手（岩盤や重量ブロック）に当たったときは、従来どおり跳ね返ります
- 大きさの条件（`○倍以上でないと壊せない`）もそのまま効きます。足りないときは対象のマスに必要な倍率が出ます

回転させて壁へ向けてやれば、そのまま掘削機として使えます。壊せるかどうかを決めるのはあくまでブロック／タイル側の設定なので、壊させたくない壁は「体当たりで壊れる」を切っておけば素通りも掘削もされません。

### 調整できる項目

Lab_Editor のアセット管理でこの敵を選ぶと、右側のパラメータ欄に出ます。

| 項目 | 意味 | 既定 |
|---|---|---|
| 飛ぶ速さ(px/フレーム) | 直進する速さ | 3.0 |
| 跳ね返り角の乱れ(度) | 反射角へ足す乱れの最大値。0にすると物理どおりの正反射になる | 25 |
| 胴体の節の間隔(px) | 節と節の距離 | 22 |

節の数は `parts`（パーツ編集）で増減します。節を増やすほど長い胴になります。

### 編集ツールへの反応

| 操作 | 反応 |
|---|---|
| 回転 | **回した向きがそのまま進む方向になります。** 狙った所へ飛ばしたり、自分から遠ざけたりできます |
| 向き反転 | 進む方向が逆になります |
| 拡大 | 体が重くなって遅くなります |
| 縮小 | 軽くなって速くなります |
| 一時停止・速度 | 他の敵と同じように効きます |

ステージに置くときの角度（配置ごとの「大きさ・角度」）も、そのまま**飛び出す方向**になります。45度で置けば斜め下へ飛び出します。

### 巻き戻しについて

跳ね返る角度は乱数で決まりますが、**巻き戻して再生し直しても必ず同じ角度になります。** 「何回目の跳ね返りか」と「どこで跳ね返ったか」だけから決まる値を使っているためで、`rand()` は使っていません。巻き戻して跳ね返り先を確かめてから動く、という遊び方が成立するようにするためです。

胴体も専用の記録を持たず、巻き戻し用の履歴をそのまま軌跡として使っています。そのため巻き戻すと胴体もきちんと巻き戻ります。

## よくある問題と対処方法

| 症状 | 原因・対処 |
|---|---|
| 棘ブロックに乗っても死なない | **修正済みです。** 以前は足元の1点しか見ておらず、着地すると必ず1マス上を調べてしまうため、「当たり判定あり＋即死」のタイルが無害になっていました。現在は体が触れているタイルを全て見るので、乗っても・横から当たっても・頭をぶつけても即死します |
| Lab_Editorの「▶ プレイ」を押しても何も起きない／「ゲーム実行ファイルが見つかりません」 | ゲーム本体(`Lab_Project_01.vcxproj`)を先にビルドし、`x64/Debug/Lab_Project_01.exe`を生成してください |
| `dotnet build`が「ファイルをコピーできません...別のプロセスによってロックされています」で失敗する | Lab_Editor.exeが起動中です。閉じてから再ビルドするか、`dotnet build -c Release`で別出力先にビルドしてください |
| 敵・ギミックの画像が表示されない／`Log.txt`に「画像ファイル...がありません」と出る | 該当のスプライト画像(`img/`フォルダ)が実際には存在しません。アセット管理の「📁選択」で画像を割り当ててください |
| BGM/SEが鳴らない | `assets/bgm.json`/`se.json`/`ui_se.json`のエントリで **id・name・fileがすべて空でない**ことを確認してください（IDが空のエントリは読み込まれません）。サウンド管理画面で保存しようとすると空欄チェックで警告が出ます |
| 敵のHP・移動速度などをテンプレートで変更しても反映されない | アセット管理画面で編集後、必ず「💾 保存して閉じる」を押してください。マップ上の配置自体を打ち直す必要はありません |
| 自作スクリプトを書いた敵・ギミックが動かない／エラーになる | `logs/error.log`を確認してください。`[BehaviorScript] [Tick] ERROR: ...`という行があれば、スクリプトのJSON構造（`body`が配列になっているか、`cond`の式が正しいか等）を見直してください。何も表示されない場合は`type_enum`が20（敵）/24（ギミック）になっているか確認してください |
| 「🧩 挙動スクリプトを編集」ボタンを押しても「対象外」と言われる | 敵は`type_enum=20`、ギミックは`type_enum=24`（いずれも「カスタムスクリプト」）の行でのみ使えます。「🧩 パーツを編集」はタイプに関係なくどの行でも使えます |
| パーツを追加したのに、本体が動くとパーツが置き去りになる | パーツにスクリプトが無い（または`OnSpawn`が無い）と、初期位置に固定されたまま本体を追従しません。`SetLocalOffset`で固定オフセットを毎フレーム設定する最小スクリプトを入れてください（前章参照） |
| ソケット（数値欄・条件欄）に別のブロックを差し込めない | 既にブロックが差し込まれているソケットには上書きドロップできません。右クリックで一度空にしてからドラッグし直してください |
| 新しく`.h`/`.cpp`ファイルを追加したらビルドエラーになる（謎の構文エラーが大量に出る） | このプロジェクトはソースファイルの文字コード判定でCP932(Shift-JIS)とUTF-8のせめぎ合いがあり、**LF改行のみのファイルだと日本語コメントの解釈でコンパイラが誤爆することがあります**。新規ファイルは既存ファイルと同様にCRLF改行で保存してください |
| ステージファイルを直接編集したらゲームが起動しなくなった | JSON構文エラーの可能性が高いです。`node -e "JSON.parse(require('fs').readFileSync('assets/stages/xxx.json','utf8'))"`などで構文チェックしてから再度読み込んでください |

## 既知の制限・今後の予定

- 巻き戻し（リワインド）機能は位置・速度・向き・スケール・角度・生存状態のみを記録しており、スクリプトの実行状態（変数・コールスタック）やパーツのHPは巻き戻し対象に含まれません。スクリプトで動く敵・ギミック・パーツを巻き戻すと、見た目の位置は戻ってもスクリプトの内部状態は戻らない場合があります
- `OnDeath`は死亡と同じフレーム内で完結する処理のみ対応しており、`Wait`を挟む複数フレームの死亡演出は未対応です
- アイテムは取得と同時に画面から消えるため、アイテムのパーツは装飾的な意味合いが中心です（取得判定はパーツに触れても本体と同様に発生します）
- 一部のギミック（ポータル・橋・破壊ブロック等）は専用スプライト画像が用意されておらず、ゲーム内で表示が欠けることがあります。複合パーツのテンプレートも同様に、既存の汎用画像（`img/enemy.png`等）を仮のスプライトとして使っているものがあります
- 効果音は`jump`（ジャンプ音）のみ登録済みで、敵の攻撃音・被弾音・死亡音などは素材が未整備です
